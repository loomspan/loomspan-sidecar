# Session-owned configuration drafts research

## Research Question

What complete authored-content, snapshot identity, validation, and test contracts exist in the current checkout for PR 1.1.3's isolated draft model?

## Summary

PR 1.1.1 supplies an immutable `ManagedConfiguration` value containing ordered named skill YAML and one REST YAML string; PR 1.1.2 stores submitted snapshots and an intended-production pointer. The checkout has no draft or candidate model and no validation-result association for managed configuration. Existing storage and runtime loading are separate: the store preserves authored text, while mounted skill and REST files still supply the running configuration. `README.md:97-107`, `README.md:109-119`, `README.md:133-149`, `README.md:465-470`.

## Current Behavior and Data Flow

1. `ManagedConfiguration` accepts the complete ordered `List<SkillDocument>` and raw REST routes YAML. It copies the list, requires non-null REST text/documents/YAML, and enforces nonblank, exactly unique source labels. It does not parse YAML or resolve placeholders (`src/main/java/ai/loomspan/sidecar/storage/ManagedConfiguration.java:11-29`). The framework's public `SkillDocument` is a two-string record (`C:/opendev/code/loomspan-framework/src/main/java/ai/loomspan/api/SkillDocument.java:4`). These immutable records and strings make source content safe from later mutation through a caller-owned list.
2. `ConfigurationSnapshot` records a local UUID, optional source UUID, positive submission sequence, `ManagedConfiguration`, and status (`src/main/java/ai/loomspan/sidecar/storage/ConfigurationSnapshot.java:7-19`). A stored `sourceId` denotes provenance; no field currently represents a draft's runtime-published base. `ConfigurationSnapshotStore.current()` reads the SQLite selected pointer (`src/main/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStore.java:56-70`). The README identifies this as intended production, distinct from an activated framework generation (`README.md:133-141`).
3. The Spring storage bean migrates SQLite, initializes the selected snapshot, and prunes history (`src/main/java/ai/loomspan/sidecar/storage/StorageConfiguration.java:28-59`). `ConfigurationSnapshotStore.submit()` checks the expected pointer, inserts a complete pending snapshot, and switches the pointer in a transaction (`src/main/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStore.java:73-87`). `revert`, `updateStatus`, and `prune` handle submitted history (`ConfigurationSnapshotStore.java:89-141`). None is a draft operation.
4. Repository insertion writes a new local UUID, REST text, ordered labeled skill documents, and pending status (`src/main/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepository.java:22-46`). Reads reconstruct the same `ManagedConfiguration`, check document count/order, and expose the stored status (`ConfigurationSnapshotRepository.java:49-85`). The schema has only snapshot, skill-document, status, and store-state tables; triggers reject content updates (`src/main/resources/db/migration/V1__configuration_snapshots.sql:1-42`). There is no draft table.
5. The current REST route loader loads a configured resource and resolves placeholders during runtime configuration, reporting a location/path in failures (`src/main/java/ai/loomspan/sidecar/rest/RestRouteLoader.java:46-112`, `:325-359`). This is separate from `ManagedConfiguration` and is not a draft validator. The framework remains the authority for skill validation (`ai/thoughts/design-lens.md:32-41`). The existing `SkillInputValidationIssue` public type describes execution input issues with path/code/message, not managed configuration validation (`C:/opendev/code/loomspan-framework/src/main/java/ai/loomspan/api/SkillInputValidationIssue.java:3`; `src/main/java/ai/loomspan/sidecar/api/ApiExceptionHandler.java:18-23`).
