# Sidecar portable skill naming research

## Research Question

Where does Sidecar discover, accept, queue and inspect a skill identity today? Which public Framework operations establish the exact identity, which existing loaders validate physical definition paths, and which Sidecar boundaries can verify the replacement contract?

## Summary

- Catalog lookup and POST currently assume `default`, use the presence of a hyphen to decide whether to add `default-`, and call the earlier one-name Framework operations. The execution record retains that one request string.
- The matching Framework checkout exposes exact namespace catalogs, exact local lookup, two-component invocation and public metadata constructors with the same component and pair checks. The catalog and invocation APIs report missing and malformed targets differently.
- Framework startup already owns validation of physical mounted skill paths. Sidecar bundle format 4 independently accepts only fixed names and ordinal skill paths and carries an exact diagnostic label separately. Sidecar tests can exercise both boundaries without depending on Framework internals.
- The SDK and quickstart are already committed at the new wire contract. The current server and test fixtures still need the paired API and exact authored, structured-model and provider-tool spellings.

## Current Behavior and Data Flow

### HTTP discovery, submission and polling

- [SkillCatalogController.java, lines 13–25](../../../src/main/java/ai/loomspan/sidecar/api/SkillCatalogController.java#L13) exposes list and detail under `/v1/skills`. Both use `reloader.snapshot("default")`. Detail treats any hyphen as evidence that the caller supplied a qualified name. Otherwise it adds `default-`. It returns the original Framework descriptor directly; an empty result becomes `ResourceNotFoundException`.
- [ExecutionController.java, lines 41–67](../../../src/main/java/ai/loomspan/sidecar/api/ExecutionController.java#L41) repeats the catalog precheck, reads the capped JSON business object, calls `template.validate(name, input)` and admits the request with the original name, the measured input size, and the authenticated issuer/subject and JWT. POST returns 202, an `id`, and a context-relative poll path expanded into `Location`. GET polls by UUID and owner. The response maps the one `skillName` independently of `result`, `failure`, `configurationSnapshotId` and conditional `events`.
- [JwtSecurityConfiguration.java, lines 55–81](../../../src/main/java/ai/loomspan/sidecar/security/JwtSecurityConfiguration.java#L55) applies authentication to `/v1/**` with a stateless bearer chain. The new namespace URLs are already covered. The observability routes have separate Framework authentication; management uses an earlier chain. Authenticated requests are needed to establish 404 on deleted routes because unauthenticated calls to the old URL can still be intercepted by `/v1/**`. Role extraction preserves exact names.
- [ApiExceptionHandler.java, lines 13–43](../../../src/main/java/ai/loomspan/sidecar/api/ApiExceptionHandler.java#L13) maps Sidecar input problems and Framework `SkillInputValidationException` to 400, `AccessDeniedException` to 403, and Sidecar missing-resource exceptions to 404. There is no catch-all mapping for `IllegalArgumentException` or `SkillReloadException`. Payload, capacity and readiness errors use 413, 429 and 503. The cache filter adds `no-store` for every response.
- Discovery remains unfiltered by skill roles. Framework validation enforces role requirements on submission. If the active generation changes between request-time precheck and validation, or between validation and the queued handoff, those are separate Framework observations today. The precheck is metadata only. Request-time validation holds its own release-scoped capture and does not give Sidecar a worker reservation.

### Public Framework identity and failure distinctions

The matching Framework checkout uses two exact portable components. Each is 1–64 ASCII characters and matches `[a-z][a-z0-9]*(?:-[a-z0-9]+)*`, with no `anthropic` or `claude` substring. For pair validation the length is `namespace.length() + 2 + localName.length()` and at most 64. A namespace-only request applies its component rules. `order-support` allows 49 characters in a local name. Hyphens have no owner-separator role.

| Supported operation or type | Observed contract and source |
| --- | --- |
| `SkillReloader.snapshot(namespace)` | Exact active namespace, including an installed empty namespace. Malformed names throw `IllegalArgumentException`. Valid absent namespaces throw public `SkillReloadException` with `No active namespace '...'`. The exception type also represents operational failures on other reloader operations, so the finding is specific to snapshot. [Public interface](../../../../loomspan-framework/src/main/java/ai/loomspan/api/SkillReloader.java#L45), [lookup implementation](../../../../loomspan-framework/src/main/java/ai/loomspan/internal/skill/DefaultSkillReloader.java#L137), [generation manager](../../../../loomspan-framework/src/main/java/ai/loomspan/internal/skill/SkillGenerationManager.java#L120). |
| `SkillCatalog.skill(localName)` | Validates the complete namespace/local pair and returns an empty optional on an absent local name. Malformed components, qualified strings supplied as the local name, and an overlength valid-looking pair throw `IllegalArgumentException`. Lookup is exact within this snapshot. [Public interface](../../../../loomspan-framework/src/main/java/ai/loomspan/api/SkillCatalog.java#L11), [lookup implementation](../../../../loomspan-framework/src/main/java/ai/loomspan/internal/skillapi/DefaultSkillCatalog.java#L61). |
| `ValidatedSkill(namespace, localName, kind)` and `SkillDescriptor(namespace, localName, description, kind, inputSchema, outputSchema)` | Public constructors check the pair without a catalog, input, provider, or authorization. Both have exact `namespace()`, `localName()` and `qualifiedName()`. The public value tests explicitly exercise grammar and 49/50-character boundaries. | `SkillTemplate.validate(namespace, localName, input)` and `SkillInvocationHandoff.handoff(namespace, localName, input)` | Capture the exact pair before input conversion and enforce current authorization. [Template](../../../../loomspan-framework/src/main/java/ai/loomspan/api/SkillTemplate.java#L17), [Handoff](../../../../loomspan-framework/src/main/java/ai/loomspan/api/SkillInvocationHandoff.java#L14), [capture implementation](../../../../loomspan-framework/src/main/java/ai/loomspan/internal/skillapi/DefaultSkillTemplate.java#L150). |

The public API package has no standalone pair validator. Catalog detail cannot run until its namespace exists. This matters when the HTTP route includes both an absent namespace and a malformed local name or overlength pair. Public constructors provide evidence of a validation operation independent of namespace availability. Framework internals linked here explain the public behavior; the Sidecar architecture tests prohibit application and test imports from those packages.

## Dependencies and Operational Constraints

- The pinned `ai.loomspan:loomspan-spring-boot-starter:1.0.0-beta.10-SNAPSHOT` comes from the local Maven repository. The parent orchestrator has begun the required sibling Framework install with its prescribed Mockito agent. Sidecar builds against that artifact. Source references use the sibling Framework checkout, with framework-only verification recorded separately in the handoff. Repository policy defers hosted CI until the release artifact is published.
- Sidecar uses Java 21, Maven 3.9.11, loopback JWT/callback/model fixtures, temporary SQLite databases and Playwright. Prior Sidecar full-suite evidence used local Chromium 1187 and native Windows permissions. `src/main/resources/application.yml` defaults the JWT audience to `loomspan-sidecar` and storage to `/sidecar/data/sidecar.db`; local verification needs an explicit isolated DB path.
- Docker CLI is present and the Linux daemon did not answer when the prior pipeline checked. No real provider is needed. A native Java CLI may use `--server.address=127.0.0.1`, a selected local port, `--loomspan-sidecar.configuration.mode=file`, `--loomspan.skills.locations=file:/.../examples/quickstart/sidecar/skills/*.yaml`, a `--spring.config.additional-location` pointing to the checked-in execution YAML and a local JWKS path. The Python host writes `jwks.json` under `QUICKSTART_KEY_DIRECTORY` and needs OpenSSL, port 8081 and a writable temporary directory. The SDK review separately exercised native fixture token signing and callback verification.
- Each SDK can reuse a fresh `/token` JWT against a native verification instance. Java core exposes `CredentialSnapshot.of(token)`; Python's `CredentialSnapshot(token)` supports sync and async clients. The checkout's installed Python venv carries dependencies. The public Python `run` examples currently submit a `text` business key, while the planner expects `message`; direct SDK methods allow the planner's correct map. Fixture responses restart after the fourth request and `/status` contains cumulative callback records. Sequential runs can distinguish callbacks by count or use a fresh host. Current management seed tests and the quickstart walkthrough's authenticated publication are separate ways to initialize database mode without contacting any live service.
