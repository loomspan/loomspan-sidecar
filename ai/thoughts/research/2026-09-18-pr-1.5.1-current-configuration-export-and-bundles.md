# Current Configuration Export Research

## Research Question
Where do runtime configuration, management authorization, and console access currently reside?

## Summary
`RuntimeConfigurationService` publishes a `ConfigurationSnapshot` into a volatile field during activation. Its `current()` also consults the database, whose intended pointer can differ from the running snapshot. A separate captured published reference is available under the service's publication lock. No export or bundle reader exists.

## Repository State
`main` at `560f1a7e26c209eba2a1311ad8bc84dc6cec87b9`; the roadmap and three new tickets were already modified/untracked. They are preserved as developer work.

## Current Behavior and Data Flow
`ConfigurationSnapshot` contains local/source identity, sequence, content, and status. `ManagedConfiguration` copies the skill list and requires unique nonblank source labels; `SkillDocument` carries label and exact YAML. REST authored text is `restRoutesYaml`. `ConfigurationSnapshotStore` creates an active empty snapshot on first startup. Publication holds `publication`, switches framework state, then assigns `published`; status recording and pruning occur afterward. `current()` can fetch stored status, while `withEditingState()` reads the volatile published snapshot under a short transition gate.

## Affected Areas
| Area | Current behavior and evidence |
| --- | --- |
| Runtime | Published reference differs from intended database selection during faults (`RuntimeConfigurationService`). |
| Console | Current page is read-only and fetches JSON; no download control (`ManagementPagesController`, `console.js`). |
| Security | Authenticated management users can read current configuration; editing mutations require editor (`ManagementSecurityConfiguration`). |
| Storage | History and private drafts have distinct paths and need not be read for export (`ConfigurationSnapshotStore`, `ManagementEditingService`). |
