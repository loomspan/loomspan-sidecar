# Synchronous Python SDK research

## Research Question

What does the current Sidecar API and Java SDK expose for existing-credential
discovery, submission, status and waiting? Which transport facilities have evidence
for a synchronous absolute I/O deadline, native interruption, and ordinary SSL
contexts on the Python support target?

## Summary

Sidecar already exposes the four HTTP routes required for the SDK. Its Java
client supplies the acceptance, status parsing, diagnostic fidelity and error
baseline. There is no existing Python SDK package in this checkout. The observed
Java behavior and a bounded local transport probe are independent evidence.

## Current Behavior and Data Flow

- [JWT security](../../../src/main/java/ai/loomspan/sidecar/security/JwtSecurityConfiguration.java#L58)
  authenticates `/v1/**`. Catalog reads use the default public Framework
  snapshot. A short lookup name may resolve to a qualified descriptor such as
  `default-echo`. Descriptor names must be preserved as returned. A string
  equality check against the discovery lookup argument would reject this
  supported behavior.
- [Execution submission](../../../src/main/java/ai/loomspan/sidecar/api/ExecutionController.java#L41)
  checks the skill, reads an object through the capped reader, validates it via the
  Framework, then admits work for the authenticated owner. It returns HTTP 202
  with `{"id": "<UUID>"}` and Location. The Java SDK uses the body UUID and
  constructs its own local status URL. Status lookup enforces ownership and
  returns HTTP 200 even for a failed execution.
- [Execution serialization](../../../src/main/java/ai/loomspan/sidecar/api/ExecutionController.java#L54)
  writes `id`, `skillName`, `status`, `createdAt`, `completedAt`, `result`,
  `failure`, `configurationSnapshotId` and conditionally `events`. Failure
  includes `kind`, `message` and optional `issues` with path, code and message.
  [The coordinator](../../../src/main/java/ai/loomspan/sidecar/execution/ExecutionCoordinator.java#L219)
  sets configuration identity when work enters RUNNING and retains the final
  result/failure with the history selected by diagnostics policy. The Framework
  public event record carries timestamp, level, type, details, frame ID and route.
  History may be absent, and a present list may be empty. Sidecar emits Java
  Instant timestamps, which can have more than six fractional digits.
- [Java response parsing](../../../sdks/java/core/src/main/java/ai/loomspan/sdk/SidecarClient.java#L297)
  requires a descriptor object with nonblank name/kind/inputSchema and optional
  description/outputSchema as text. Status requires canonical UUID syntax,
  requested-ID equality, skill, known state and valid creation instant. Terminal
  states require completion time. FAILED also requires a failure object. Event
  details must be an object. Optional text preserves null and empty. Known
  fields are selected and additive fields are tolerated. Result text is never
  parsed again, including JSON-looking text. Issue lists default to empty.
  Java copies event detail data on construction and access, and copies list
  containers. Duplicate names at any object depth and trailing JSON tokens are
  disabled by the Jackson configuration at lines 45–47.
- [Java client transport](../../../sdks/java/core/src/main/java/ai/loomspan/sdk/SidecarClient.java#L151)
  applies Authorization to each request, disables auth handling and sends
  `Accept: application/json`. Its builder disables retry, redirect, cookie and
  compression behavior. The response deadline watchdog cancels the request, and
  cleanup cancels before closing immediately. Content-Length can reject early.
  Streaming still counts bytes even if length was absent. Local validation
  includes the base URL, object input, credential, ID and closed state. Valid
  base paths survive, and one path segment is encoded per skill name. Java
  rejects blank, C0/C1 control, slash, backslash, percent and the whole names
  `.` and `..`. Java `String.isBlank()` and Python `str.isspace()` differ
  for some Unicode spacing characters, including nonbreaking spaces.
- [Java error handling](../../../sdks/java/core/src/main/java/ai/loomspan/sdk/SidecarClient.java#L196)
  classifies observed non-2xx as HTTP failure and exposes a complete bounded JSON
  object only after replacing credential occurrences in keys and string values.
  It discards malformed, trailing or oversized bodies and preserves HTTP status.
  An invalid/unusable 202 or unexpected 2xx on submission leaves acceptance
  unknown. An invalid/unusable status/discovery response is a protocol failure.
  Java conservatively treats I/O failure from its dispatched execute call as
  uncertain for POST when no non-2xx status was observed. It does not infer IDs.
  Credentials accept printable ASCII excluding spaces and DEL, hide their token
  in the default display, and offer no public getter.
- [Java wait](../../../sdks/java/core/src/main/java/ai/loomspan/sdk/SidecarClient.java#L120)
  repeats only successful QUEUED/RUNNING reads, returns COMPLETED/FAILED,
  caps each request and poll sleep against the same monotonic deadline, and
  stops on the first read failure. Standalone status errors retain the requested
  ID. Wait errors retain that ID and the last good snapshot. In Java's specific
  I/O catch path, wait expiry is checked before reclassifying the observed status.
  The Python ticket and design independently require preserving observed HTTP
  failures and carrying wait context. Native Python interruption and future
  async cancellation are deliberate differences from Java's interrupt flag API.

## Dependencies and Operational Constraints

- [HTTPX synchronous timeouts](https://www.python-httpx.org/advanced/timeouts/)
  bound inactivity of individual reads/writes. Public `iter_raw` supports raw
  streaming and HTTPX accepts an SSLContext, but timing around iterator yields
  cannot stop a read still in progress. Applying a timed join to a background
  caller has the same shortcoming. [libcurl's timeout](https://curl.se/libcurl/c/CURLOPT_TIMEOUT.html)
  covers the transfer, while [PycURL's TLS setup](https://pycurl.github.io/docs/dev/quickstart.html)
  uses libcurl certificate/trust settings and does not expose a Python SSLContext
  interface for the provided configuration.
- [h11 0.16.0](https://pypi.org/project/h11/0.16.0/) publishes a pure-Python
  wheel and provides [public HTTP/1.1 framing events](https://h11.readthedocs.io/en/stable/api.html)
  with bounded incomplete events, independent of network I/O. Python
  [socket](https://docs.python.org/3/library/socket.html#socket.socket.settimeout)
  and [SSLContext](https://docs.python.org/3/library/ssl.html#ssl.SSLContext.wrap_socket)
  expose timeouts on connect, handshake and raw reads/writes. Timeout-mode
  `sendall` and `do_handshake` cap the whole respective call, and each fresh
  `recv` can receive the remaining time from an absolute monotonic deadline.
  A single-use socket can close without draining an incomplete response.
- Bounded feasibility probe, separate from production tests: Windows x86-64,
  CPython 3.13.13, `uv run --no-project --with h11==0.16.0 python -`. A local
  fixture sent status and headers, then either stalled or wrote one byte every
  20 ms. Using a 120 ms budget and the remaining time before each blocking
  socket read, both paths ended at 124 ms. h11 retained the observed 503
  and 200 respectively, and the peer observed EOF or socket abort after client
  shutdown. Windows can report an abort on the peer when the client closes
  with unread bytes. The probe did not exercise production lifecycle or TLS.
- Platform hostname lookup is a distinct boundary. The Apache 5.6.1
  [connection operator](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.1/httpclient5/src/main/java/org/apache/hc/client5/http/impl/io/DefaultHttpClientConnectionOperator.java#L179)
  invokes the [system resolver](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.1/httpclient5/src/main/java/org/apache/hc/client5/http/SystemDefaultDnsResolver.java#L44)
  before creating the socket, and [cancellation](https://raw.githubusercontent.com/apache/httpcomponents-client/rel/v5.6.1/httpclient5/src/main/java/org/apache/hc/client5/http/impl/classic/InternalExecRuntime.java#L275)
  discards the endpoint without aborting an in-progress OS resolver call. Python
  `socket.getaddrinfo` also has no portable timeout/cancellation parameter.
  Resolver latency can consume a budget without a subsequent HTTP dispatch.
  This is distinct from a stalled TCP/TLS/HTTP exchange after resolution.
- The host has Windows CPython 3.13 and uv. WSL Ubuntu is available on x86-64,
  with system Python 3.8.2. A target-range Linux interpreter was not observed
  in the initial WSL check. macOS ARM64 was not observed. The phase targets
  CPython 3.12–3.15 on Linux and one target-version run on each Windows and
  macOS ARM64. This probe establishes one transport facility on one platform.
- The ticket authorizes local synthetic verification and normal dependency
  resolution. No real Sidecar instance, paid providers, publication, push or
  operational data changes are in scope here. No development data reset applies.

## Open Questions

- Planning owns transport selection and the supported dependency range. Evidence
  remains necessary for in-flight close and native KeyboardInterrupt, TLS
  handshake and client identity, the entire wait budget, and deadline accounting
  across connect, headers, request upload and body framing.
- Timestamp representation and validation must preserve Sidecar's fractional
  precision. Java Instant additionally accepts an extended year range and
  ISO_INSTANT edge spellings beyond ordinary Sidecar production timestamps.
- Planning must resolve pre-write network error classification and the precedence
  between an observed HTTP error and wait expiry while reading that error body.
  The observed-status requirement in the ticket governs Python's behavior.
