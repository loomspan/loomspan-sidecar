# Java SDK PEM signing research

## Research Question

What currently implements Java signing, Spring configuration, public exports and
token verification; which maintained consumers and tests depend on the contracts
being replaced by PR 11.1?

This is Step 1 of the developer-approved Full 5-Step Pipeline. Research describes
the current checkout; the ticket and shared PEM design define the requested future
contract. No implementation or test execution occurred in this step.

## Summary

The Java SDK is an independent two-module Maven reactor under `sdks/java`, outside
the root Sidecar reactor. Core currently supports PEM, JKS and PKCS12 signing;
Spring exposes all three with password references and optional signing certificates.
All feed the same RS256 source and issuance path. The existing PEM envelope check
is only prefix/suffix based and its decoder is MIME Base64, so the source does not
establish the new exactly-one-block contract.

Atomic export, fresh colocated identity, fixed provided identity, public thumbprint
and safe diagnostics already have substantial focused tests. Certificate and
keystore support are mixed into those tests and their helper. Existing Sidecar
tests validate public JWK trust and real HTTP security, but use Sidecar fixture
tokens rather than the SDK signer. The maintained neighboring suite has actual
SDK-to-Sidecar-to-callback recipes and explicit consumers of the obsolete settings
and constructor. Its private signing fixtures already use unencrypted PKCS#8.

### Core configuration and initialization

`sdks/java/core/src/main/java/ai/loomspan/sdk/SigningSettings.java:6` is a public
record with explicit mode, colocated directory and nested provided settings. Its
`Provided` record at line 7 carries format, key location, alias, two password
references, certificate location and public-export path. The compact constructor
at line 11 rejects unknown/missing modes and mixed modes; provided mode requires
format, key location/export and format-specific options.

`SigningKeys.java:23` initializes once at startup. At line 27 it chooses the export
(`key-directory/jwks.json` or explicit provided path), validates provided collisions,
then creates a fresh 2048-bit RSA pair in colocated mode. It checks the directory
exists and does not create it. Provided mode branches at line 42:

- PEM reads the whole file, strips surrounding whitespace, checks PRIVATE KEY
  prefix/suffix, removes delimiter strings, and MIME-decodes the remaining text.
  JCA RSA `KeyFactory` consumes a `PKCS8EncodedKeySpec`. It requires an
  `RSAPrivateCrtKey` to derive the public modulus/exponent.
- Optional PEM certificate input uses the JCA X.509 certificate factory.
- Keystore mode resolves store/key passwords, uses `KeyStore.getInstance(File,
  char[])`, checks the detected format, looks up the alias and certificate chain,
  and clears resolved password arrays.

The common path validates RSA strength of at least 2048 bits and verifies a
sign/verify challenge. Certificates can trigger a 30-day expiry warning. A Nimbus
RSA public key computes RFC 7638 `kid`; the exported JWK has public `kty,n,e`,
`kid,use=sig,alg=RS256` and optional `x5c`. `LocalSource` at line 134 stores private
material privately and exposes only `signRs256`, RSA public key and kid through
`SigningKeySource.java:6`. Diagnostic catches do not attach parser/provider causes;
source `toString` is redacted.

`SigningKeys.java:116` protects input paths by absolute normalized equality and,
for existing files, `Files.isSameFile`. The current input inventory includes the
private key, certificate and file-backed passwords. `publish` at line 150 writes a
temporary sibling, moves with `ATOMIC_MOVE` and `REPLACE_EXISTING`, and cleans up
the temp file in `finally`. No fallback move exists. A package-private
`FileOperations` seam at line 159 provides deterministic write/move failure tests.
The injected clock is used for signing-certificate warning timing.

`SecretReference.java:8` is a public signing-secret helper accepting env references
or absolute UTF-8 files. It strips one terminal line ending and redacts itself.
Repository and sibling-suite searches found its production consumers only in
SigningSettings, SigningKeys and SigningProperties, with tests only in the signing
