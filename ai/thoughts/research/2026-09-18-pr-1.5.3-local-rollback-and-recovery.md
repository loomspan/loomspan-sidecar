# Local Rollback and Recovery Research

## Research Question

How do retained history, destructive import, runtime publication, management authorization, and stopped SQLite recovery currently work, and what executable evidence exists for them?

## Summary

The checkout has immutable, full-content local snapshots with a nullable source ID, retained history inspection, and a database-first publication path. The import workflow already validates a complete candidate, binds explicit review to the uploaded bytes and current runtime/lease grant, then holds publication and editing gates through a destructive cutover (`ManagementConfigurationImportService.java:57-112`, `RuntimeConfigurationService.java:171-277`). There is no rollback review/confirm endpoint or browser action in the current controller and history view (`ManagementConfigurationController.java:103-137`, `console.js:130-179`). Recovery documentation and a stopped database copy test exist, but the current test verifies configuration selection/history only, not management account recovery (`README.md:197-258`, `RuntimeConfigurationRecoveryIntegrationTest.java:99-120`).

## Current Behavior and Data Flow

### Storage, history, and startup

`V1__configuration_snapshots.sql:1-42` stores snapshot content, ordered skill documents, a nullable `source_id`, status, and one selected sequence; triggers prohibit content updates. `ConfigurationSnapshotRepository.java:22-46` allocates a fresh random local UUID and pending status for every insertion; `:48-90` reads history in ascending sequence and reconstructs complete authored content. `ConfigurationSnapshotStore.java:74-90` inserts and switches the intended pointer in one transaction, guarded by the expected current ID. Its `revert` transaction restores the predecessor and records `FAILED` (`:93-113`). Reads by local ID return null when absent (`:115-118`). Pruning counts all statuses, protects the selected snapshot plus caller-protected IDs, and defaults to ten (`:130-151`, `SidecarSnapshotProperties.java:8-27`).

At startup the runtime takes the committed pointer, prepares skill documents, stages matching REST resources, publishes, records `PUBLISHED`, prunes, then opens execution (`RuntimeConfigurationService.java:78-123`). It does not silently select an older snapshot when selected content is invalid (`ConfigurationSnapshotStore.java:153-172`). A committed `PENDING` record can therefore be the next startup selection. The runtime's `Current` and `Inspection` keep running and intended IDs/status separate (`RuntimeConfigurationService.java:32-39,279-334`).

### Existing import and publication transition

Import review reads one bounded temporary ZIP, parses format 1, validates the full destination candidate, counts content, captures runtime/lease observation, and saves a review ID plus upload digest in the session only when validation succeeds (`ManagementConfigurationImportService.java:57-74,149-174`). Confirmation rereads and hashes the upload, revalidates, checks the same session review and live account/session, then calls `runtime.importConfiguration` (`:76-135`). A stale runtime snapshot or replacement lease grant yields refreshed observation; lease renewal retains the same grant ID (`:94-145`, `ManagementEditingState.java:22-39`).

`RuntimeConfigurationService.java:171-197` holds the publication lock and editing transition lock, rechecks health, admission, current runtime ID, and lease grant before acceptance. `publishCandidate` calls public framework `prepare(Collection<SkillDocument>)`, prepares and validates REST resources, stages a new generation, and only then clears all drafts and leases for import (`:199-226,336-349`). It inserts the new snapshot with source provenance and changes the intended pointer before framework publication (`:217-239`). A failure before cutover leaves editing state intact; a failure after cutover leaves drafts discarded. Publication failure discards staged resources and attempts pointer reversion with `FAILED` status; unreverted failure sets a mutation fault (`:241-259`). A status-write failure after successful activation leaves runtime active, marks mutation fault, and reports a bookkeeping error rather than reverting (`:261-277`). `requireHealthy` blocks subsequent configuration mutations when faulted (`:384-386`).

Ordinary publication enters through `ManagementEditingService.publish` and `RuntimeConfigurationService.publish`, using the publication lock but without destructive prepublication draft clearing (`RuntimeConfigurationService.java:153-167`). Editing operations take the shared transition gate (`:365-382`); `ManagementEditingState.java:13-61` holds ephemeral drafts, lease session/tab/grant, and clear operations. Session/account invalidation shares this gate. The accepted publication runs beyond the HTTP session lifecycle; existing integration tests cover browser disconnect for import and ordinary publication (`ManagementConfigurationHttpIntegrationTest.java:432-463,744-781`).

REST resources are bound to process-local framework generations and durable snapshot IDs, retained while generations remain admitted, then retired and closed (`GenerationRestResources.java:18-107`). Pruning includes resource-protected IDs (`RuntimeConfigurationService.java:359-363`). The matching framework checkout documents `SkillReloader.prepare(Collection<SkillDocument>)` as a fresh frozen complete replacement and `publish` as activation; it says generation IDs are process-local and retirement callbacks, not publication, signal resource release (`C:/opendev/code/loomspan-framework/README.md:199-230`).

### Management HTTP and browser

The controller exposes current, export, oldest-first history list, exact history detail with 404 `history_not_found`, ordinary publish, and import review/confirm (`ManagementConfigurationController.java:50-137`). Import conflicts return 409 with refreshed observation and publication failures return runtime/intended state and fault codes (`:150-193`). `ManagementSecurityConfiguration.java:42-85` protects the management path with form session auth; import and editing mutations require `MGT_EDITOR`, while other authenticated history/current reads include viewers. Spring Security CSRF applies to management POSTs; JWT execution uses a separate security chain (see `JwtSecurityConfiguration.java`). `ManagementSessionGuard.java:22-59` enforces idle expiry and advances activity only on explicit activity reports.

The history page currently presents retained list and exact detail with live text status (`ManagementPagesController.java:116-127`). `console.js:10-19,72-97` builds nodes and assigns authored content with `textContent`; `:130-179` renders status/source/current marker, checks detail identity, clears detail after 404, and refreshes history. There is no rollback control in that detail flow. The import page separately shows source/producer/validation/runtime/lease information, a draft-loss warning, and explicit confirmation (`ManagementPagesController.java:162-175`, `import.js:23-59`). Its confirm UI distinguishes stale confirmation, known activation/bookkeeping faults, and unknown disconnected outcome (`import.js:98-137`).

### Backup and recovery

`StorageConfiguration.java:59-116` uses one local SQLite path with foreign keys, WAL, synchronous FULL, and a five-second busy timeout. Migrations create configuration snapshots and management account/token tables (`V1__configuration_snapshots.sql`, `V2__management_identity.sql`). The documented stopped procedure copies `sidecar.db` and existing `-wal`/`-shm` companions, removes stale destination companions before restore, sets ownership to UID/GID 10001, restarts, and notes that the committed pointer controls selection (`README.md:197-258`). The console's recovery page currently gives a shorter read-only version (`ManagementPagesController.java:129-138`). `RuntimeConfigurationRecoveryIntegrationTest.java:99-120,171-175` copies the database file set between stopped contexts and checks restored pointer/history and runtime activation; its backup point is the initial empty snapshot and it does not verify account login or management/configuration access after restore.

The configuration ZIP carries the running snapshot's authored skills and routes but excludes retained history, accounts, private drafts, sessions, leases, environment values, URL allowlists, SMTP/model connections, and SSL bundles (`README.md:645-657`). It preserves sensitive authored literals (`:680-684`). Import is rejected by the runtime mutation fault gate (`RuntimeConfigurationService.java:182-185,384-386`). The existing README distinguishes database recovery from ZIP import and warns that `PENDING` does not prove activation (`README.md:686-695,755-797`).
