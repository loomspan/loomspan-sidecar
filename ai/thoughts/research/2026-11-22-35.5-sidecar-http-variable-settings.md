# Sidecar HTTP variable settings research

## Research question

Trace the existing file-startup and HTTP invocation paths, the ownership of
fixed and caller credentials, and the fixtures and checks affected by 35.5.

## Summary

Sidecar's HTTP executor already reads the Framework's captured executor and
skill configuration maps and validates both during invocation. The current
fixed-auth path reads encrypted records from the executor map and decrypts
them per invocation. Caller passthrough independently reads request
authentication from Spring Security. The managed candidate builder is the
sole production caller of the HTTP credential attachment helper. Its removal
is assigned to 35.6.

## Current behavior and data flow

- `src/main/java/ai/loomspan/sidecar/configuration/ConfigurationModeConfiguration.java:17`
  selects `file` or `database`. The file path leaves configured skill
  locations and settings to Framework startup. Database mode substitutes
  empty bootstrap skill locations and filters deployment execution settings.
- Framework's public `SkillExecutorInvocation` exposes immutable captured
  `executorConfig()` and `skillConfig()` maps separately from `input()`.
  The 35.1–35.4 Framework handoff at
  `ai/thoughts/future/framework-variable-references-handoff.md` in the
  sibling checkout documents exact whole-node markers, startup lookup via
  the effective Spring `Environment`, captured resolved strings, and the
  separate explicit-map preparation contract. Framework 35.4 covers startup
  selection and resolution from one cache across effective connection,
  namespace executor and configured executor-backed skill settings. That
  evidence is Framework behavior, with Sidecar qualification still required.
- `src/main/java/ai/loomspan/sidecar/http/HttpSkillExecutor.java:20` registers
  the supported `@SkillExecutor` bean. It validates invocation executor
  settings and the selected operation, maps invocation input, then copies
  target headers. The fixed branch adds values by decrypting records from
  the selected executor settings through `ProviderCredentialCipher`. It
  catches decryption/value-validation failures and returns a generic error.
- `src/main/java/ai/loomspan/sidecar/http/HttpExecutorConfiguration.java:31`
  accepts a fixed target only with `auth.header-refs` and requires its record
  identifiers in the top-level `credentials` inventory. The current header
  validator (`:136`) rejects case-insensitive duplicates, invalid HTTP names,
  transport/framing and cookie headers, ordinary `Authorization`, and certain
  payload headers under the separate reference path. The case-insensitive
  lookup helper also governs `Content-Type` for JSON bodies. Operation
  validation (`:62`) includes target selection, allowed methods, path rules,
  JSON Pointer mappings, body and recoverable statuses.
- `src/main/java/ai/loomspan/sidecar/http/HttpRequestMapper.java:16` fills
  complete path placeholders from mapped invocation input, guards segments,
  and URL-encodes the selected values. It does not look up installation values.
  `HttpExecutorClient.java:31` sets headers once on the outgoing request and
  sends through the shared Apache pool with redirects, retries and cookie
  handling disabled.
- `src/main/java/ai/loomspan/sidecar/execution/ExecutionCoordinator.java:177`
  rechecks authenticated execution credentials before handoff and binds the
  security context during Framework admission. `HttpSkillExecutor.java:35`
  requires an authenticated `JwtAuthenticationToken` whose expiry is after
  the current clock instant, and adds `Bearer ` followed by the original
  token. The caller token is not in either captured configuration map.
