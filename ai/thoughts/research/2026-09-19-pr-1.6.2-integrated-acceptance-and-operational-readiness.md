# Integrated acceptance and operational readiness research

## Research Question

What current Sidecar code, fixtures, checks and operator instructions support the ticket's complete browser/application/Compose, interruption and recovery acceptance, and what integrated evidence is still absent from the checkout?

## Summary

The checkout has the production Compose definition, a disposable production verifier, a Playwright HTTPS login exercise, fixture SMTP and model/JWT host services, stopped database backup/restore instructions, and many focused Sidecar integration tests. The production verifier currently exercises locked setup, emailed initial setup and recovery, browser login, authored publication, REST/model execution, container recreation, stopped backup/restore, and SIGTERM completion/cutoff (`scripts/verify-production.py:113-307`). It does not currently exercise invitation, concurrent browser editing, two-instance export/import and destination binding, local rollback, invalid import preservation, or interruption at the publication pointer boundary in the Compose deployment. Those behaviors have narrower Java tests and documented contracts; the ticket seeks new combined deployment evidence.

No tests or containers were run in this research step. Existing passing claims in older tickets and docs are historical, not verification of this checkout.

The identity service provisions the initial administrator by setup credential, issues invitation/reset links, and stores password changes; forgotten-password lookup masks missing account/delivery outcomes (`src/main/java/ai/loomspan/sidecar/management/ManagementIdentityService.java:68-160`). 3. **Editing and publication.** Browser assets `src/main/resources/static/management/assets/{console,editor,import}.js` drive protected API operations. Management editing endpoints enforce session/tab/lease/candidate ownership, while the runtime service serializes publication, imports, rollback and editing transitions (`src/main/java/ai/loomspan/sidecar/management/ManagementEditingService.java`; `src/main/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationService.java:154-221,393-408`). Destructive import/rollback clears all drafts at cutover after preparation/staging; failures before cutover leave them intact. Activation failure attempts pointer reversion; failed reversion or post-activation bookkeeping fault stops mutations. `README.md:137-192,600-666,690-719` documents the state and API contracts. The production verifier uses management HTTP to acquire a lease, save/validate/publish the quickstart YAML/REST fixture and then executes REST `identityLeaf` and model-backed `quickstartPlanner` with JWT, checking the durable configuration ID and authored `${TARGET_URL}` text (`scripts/verify-production.py:77-112,242-254`). 4. **Export, import and rollback.** `ConfigurationBundleV1` encodes the current published authored configuration, and the management import/rollback services guard review/confirmation with the exact source candidate, current runtime ID and lease grant (`src/main/java/ai/loomspan/sidecar/bundle/ConfigurationBundleV1.java`; `src/main/java/ai/loomspan/sidecar/management/ManagementConfigurationImportService.java`; `ManagementConfigurationRollbackService.java`). `RuntimeConfigurationService.java:174-221` resolves rollback source from local retained history under publication/editing locks and checks destination validation; both paths call the same fresh publication method. `README.md:668-719,758-839` distinguishes configuration ZIP from local history, documents destination URL allowlist/binding and destructive draft policy, and says no source history or accounts move. `RuntimeConfigurationIntegrationTest.java:586-617` already tests two service instances and authored bundle transfer; it is not two independent production Compose installations or a real browser round trip. `ManagementImportBrowserIntegrationTest` and `ManagementHistoryBrowserIntegrationTest` cover narrower UI behavior.
