# Embedded Console and Account Flows Research

## Research Question

What browser surface, account/session contracts, published-configuration data, packaging, and executable evidence exist before PR 1.4.1?

## Summary

Sidecar has server-rendered minimal setup, login, recovery, password-change, and home pages, plus JSON account/session and protected configuration APIs. There is no application-owned frontend asset tree or browser workflow implementation. The management security chain uses form login, server sessions, role authorities and CSRF; the separate execution chain uses JWTs. `GET /api/management/configuration/current` already returns a complete runtime-published snapshot with separately identified intended database selection.

## Current Behavior and Data Flow

### Browser entry and account lifecycle

`ManagementPagesController` constructs HTML strings for `/management/login`, `/setup`, `/forgot`, `/password/set`, `/password/reset`, `/home`, and `/password/change` (`src/main/java/ai/loomspan/sidecar/management/ManagementPagesController.java:20-100`). It embeds Spring's CSRF token in each POST form (`:106-108`) and escapes the emailed token inserted into a hidden input (`:62-68`). The setup page distinguishes unreserved, reserved and activated bootstrap text, but always renders the setup form (`:29-40`). The home page currently shows the signed-in email/role, sign-out form and password-change link, without account administration or configuration views (`:79-85`). Password-link pages show a generic invalid-link-or-password message after failure and direct successful users to sign in normally (`:70-78`).

The JSON API at `/api/management` exposes `GET /session` with id, email, role, effective permissions and CSRF token; `POST /session/activity`, `/logout`, `/setup`, `/password/forgot`, `/password/{set,reset,change}`; and admin account listing, invitation, alteration and resend (`src/main/java/ai/loomspan/sidecar/management/ManagementController.java:51-121`). Setup and password-token requests are attempt limited. Forgot requests return the same accepted response regardless of address or throttling (`:77-85`); identity handling also suppresses database/mail failures for that path (`ManagementIdentityService.java:116-125`). API email unavailability is 503; identity/input rejection is a generic 400 (`ManagementController.java:132-143`).

The one-time setup credential comes from `LOOMSPAN_SIDECAR_SETUP_TOKEN`, is validated as canonical unpadded base64url for 32 bytes, and is compared without persisting plaintext (`ManagementIdentityService.java:48-59,195-206`). Setup reserves one email in SQLite, issues a 24-hour password-set link, and lets only that address retry a failed delivery while reserved (`:67-89`). Redeeming the set link activates bootstrap; it does not create a session (`:128-146`). Invitations use the same 24-hour set-link path; resets use a 30-minute link (`:91-123`). Tokens are random, SHA-256 digested in storage, expiring and single-use; a new token consumes earlier account tokens (`:179-193`). Password set/reset/change increment credential version and clear editing state (`:128-169`); login is possible only for enabled accounts with a password hash (`ManagementAccountRepository.java:9-10`, `ManagementUserDetailsService.java:43-52`).

Email is normalized to lowercase and validated before storage; the account API has no email edit operation (`ManagementPolicy.java:12-20`, `ManagementController.java:105-121`). Password policy is 15–128 Unicode code points and at most 512 UTF-8 bytes, with uppercase, lowercase, digit, and non-whitespace punctuation/symbol; spaces are allowed but do not count as symbols (`ManagementPolicy.java:22-40`). The existing password-set page gives shorter guidance without the byte cap or space distinction (`ManagementPagesController.java:62-68`). SQLite's account update guards the last enabled activated administrator inside the SQL write (`ManagementAccountRepository.java:67-72`).

`ManagementMailService` requires a configured SMTP host/sender and trusted external HTTPS base URL (loopback HTTP is allowed), creates links from that URL, and maps delivery exceptions to a safe unavailability error (`ManagementMailService.java:29-59`). The form setup path catches delivery errors and tells the user to check configuration and retry (`ManagementPagesController.java:42-46`). The anonymous forgot form uses the same generic response (`:54-60`). Missing mail is not a startup or execution gate; the code checks availability only for email-dependent actions.

### Session, authorization and execution boundary

The order-1 security chain matches `/management/**` and `/api/management/**`, permits only login/setup/forgot/link paths anonymously, requires `MGT_ADMIN` for accounts/takeover, `MGT_EDITOR` for editing mutations/publication, and authentication for the remaining management requests (`ManagementSecurityConfiguration.java:32-84`). Spring form login posts email/password to `/management/login`, redirects success to `/management/home`, and logout invalidates the session (`:62-75`). CSRF remains enabled for this chain. `ManagementUserDetailsService` grants viewer to all roles, editor to editor/admin, and admin to admin (`ManagementUserDetailsService.java:43-52`). The session guard rechecks account activation/version and a 30-minute default meaningful-activity timestamp on each authenticated management request; reads alone do not advance it (`ManagementSessionGuard.java:25-38,40-70`, `SidecarManagementProperties.java:9-22`). The JSON activity endpoint deliberately reports activity; lease activity joins editor and login renewal (`ManagementController.java:59-63`, `ManagementEditingController.java:62-70`). Logout/session expiry also clear session-owned editing via session lifecycle integration.

The order-2 chain is stateless, disables CSRF, authenticates `/v1/**` with JWT, and denies other unmatched paths (`JwtSecurityConfiguration.java:87-105`). Management accounts and JWT identities therefore have different routes and authority sources. `NoStoreResponseFilter` sends `Cache-Control: no-store` globally and `Referrer-Policy: no-referrer` for management paths (`src/main/java/ai/loomspan/sidecar/api/NoStoreResponseFilter.java:14-26`). Session cookie defaults are HttpOnly, SameSite=Lax, Secure (`src/main/resources/application.yml:48-54`).

### Published configuration inspection

`GET /api/management/configuration/current` returns `RuntimeConfigurationService.Current`, whose `published` field is the full `ConfigurationSnapshot`; `intendedId`, `intendedStatus`, and `mutationFault` are separate (`ManagementConfigurationController.java:20-35`, `RuntimeConfigurationService.java:30-34`). `current()` holds the publication lock, reads the runtime-published snapshot and corresponding store record, and returns the runtime object if storage lookup fails (`RuntimeConfigurationService.java:244-259`). History endpoints expose retained full submitted snapshots, with 404 for a missing/pruned ID (`ManagementConfigurationController.java:37-45`). A snapshot has local/source IDs, submission sequence, status, and `ManagedConfiguration` (`ConfigurationSnapshot.java:6-19`). Its skill documents and REST YAML preserve exact authored text and source labels, without parsing/resolving placeholders (`ManagedConfiguration.java:10-28`). The README explicitly says viewer inspection includes literal sensitive values (`README.md:554-570`). Runtime startup selects the database snapshot, prepares/stages/publishes it, and only then opens execution dispatch (`RuntimeConfigurationService.java:78-105`).

The private editing API returns only the caller session's draft and validation; acquiring a lease, saving, validating and publishing require tab/grant/candidate identifiers (`ManagementEditingController.java:41-105`, `ManagementConfigurationController.java:47-50`). The ticket's current-configuration screen can read the published endpoint without accessing those private results. Future browser authoring belongs to PR 1.4.2.

### Packaging and deployment

The Maven build targets Java 21 and Spring Boot 4.1.0, depends on the locally installed `loomspan-spring-boot-starter:1.0.0-beta.5-SNAPSHOT`, and repackages an executable JAR (`pom.xml:12-20,39-56,125-132`). The Dockerfile copies only that JAR into the runtime image and exposes application port 8080 plus health port 9091 (`Dockerfile:1-17`). Application resources currently contain YAML, Flyway migrations and the controlled empty skill source; no `static`/`public` frontend asset directory appears in `rg --files`. `application.yml` contains management idle/lease, sender/base URL and standard `spring.mail.*` values, including five-second SMTP timeouts (`src/main/resources/application.yml:13-17,33-44`). README states the browser surface is on the application port; 9091 is health-only (`README.md:433-442`).
