# Python SDK FastAPI Integration Research

## Research Question

What checked-out SDK contracts, Java callback behavior and FastAPI/ASGI
boundaries govern the PR 10.5 integration, and what evidence already exists?

## Summary

Python already has an async execution client, an explicit synchronous token
issuer and an async callback verifier that owns trust refresh. Each works without
a web framework. No FastAPI module, optional dependency group or executable
FastAPI example is present. Callback route matching, raw HTTP credential
selection, application lifespan composition and request identity transfer are
the web integration gaps. The Java SDK establishes the HTTP semantics; ASGI
server parsing and Starlette routing differ from the servlet firewall.

## Current Behavior and Data Flow

**Client.** `AsyncSidecarClient` validates URL, deadlines, response size and TLS
context through the shared `_client_options`. Constructor state consists of
transport configuration and synchronization objects. Context entry checks
that the client is open; network I/O starts on operation, not entry. Client
exit closes the local transport, cancels active exchanges and waits for local
connection cleanup. The client can be shared by tasks within an async runtime.
The credential is passed per operation, including status and waiting. Neither
client close nor native cancellation calls a remote cancellation endpoint.

**Issuance and export.** `AuthenticatedIdentity` freezes the application-selected
subject and exact authorities. `IssuanceSettings` validates the issuer, roles
and independent positive lifetime. `ExecutionTokenIssuer` construction is
synchronous and initializes signing and public export. Colocated signing
generates a fresh key; provided signing loads strict unencrypted PKCS#8 RSA
material without fallback. Export is an atomic replacement of public-only JWKS
in an existing directory. A successful publication can precede a later startup
failure in a composed app; no public-export deletion or rollback contract exists.
The issuer has no close operation. `issue` intersects exact names with the
allowlist and returns the opaque per-operation credential.

**Verification and refresh.** `CallbackVerifier.open` validates the issuer and
optional audience/path, reads its public material directly and initializes
configured overlap trust off-loop. The issuer name is the default callback
audience. Without overlap, no background polling or read of the issuer's export
occurs. With overlap, successful initialization enters the refresh task group;
the first unusable overlap file fails entry, while detected runtime invalidity
empties all trust including the own key. Recovery publishes the complete valid
set. The context closes trust, releases waiters and cancels the worker. The
AnyIO task-group scope is entered and exited by the owning lifespan task.
`verify` checks the selected trusted key and JWT claims/signature and applies
the 60-second skew at verification time. Its immutable `CallbackPrincipal`
contains only issuer, subject and exact authorities. Later trust changes do
not mutate the principal. Sidecar's HTTP executor separately rejects credentials
whose expiry is at or before its clock immediately before passthrough.

**Java HTTP baseline.** A highest-precedence stateless callback filter chain
matches the literal prefix at a segment boundary in the servlet context.
Prefix settings strip one trailing slash and reject blank, root, empty/dot
segments, whitespace/control, wildcard and path-syntax markers. Audience and
overlap settings reject explicit blanks. The resolver checks the raw query
names with UTF-8 URL decoding, rejects malformed percent syntax and any exact
decoded `access_token` name, and rejects duplicate or malformed bearer headers.
The bearer regex is ASCII token characters and one space after a case-insensitive
Bearer scheme. Cookies and form bodies are outside callback credential
selection. Missing/invalid credentials produce 401 and `WWW-Authenticate:
Bearer`; authenticated non-GET/POST and business authorization denials produce
403. The servlet firewall can reject TRACE or malformed paths before the filter.

**FastAPI and Starlette behavior.** Inspected FastAPI 0.162.2 and Starlette
1.10.0 in an isolated Windows CPython 3.13 environment.

- FastAPI's `__call__` applies its configured `root_path` before entering
  Starlette. Starlette sets `scope["app"]` to the currently entered application.
  Starlette's router strips the root only if the decoded path equals it or has
  a slash at that boundary. If the root does not appear there, routing uses the
  supplied path as is. `Mount.matches` extends `root_path` while retaining the
  original decoded `path` and optional `raw_path`. A separately configured root
  on a mounted FastAPI child overrides the inherited root in FastAPI's call.
  URL rendering incorporates host and escapes path delimiters; the ASGI scope
  and routing calculation provide separate evidence from URL rendering.
- The router handles lifespan messages on the main application and dispatches
  mounted apps through matching HTTP/WebSocket routes. FastAPI documents that
  mounted sub-apps do not get automatic lifespan startup. Starlette's router
  sends startup/shutdown failure on exceptions and re-raises. `request.state`
  is a view of the scope's state dictionary, while `request.app.state` belongs
  to the app selected by `scope["app"]`. These are different lifetimes. Normal
  FastAPI overrides are app-specific mappings keyed by the dependency callable.
- `add_middleware` inserts first among user middleware; the last registration
  wraps earlier ones. CORS answers preflights directly and can skip everything
  inside it. Login/CSRF middleware can also terminate before invoking downstream
  code. When browser policy runs inside the callback guard, the application can
  still apply its own policy to a successfully authenticated callback unless it
  scopes that policy to browser routes. FastAPI/Starlette routing on its own
  provides slash redirects and method handling, so router outcomes alone do not
  establish the SDK boundary.
- ASGI supplies a decoded path, optional raw path, raw percent-encoded query
  bytes and a header list retaining duplicates. `receive` is the request-body
  channel. Uvicorn 0.54.0's h11 protocol decodes the raw path with `unquote`,
  prepends configured server root to both path forms, and responds 400 to
  `h11.RemoteProtocolError` before constructing a scope. A direct h11 0.16.0
  parser probe accepted TRACE plus paths containing `//`, `;`, `%2f`, `%ZZ`,
  `%00` and dot segments. Raw target space and raw NUL were rejected. This is
  specific to the examined backend, distinct from a reverse proxy or another
  server's behavior.

## Affected Areas

| Area | Current behavior and evidence |
| --- | --- |
| Typed construction and app ownership | Core validation and resource lifetimes are separate entry points; the issuer performs I/O on construction, and no ASGI app currently coordinates these resources. |
| Callback prefix, methods and credentials | Python's verifier starts at an extracted token. No Python HTTP boundary applies the Java prefix/method/credential rules today. |
| Browser and business authorization | Authentication, record ownership and CSRF are separate Java concerns. The design keeps existing application login and business checks, with callback ownership determined by verified issuer plus subject. |
| Identity lifetime | Verifier returns an immutable snapshot. No Python request-local bridge or admission-through-handler lifecycle evidence exists. |
| Packaging and examples | `sdks/python/pyproject.toml:6` has core-only dependencies and `__init__.py:3` exposes independently usable core classes. The only checked-in scripts are existing-credential sync and async examples. |

## Open Questions

- Planning must fix the exact malformed-path classification and its scope
  around mounts/root prefixes. ASGI `raw_path` is optional, and middleware
  receives only the path left by the server and any preceding proxy. Preserve
  ordinary non-callback routing while accounting for aliases to the protected
  segment boundary. The design specifies HTTP GET/POST callbacks; the prefix
  can also be presented to a FastAPI app as a WebSocket scope.
- Planning must choose dependency bounds to exercise and how the installed
  smoke evidence drives example submission/callback behavior. The probes
  establish a current viable dependency set, not support at untested bounds.
- There is no existing FastAPI startup failure, omitted lifecycle, CORS/login
  ordering, mounted/root-path, concurrent cleanup, or withdrawal/expiry
  admission-through-handler test. These evidence gaps belong to this ticket.
