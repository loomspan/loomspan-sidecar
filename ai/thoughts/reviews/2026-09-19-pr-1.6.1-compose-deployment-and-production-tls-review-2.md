## Findings

### [P1] Require STARTTLS when production SMTP is configured to use it
- Location: `examples/production/compose.yaml:27` and `src/main/resources/application.yml:48`
- Scenario: A configured SMTP server, or an intermediary, does not advertise STARTTLS while the production example supplies SMTP authentication credentials and `SMTP_STARTTLS=true`.
- Impact: Angus Mail's `mail.smtp.starttls.enable` is opportunistic; the SMTP connection continues without TLS and can send login credentials in plaintext.
- Evidence: The production Compose file initially set only `LOOMSPAN_SIDECAR_SMTP_STARTTLS`; the application mapped only `mail.smtp.starttls.enable`. The installed Angus Mail 2.0.3 package Javadoc states that when STARTTLS is unavailable the connection continues without TLS unless `mail.smtp.starttls.required` is true.
- Fix: Map `mail.smtp.starttls.required` in application configuration and set the production Compose value to follow `SMTP_STARTTLS`. Document the fail-closed behavior and test rejection by a fixture SMTP server without STARTTLS.

## Findings Resolved in This Context
