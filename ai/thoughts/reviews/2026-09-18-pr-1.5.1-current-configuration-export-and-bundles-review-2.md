### [P2] Exercise the inclusive compressed-input boundary
- Location: `src/test/java/ai/loomspan/sidecar/bundle/ConfigurationBundleV1Test.java:172`
- Scenario: The ticket explicitly requires boundary checks for allowed and excessive ZIP input sizes. The test exercised 100 MiB plus one byte, but did not exercise exactly 100 MiB.
- Impact: A future off-by-one change could reject a permitted 100 MiB input while the test suite passed.
- Evidence: `compressedInputLimitCountsBytesActuallyRead` initially asserted only `MAX_ZIP_BYTES + 1`; the reader uses `total > MAX_ZIP_BYTES`.
- Fix: Added an exactly 100 MiB synthetic input assertion that reaches ZIP validation and fails as an invalid archive, alongside the existing oversize assertion. The focused test passes.
