## Findings

### [P2] Reject invalid parameters on the `rsaEncryption` identifier

- Location: `sdks/java/core/src/main/java/ai/loomspan/sdk/SigningKeys.java:93`.
- Scenario: The provided PEM contains an otherwise usable RSA key and a valid
  ASN.1 `INTEGER` as the `rsaEncryption` algorithm parameter.
- Impact: Startup accepts and publishes an identity from malformed PKCS#8 even
  though the ticket requires invalid material to fail before publication.
- Evidence: A compiled-loader probe accepted the mutated fixture. The added
  focused test then failed because initialization threw no exception. The
  algorithm specifies a NULL parameter. [RFC 8017, Appendix A.2.2](https://www.rfc-editor.org/rfc/rfc8017.html#appendix-A.2.2)
- Fix: Reject a present non-NULL parameter for this OID using the existing ASN.1
  types. Preserve successful loading and identity when the parameter is absent.

## Findings Resolved in This Context

The loader now rejects the invalid parameter before JCA key construction and
publication. The regression test preserves the prior public export and proves
that a key with absent parameters retains the expected `kid`. A separate probe
of the final SDK classes accepted a disposable key emitted by the maintained
suite's actual fixture generator and produced exactly its independently derived
public JWK. Re-review found no remaining actionable findings.
