## Findings

### [P2] Enforce PEM boundary lines and complete Base64

- Location: `SigningKeys.java:74` before review fixes.
- Scenario: Join the final Base64 line to the end delimiter or remove the
  synthetic fixture's required Base64 padding.
- Impact: Both malformed forms started a signer and published JWKS.
- Evidence: The compiled initializer accepted both mutations. The focused
  regression failed before the fix. The standard textual grammar uses a final
  line break before the end delimiter. [RFC 7468 §3](https://www.rfc-editor.org/rfc/rfc7468#section-3)
- Fix: Require the end boundary on its own line and complete Base64 quanta.
  Keep ordinary surrounding whitespace and LF, CRLF and CR support.

### [P2] Validate optional PKCS#8 fields as well as outer framing

- Location: `SigningKeys.java:81` before review fixes.
- Scenario: Append a tagged attributes field inside the PKCS#8 sequence and
  adjust the sequence length. The field can contain a truncated TLV or a
  complete TLV of the wrong type. The optional v2 public field likewise permits
  a DER object of the wrong type when parsed only by JCA.
- Impact: The outer length check passed, and the JDK created a signer from the
  malformed key container. Providers that validate optional fields can reject
  that same input.
- Evidence: The regression first establishes that valid attributes preserve the
  same kid. The malformed attribute mutations and a NULL in the public field
  succeeded before the fix. OpenJDK's PKCS#8 decoder skips both optional fields.
  [OpenJDK PKCS8Key](https://raw.githubusercontent.com/openjdk/jdk21u/master/src/java.base/share/classes/sun/security/pkcs/PKCS8Key.java)
- Fix: Use Bouncy Castle 1.86 ASN.1 types to consume the complete structure and
  validate optional attributes. If the container includes an RSA public field,
  require it to match the signer's derived public fields. The dependency replaces
  the handwritten length check. JCA still performs RSA key construction, signing
  and verification. Valid optional fields remain usable.
  [RFC 5208 §5](https://www.rfc-editor.org/rfc/rfc5208#section-5),
  [RFC 5958 §2](https://www.rfc-editor.org/rfc/rfc5958#section-2)
