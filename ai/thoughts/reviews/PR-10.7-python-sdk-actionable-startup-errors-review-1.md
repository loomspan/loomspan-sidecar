## Findings Resolved in This Context

### [P2] Report a malformed BER integer as invalid key material

- Location: `sdks/python/src/loomspan_sdk/_signing.py:95`
- Scenario: A provided PEM wraps a BER sequence with a zero-length INTEGER.
- Impact: Startup rejects the key but advises checking the SDK runtime when
  replacing the invalid key is the appropriate remedy.
- Evidence: The real BER decoder raises `IndexError` while reading the empty
  INTEGER. The public issuer regression using a synthetic malformed PEM
  reproduced the generic fallback before the fix.
- Fix: Normalize the decoder's `IndexError` at the structural read so it uses
  the sanitized invalid-key diagnostic. The regression asserts that the input
  and prior export survive and that displayed diagnostics omit backend details.

### [P3] Tell developers to use a file destination for the public JWKS

- Location: `sdks/python/src/loomspan_sdk/_signing.py:144`
- Scenario: `jwks_export` names an existing directory under a writable parent.
- Impact: Publication fails closed. The previous message only advised checking
  the parent directory and write or replacement permissions, which can all be
  correct while the destination is a directory.
- Evidence: The existing invalid-destination test reproduced the failure with
  a real directory as the export target.
- Fix: Add the file-path remedy to the shared publication message and
  troubleshooting guide. Assert it in the invalid-destination test.
