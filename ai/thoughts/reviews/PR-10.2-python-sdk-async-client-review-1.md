## Findings Resolved in This Context

### [P2] Preserve native cancellation when client shutdown overlaps

- Location `sdks/python/src/loomspan_sdk/_async_transport.py:48` and the exchange scope now at line 105.
- Scenario. A status task is suspended on a loopback response. Client
  `aclose()` and the application's `Task.cancel("caller cancellation")`
  reach the task in one asyncio turn.
- Impact. Both cancellations entered the caller's task. Asyncio combined them
  into a native exception carrying the SDK's AnyIO cancel-scope message in
  place of the application's message. A deadline using the same ownership
  had the same exposure.
- Evidence. A real-socket probe and
  `test_caller_cancellation_keeps_its_message_when_client_closes` reproduced
  the substituted message on Windows with AnyIO 4.16.0. The test also checks
  peer-observed release, one request and the absence of SDK state on the exception.
- Fix. A task group joins each exchange and polling delay. The SDK-owned
  scopes act on their child task, and caller cancellation reaches the caller
  separately. The exchange still registers its cleanup owner before its first
  await and uses absolute deadlines computed before the child starts. The close
  test checks exchange completion and peer closure without requiring the caller
  to have already resumed when local resources are released.
