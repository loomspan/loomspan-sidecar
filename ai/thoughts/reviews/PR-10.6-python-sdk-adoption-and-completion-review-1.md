## Findings Resolved in This Context

### [P2] Verify the wheel in both running Python containers before recording evidence

- Location — Suite `scripts/baseline.py:24`, called by `scripts/smoke.py` and the capture/replay paths.
- Scenario — Stage a newer wheel with the same SDK version and record its digest while the existing Python containers are still running from the prior build. The Java packages can already match.
- Impact — Smoke and replay could label an old runtime with the new wheel's digest. The same gap could affect the app or the shared fixture image independently.
- Evidence — The focused regression reproduced both false passes with distinct expected and running digests. The Dockerfile installs its sole wheel from `/sdk` and retains the input in the image. Matching `importlib.metadata` versions alone cannot distinguish same-version wheels.
- Fix — Check the actual SHA-256 of the image-local wheel in both selected containers before returning the recorded baseline. Report the service and rebuild action on a missing or stale wheel.

### [P2] Make the public trust mount traversable by Sidecar on Linux

- Location — Suite `scripts/prepare.py:32` and `compose.yaml` trust-directory mounts.
- Scenario — A fresh Linux installation provisions under umask `077`. The app publishes a public `0644` JWKS under a `0700` directory while Sidecar runs as UID `10001`.
- Impact — Sidecar cannot open the public trust file, and readiness waits for usable trust even though the app has started.
- Evidence — The regression reproduced `0700` on the disposable Linux image. The existing file permission change only affects the JWKS entry and directory traversal still requires execute permission.
- Fix — Make the fixed public-only directory `0755` on POSIX, rejecting link targets before changing its permissions. The private PEM remains outside that directory at `0600` on POSIX. The regression passes inside Linux and preserves the PEM mode.

### [P3] Document the current callback mount

- Location — Suite `docs/suites.md:39` and its new-suite instructions.
- Scenario — The suite boundaries guide directed consumers to a prefixed Python callback alias and future suites to prefixed HTTP routes after the host removed the alias.
- Impact — The documented callback alias returns `404`. Applying the old instructions to a new callback could place it outside the SDK's guard.
- Evidence — `apps/python/app.py` mounts only `/skills`, and `test_sdk_execution_boundary` asserts denial for the removed alias.
- Fix — Describe `/skills` as the protected callback mount, distinguish prefixed public APIs, and retain suite-owned authorization.
