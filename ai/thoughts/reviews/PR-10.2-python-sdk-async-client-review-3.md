## Active Project Guardrails

- Shared HTTP framing and validation directly replace the old sync-only
  helpers. Each transport retains its native I/O and resource ownership.
- TLS stays verified, operator-provided contexts retain the private-CA and
  client-identity options, and authenticated closure is required for a
  TLS-delimited body. The request builder uses only the configured destination
  and the operation's own credential. Error decoding runs outside the caught
  transport exceptions and redacts credentials in usable HTTP problems.
- Product docs describe current behavior and examples. This SDK-only diff
  touches no Framework APIs, server state, stored credentials, or release
  configuration. No development-data reset applies.

## Open Questions and Assumptions

- The supported sharing boundary is one async application runtime per client.
  The focused executable verification uses asyncio.
- A system resolver or trust load already running can finish after its
  caller's bounded await. A trust load still running can temporarily prevent
  a new HTTPS connection from starting. The implementation plan and README
  record this behavior, and the focused suite verifies recovery after the
  verified context is cached.
