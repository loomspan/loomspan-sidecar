## Findings

### [P3] Replace the loading placeholder when history refresh fails
- Location: `src/main/resources/static/management/assets/console.js:195`
- Scenario: The history list loads, an exact-detail request returns
  `history_not_found`, and the subsequent history refresh returns 503.
- Impact: The list area continues to say “Loading retained submissions…” after
  the request has ended, contradicting the error status and obscuring the
  refresh/current recovery choices.
- Evidence: `loadHistory()` replaced the list with a loading paragraph before
  both GETs, but its non-authentication error branch only changed the status
  element. The existing browser test covered this 503 branch without checking
  the list's terminal state.
- Fix: Replace the list placeholder with a textual failure/retry message on
  non-authentication errors, and assert the terminal list state in the 503
  browser case.
