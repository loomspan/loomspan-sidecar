## Findings

### [P2] Make the fixture TLS key readable by the non-root container

- Location: `scripts/verify-production.py:154`
- Scenario: On Linux CI, OpenSSL creates `privkey.pem` as root-owned mode `0600`; the production Compose service runs as UID 10001 and mounts that key read-only.
- Impact: The production verifier fails at TLS startup in hosted CI, so the required deployment gate cannot establish the release candidate's behavior.
- Evidence: Reproduced OpenSSL's `600:0:0` key mode in a Linux `python:3.13-slim` container. A UID 10001 read failed before changing the file to `0644` and succeeded afterward. The verifier had no permission adjustment between OpenSSL and container startup.
- Fix: Set mode `0644` on the disposable fixture key after generation. The temporary parent directory remains `0700` on the host; the operator's production key permissions are unchanged.

## Findings Resolved in This Context

- Applied the fixture key permission fix at `scripts/verify-production.py:158-160`. Re-reviewed the full ticket diff and found no remaining actionable issue.
