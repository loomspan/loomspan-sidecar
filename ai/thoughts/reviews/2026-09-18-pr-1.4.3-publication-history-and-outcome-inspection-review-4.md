## Findings

### [P2] Ignore superseded Current responses
- Location: `src/main/resources/static/management/assets/console.js:205`
- Scenario: The initial Current request is slow; a user refreshes after publication, receives the new runtime snapshot, then the initial response arrives.
- Impact: The older snapshot replaces the newer one while the page says it is showing the runtime-published configuration. A user investigating an uncertain publication can draw the wrong conclusion.
- Evidence: Before the fix, `loadCurrent` rendered each completed response without ordering protection. The new `olderCurrentResponseCannotReplaceNewerRefresh` browser test held the first response, displayed the second, released the first, and failed because the stale UUID replaced the current UUID.
- Fix: Increment a Current request revision on each load and render or report an error only for the latest revision; retain the existing authentication failure handling.

## Findings Resolved in This Context

- Fixed the P2 overlapping Current-response race in `console.js` and added a deterministic authenticated Playwright regression. The targeted test failed before the fix and the complete browser class passed after it. The post-fix diff review found no remaining actionable issue.
