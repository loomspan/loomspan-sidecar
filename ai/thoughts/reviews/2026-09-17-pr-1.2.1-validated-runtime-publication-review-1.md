## Findings

### [P2] Preserve available skill and route locations in validation and startup failures
- Location: `src/main/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationService.java:110`; `src/main/java/ai/loomspan/sidecar/rest/RestRouteCatalogValidator.java:19`
- Scenario: A named YAML skill has an invalid field, or a REST skill has no authored route. Framework preparation and route validation identify the document or route field, but validation returned a generic `candidate` issue or omitted the route location. Invalid selected content also produced a generic startup error.
- Impact: Operators could not locate a rejected candidate or selected startup fault without inspecting every document, contrary to the source-labelled diagnostics requirement.
- Evidence: The framework's public `SkillReloadException` wraps a cause naming `Byte array resource [missing-description.yaml]` and `field 'description'`; the pre-fix service discarded that information. The route validator knew the affected skill name but emitted no structured location marker.
- Fix: Extract only known authored document labels and safe field paths from exception causes, add route field markers, and include a safe phase/source in startup errors. Do not echo arbitrary exception text or resolved URLs.

### [P2] Keep retired-client close work off framework callback threads during shutdown
- Location: `src/main/java/ai/loomspan/sidecar/rest/GenerationRestResources.java:96`
- Scenario: A retirement notification races with `stop()` after the cleanup executor rejects new work.
- Impact: The pre-fix rejection path closed the Apache client inline on the framework callback thread, allowing cleanup latency to delay retirement or shutdown notification.
- Evidence: `retire()` caught `RejectedExecutionException` and called `closeOwned()` directly; `stop()` already closes every owned resource, including one removed from the generation map but not yet queued.
- Fix: Leave rejection cleanup to `stop()`'s owned-resource sweep. Closure remains idempotent and no callback performs slow client teardown.

### [P2] Verify model-only durable execution correlation
- Location: `src/test/java/ai/loomspan/sidecar/execution/ExecutionConfigurationCorrelationIntegrationTest.java:33`
- Scenario: A model-backed skill has no REST invocation; route-only correlation tests cannot demonstrate its durable ID capture and retention.
- Impact: A primary acceptance criterion lacked executable evidence for a distinct execution path.
- Evidence: The new correlation test previously exercised only a REST skill, while the authenticated nested test included REST work.
- Fix: Add a real framework, SQLite, and loopback-model execution that checks the captured durable ID after completion, publication, and retirement.

### [P3] Remove obsolete mounted-route settings from tests
- Location: `src/test/java/ai/loomspan/sidecar/LoomspanSidecarApplicationTest.java:16`; `src/test/java/ai/loomspan/sidecar/management/ManagementEndpointIntegrationTest.java:24`; `src/test/java/ai/loomspan/sidecar/security/ConsoleSecurityIntegrationTest.java:18`; `src/test/java/ai/loomspan/sidecar/security/JwtStartupIntegrationTest.java:134`
- Scenario: Several context tests still supplied the retired `loomspan-sidecar.rest-routes-location` property and custom empty discovery patterns.
- Impact: Those tests appeared to exercise a mounted configuration source although the property was ignored, obscuring which startup path they covered.
- Evidence: The production loader no longer reads the property, and the application configuration now points at the controlled packaged empty source.
- Fix: Remove obsolete overrides and run the tests through the database-selected default startup path.
