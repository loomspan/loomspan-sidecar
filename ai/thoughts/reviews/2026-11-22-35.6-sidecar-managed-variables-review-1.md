## Findings

### [P2] Report every missing authored occurrence during restoration

- Location `src/main/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationService.java:125`.
- Scenario A selected database snapshot restored without its referenced installation value contains two occurrences of the same variable. The runtime detects both but picks the first issue to report during startup.
- Impact The startup diagnostic identifies only one occurrence, so an operator cannot see all affected authored locations for the missing installation value.
- Evidence A disposable database selected an HTTP document that referenced `records.path` from `config.path` and `config.nested[0]`. The focused test failed before the fix because the startup exception omitted the second location.
- Fix Join the safe preparation locations and include the fixed missing or blank reason for each occurrence. Keep arbitrary provider exceptions and supplied values out of the startup diagnostic.

## Findings Resolved in This Context

- Startup now reports both authored locations with the missing-value reason. `RuntimeConfigurationRecoveryIntegrationTest.selectedConfigurationReportsEachMissingVariableLocationAtStartup` verifies the exact diagnostic fragments and that the failed activation retains the selected database pointer.
