## Findings

### [P2] Specify the required first-administrator credential format

- Location: `examples/production/README.md:33` (pre-fix text).
- Scenario: An operator follows the production guide's instruction to set a “strong random” `SETUP_TOKEN` and chooses a random string outside the application's required encoding and length.
- Impact: Management setup stays locked on the new installation even though the operator supplied a token, blocking the first administrator flow until the value is replaced.
- Evidence: `ManagementIdentityService.setupCredentialConfigured()` requires `decoded(setupCredential.get()) != null`; the root README specifies unpadded base64url encoding of exactly 32 random bytes. The production guide previously omitted that constraint while presenting itself as the ordered deployment procedure.
- Fix: State the exact format and provide the working `secrets.token_urlsafe(32)` generator in the production guide. Applied in this context.

No actionable findings remain after the fix and complete diff re-review.

## Findings Resolved in This Context

- Updated `examples/production/README.md:33-35` with the exact setup token format and generator. The harness already generates a conforming 32-byte token and exercises the real setup path; no code or test change was needed for this documentation defect.
