## Findings Resolved in This Context

### [P2] Process bundle payloads without retaining the full expanded archive
- Location: `src/main/java/ai/loomspan/sidecar/bundle/ConfigurationBundleV1.java:130`
- Scenario: A valid bundle approaches the documented 512 MiB expanded limit across many entries.
- Impact: The reader retained all entry byte arrays before decoding YAML into retained strings, creating avoidable whole-archive duplication and raising the chance of heap exhaustion at an allowed limit.
- Evidence: The initial reader populated a `Map<String, byte[]>` with every entry, then traversed that map to construct `ManagedConfiguration`. The ticket explicitly requires avoiding unnecessary whole-archive duplication.
- Fix: Index only ZIP entry metadata, parse the manifest, then read, verify, and decode each inventoried entry in turn. The actual-byte counter and CRC/SHA checks remain in the per-entry path.

### [P3] Reject empty producer versions required to be nonempty by the format schema
- Location: `src/main/java/ai/loomspan/sidecar/bundle/ConfigurationBundleV1.java:151`
- Scenario: A bundle declares an empty `sidecarVersion` or `frameworkVersion`.
- Impact: The reader accepted a manifest that violates the published format 1 schema, making the reader's structural validation inconsistent with the contract.
- Evidence: The schema specifies `minLength: 1`; the prior `text()` check accepted empty strings.
- Fix: Reject blank producer version values and add a malformed-manifest test.
