## Findings Resolved in This Context

### [P1] Bind confirmation fields to the server-reviewed observation
- Location: `src/main/java/ai/loomspan/sidecar/management/ManagementConfigurationImportService.java:30,100`
- Scenario: An editor reviewed a bundle while no lease was held. Another editor acquired a lease. The importer could send the new grant ID directly with the old review ID, without receiving or acknowledging the refreshed owner warning. The analogous runtime ID could also be substituted.
- Impact: The API could destructively clear another editor's draft and lease without confirmation tied to the observation shown during review.
- Evidence: The review session record previously held only ID and digest; the runtime compared client-supplied IDs only to current state. The existing stale-grant test sent the old grant value and did not cover forged current values.
- Fix: Store the reviewed observation with the digest, compare both submitted IDs to that server record at serialized admission, and update the record with a captured observation after a stale conflict. Return the same captured observation in the conflict body. Added an authenticated HTTP regression that submits a newly acquired grant directly with the old review token and verifies rejection and draft preservation.
