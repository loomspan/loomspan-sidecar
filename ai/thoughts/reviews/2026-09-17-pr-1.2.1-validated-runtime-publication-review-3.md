## Findings

### [P2] Label REST client staging errors with the authored source

- Location: `src/main/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationService.java:256` (before fix)
- Scenario: A route document parses, but HTTP client construction fails, for example because an SSL bundle cannot create its context. `validate()` reaches REST staging and returns the generic `candidate` issue.
- Impact: A caller cannot identify which authored document failed, contrary to source-labelled validation and actionable diagnostics. The generic text also conflates skill preparation with REST staging.
- Evidence: `validate()` sets `preparingSkills = false` before `stage()`, then calls `validationIssue()` on failure. That method formerly returned source `candidate` for staging exceptions outside route parser or catalog validation. The existing partial-client cleanup test did not assert the validation issue.
- Fix: The staging fallback now reports `rest-routes.yaml` and a secret-free REST staging message. Added a focused assertion for this failure path.
