## Findings

### [P2] Bind development HTTP ports to loopback

- Location: `examples/quickstart/compose.yaml:13`, `:46`, `:47` (pre-fix port mappings).
- Scenario: An operator follows the documented development-only HTTP quickstart on a host reachable from another machine.
- Impact: The fixture issuer/model service, JWT API, management console, and health port are reachable from other host interfaces over plaintext HTTP. The quickstart also intentionally uses a non-Secure session cookie.
- Evidence: Before the fix, `docker compose -f examples/quickstart/compose.yaml config --format json` rendered the three published ports without `host_ip`, which means Docker publishes on all interfaces. The ticket permits *local loopback* HTTP for development and README calls this a loopback example.
- Fix: Prefix all three published mappings with `127.0.0.1:` and check rendered host bindings in the image smoke verifier. Update the source-reference test to require the bound mappings.

## Findings Resolved in This Context

- Applied the loopback binding fix to `examples/quickstart/compose.yaml`, `scripts/verify-image.py`, and `ConfigurationReferenceTest`. Re-rendered Compose: every published quickstart port now has `host_ip: 127.0.0.1`. The image smoke and production verifier, including shutdown's quickstart-based fixture, passed after the fix.
- Re-reviewed the complete ticket diff after the fix. No actionable finding remains in this context; a fresh review is required because implementation artifacts changed.
