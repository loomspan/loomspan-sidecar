## Findings Resolved in This Context

### [P2] Validate the backup before removing the current database

- Location: `README.md:190`
- Scenario: An operator runs the restore snippet with an empty or wrong backup directory. The earlier snippet removed the current database, copied nothing, and allowed the next startup to create a new empty store.
- Impact: The documented recovery action could discard the only current database and silently seed a new installation.
- Evidence: The restore loop conditionally copied every member without requiring `sidecar.db`; `StorageConfiguration.dataSource` treats an absent database path as new.
- Fix: Check for the backup main file before removing any current file. Both backup and restore snippets now use `set -eu` so a failed directory creation or copy stops the procedure. Re-reviewed the edited instructions.
