## Findings Resolved in This Context

### [P2] Keep a changed file from inheriting an in-flight review
- Location: `src/main/resources/static/management/assets/import.js:87`
- Scenario: An editor starts review, changes the file selection before its response arrives, and then the old response renders and enables confirmation for the newly selected file.
- Impact: The console presents the wrong review summary and an enabled confirmation. The server digest check prevents publication of the changed bytes, but the required new-review browser step is skipped until a failed confirmation.
- Evidence: The review callback originally rendered its response without checking whether `selected` still referred to the submitted `File`. The file-change callback invalidated the summary, but the late response repopulated it.
- Fix: Capture the submitted `File` and render the response only if it is still selected. The browser test now holds a review response, changes the file, releases the response, and verifies that confirmation remains disabled.

### [P2] Show post-activation bookkeeping faults as active imports
- Location: `src/main/resources/static/management/assets/import.js:118`
- Scenario: Framework publication succeeds, but status recording or history pruning fails and the API returns `outcome_recording_failed` or `history_pruning_failed`.
- Impact: The console previously grouped this outcome under “Import failed or needs inspection,” obscuring that the imported configuration is running and mutations have stopped. The ticket requires the UI to distinguish activation, failed reversion, and bookkeeping outcomes.
- Evidence: `RuntimeConfigurationService.publishCandidate` assigns `published = submitted` before status recording; its fault response preserves the active runtime. The old browser branch ignored the failure code for every non-conflict HTTP response.
- Fix: Render separate messages for post-activation bookkeeping faults, failed pointer reversion, activation failure with successful reversion, and other unsuccessful responses. The browser test checks activation and bookkeeping messages.
