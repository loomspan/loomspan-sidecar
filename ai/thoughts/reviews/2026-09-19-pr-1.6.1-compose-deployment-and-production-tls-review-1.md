## Findings

### [P2] Isolate Compose fixture substitutions from the host environment
- Location: `scripts/verify-production.py:195`
- Scenario: An operator shell has `SMTP_PASSWORD` or another production Compose substitution variable set while running the deployment verifier. Compose gives that shell value precedence over `--env-file`.
- Impact: The controlled fixture can pass host credentials into its disposable container, visible through Docker inspection, and can run with unexpected model, JWT, or mail settings.
- Evidence: Rendering the checked-in Compose file with its example env file inherited the shell's SMTP username and password instead of the example values. Before the fix, every verifier Compose call inherited `os.environ`; the fixture env file alone did not enforce isolation.
- Fix: Pass an explicit subprocess environment with every fixture substitution pinned to the generated values, refresh it when the setup credential changes, and assert fixture mail/model values in the rendered configuration.

## Findings Resolved in This Context

- Applied the fixture environment isolation above to config, startup, recreation, stop, restore, and cleanup Compose calls. The rendered-config assertions catch future precedence regressions. Re-reviewed the full verifier and other ticket changes after the edit; no further actionable finding remained.
