## Findings Resolved in This Context

### [P2] Reject junctions before staging the SDK wheel

- Location: Suite `scripts/record_build.py:78`.
- Scenario: On Windows, `runtime-artifacts` or its `python-sdk` directory
  is an NTFS junction to a separate artifact directory. A regular SDK wheel
  with the requested name already exists at that destination.
- Impact: The staging command copies through the junction and overwrites the
  external wheel before rejecting the resolved directory. A rejected command
  can therefore modify artifacts outside the suite.
- Evidence: Both regression cases created a real junction in a disposable
  fixture and proved the external wheel lost its original sentinel bytes
  after the original command raised the expected directory error.
- Fix: Use the same directory safety check before staging and during
  verification. Reject symlinks and junctions at either directory level
  and require the resolved directory to stay inside the suite root.
  The test now verifies both external wheels and the suite baseline stay
  untouched when preflight rejects the paths.
