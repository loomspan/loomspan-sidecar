# Protected Configuration Management Testing Plan

## Change Summary

Add protected runtime/history inspection, pure public-framework validation of one exact private candidate, and lock-time authenticated Publish admission through the existing SQLite-first coordinator. The test contract must distinguish a rejected update from activation followed by failed bookkeeping.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| HTTP security | Viewer mutation, JWT-only access, CSRF bypass, foreign draft/result access | Real browser-session role and CSRF matrix in `ManagementConfigurationHttpIntegrationTest`; independent `/v1/**` JWT smoke |
| Validation | `prepare` silently stages a generation; partial/active metadata yields false REST result; warnings block | Public `SkillReloader.validate` spy/integration, complete-set add/remove/kind fixtures, issue assertions, no generation/history |
| REST validation | Route mismatch, URL allowlist/binding, SSL/auth error or client leak | Runtime/REST integration with sanitized YAML and owned-resource count or close observation |
| Candidate lifecycle | Equal-content edit, late result, discard or another session result is mistaken for current | Mutable clock/latch service and real HTTP concurrent requests; response conflict without old diagnostics |
| Publish admission | Request passes role/session/lease/base check before waiting on publisher lock | Latches at existing publisher hook; mutate account/session/grant/candidate while queued; assert no new submitted row |
| Accepted update | Logout, expiry, takeover, edit or client disconnect cancels or changes frozen B | Pause after admission before commit/publish, cause each loss, release, assert B content and final runtime/SQLite selection |
| History consistency | Mixed ID/content/status during publish/prune; pending outcome interpreted as failure | Coordinated readers with latches, retained order/content/source ID, pruned 404, injected status fault |
| Publication fault | HTTP says activation failed although B runs, or loses A/B and resource truth | Real framework/SQLite fault hooks and triggers through management POST; inspect response/current/history/catalog/resources |
| Runtime lifecycle | Editing invalidation race, stopped execution or extra drain | Existing execution/publication/shutdown tests plus targeted concurrent editing test and full `verify` |

## Existing Coverage and Environment Constraints

`ManagementEditingHttpIntegrationTest` has real HTTP form-login sessions, CSRF tokens, multiple browsers, roles, mutable clock and JWT fixture; extend its helper or create `ManagementConfigurationHttpIntegrationTest` following its local-port/temporary SQLite pattern. `RuntimeConfigurationIntegrationTest` has a real framework and SQLite coordinator, latches and stage hooks (`beforeCommit`, `beforeFrameworkPublish`, `beforeRevert`, `beforeStatus`). `RuntimeConfigurationRecoveryIntegrationTest` covers restart selection; `ConfigurationSnapshotStoreTest` covers transactional submit/revert/prune; `ConfigurationDraftTest` covers object-identity invalidation. `SupportedLoomspanApiArchitectureTest` enforces the supported framework package boundary. `pom.xml` uses Maven Surefire with Java 21 and the locally installed `1.0.0-beta.5-SNAPSHOT`; `README.md` documents `.\mvnw.cmd -B -ntp verify`. Tests use temporary databases, loopback HTTP and test JWT keys. No SMTP, production endpoint, live target service, framework build or release is needed. Framework-only validation tests do not count as Sidecar proof.

Use distinct per-test SQLite files and reset injected hooks/clocks/state. Latches need bounded awaits and `finally` release so a failing assertion cannot strand a test thread. Synthetic contents may use harmless placeholder names and sanitized values; assert secrets are absent from error bodies and logs only where captured, while authorized history correctly includes literal authored source. Avoid flaky sleeps for races.

## Tests to Add or Update

### 1. `managementConfigurationReadAndMutationSecurity`
- Type: Real HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`.
- Proves: Anonymous 401, JWT-only access to management 401, viewer GET current/history/detail 200 and validate/Publish 403, editor/admin own mutation with CSRF, missing CSRF 403, one admin cannot inspect/validate/publish another session's draft; management cookie does not grant execution `/v1/**` rights.
- Inputs/fixture: Browser helpers from `ManagementEditingHttpIntegrationTest`, separate viewer/editor/admin accounts, local JWT fixture.
- Doubles or boundary isolation: Real security chains and local-port HTTP; no external service.
- Edge cases: Wrong tab/grant/candidate, same-account second session, foreign admin, malformed UUID/body, no-store headers.

### 2. `validationUsesCompletePublicCandidateAndKeepsStructuredIssues`
- Type: Runtime/framework integration plus a narrow mocked resource failure case.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.

Map every public issue's severity/source/skill/field/message; warnings permit success and metadata; error results do not use unavailable metadata. REST checker uses proposed names/kinds, not active catalog.
- Inputs/fixture: Existing `restDocument`/route builders, second REST skill, non-REST YAML skill, malformed labelled document, a warning-producing document based on matching framework docs/tests.
- Doubles or boundary isolation: Real framework for behavior, Mockito spy/mock only to prove invocation or force sensitive client preparation failure.
- Edge cases: Add/remove REST skill, route to removed/unknown skill, route to kind-changed non-REST skill, missing route, duplicate labels, warning plus valid metadata. Assert no generic skill failure replaces structured diagnostics.

### 3. `validationChecksRestBindingsAndClosesTemporaryResources`
- Type: Runtime/REST integration.

### 4. `lateValidationNeverAttachesOrReturnsDiscardedResult`
- Type: Service race test and HTTP integration where possible.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementEditingServiceTest.java`, `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`, `ManagementConfigurationHttpIntegrationTest.java`.
- Proves: Exact candidate object and ID are required at final attachment; same-text save rotates ID/clears result; stale response is explicit 409 without obsolete issues. Another session, lease takeover/release/expiry, logout/session expiry, discard and publication invalidation cannot attach or receive old private diagnostics. Validation/status polling does not extend session/lease deadlines.
- Inputs/fixture: Mutable clock, saved candidate, latch at controlled validation boundary, two sessions/tabs.
- Doubles or boundary isolation: Stub only slow validation to hold the request; real editing state and HTTP guard for authorization cases.
- Edge cases: Edit to identical YAML, two concurrent validations for successive candidates, result after draft discard, expired lease with draft still present, session destroyed during check.

### 5. `publishedAndHistoryReadsAreCoherentDuringUpdateAndPrune`
- Type: Store and HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`, `ManagementConfigurationHttpIntegrationTest.java`.
- Proves: Current response contains runtime B content matching published ID; intended ID/status and fault remain distinct. History is ascending by sequence with immutable local/source IDs and literal authored content, including retained pending/failed rows. Detail of a pruned ID returns 404. Reads under publication/pruning coordination never return vanished documents or mixed A/B fields.
- Inputs/fixture: B/C submissions, low `max-retained`, injected pauses before commit/status/prune, SQLite transaction probes.
- Doubles or boundary isolation: Real SQLite; publisher hooks, bounded worker threads.
- Edge cases: During pending B, after failed revert, after status-recording fault, and between list/detail when pruning legitimately removes an old row. Pending is labelled unknown without inferred past success/failure.

### 6. `publishRechecksLiveAuthorityAfterWaitingForLock`
- Type: Real authenticated HTTP race integration.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`.
- Proves: Publisher lock is the admission point. A queued Publish cannot pass after account disable/role downgrade/version change, login idle expiry, logout, grant takeover/release/expiry, candidate edit/discard, or runtime base change; missing/failed validation is rejected before commit. Invalid requests create no B row or generation and preserve A.
- Inputs/fixture: Hold the fair publication lock in a first attempt using a bounded hook, then deliberately fail that attempt before commit so A and the queued request's base remain unchanged. While the second HTTP request waits, mutate one role/session/grant/candidate condition, release the first attempt, and assert that the second is rejected for that condition. Use a separate successful first publication to prove the queued base-change rejection. This prevents first-attempt invalidation from masking the intended race.
- Doubles or boundary isolation: Real HTTP/session/account store/framework/SQLite, hooks only for timing.
- Edge cases: Editor vs admin role, same-account second session, validation for older equal-content candidate, fault gate after prior attempt.

### 7. `acceptedPublishUsesFrozenContentDespitePrivateStateLoss`
- Type: HTTP and coordinator integration.
- Location: `ManagementConfigurationHttpIntegrationTest.java`, `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Proves: Once admission finishes, later logout, session/lease expiry, takeover, account disable/role change, draft save/discard, and browser disconnect do not cancel or substitute B. Successful activation clears all prior drafts/grants even if later status recording fails; failed ordinary publication preserves eligible drafts/grants.
- Inputs/fixture: Admission/barrier hook just before preparation or commit, sanitized distinctive B and subsequent C, concurrent browser operations.
- Doubles or boundary isolation: Local HTTP and SQLite; disconnect only local test client after server admission, then inspect through a new login.
- Edge cases: Concurrent draft operations at activation transition; execution dispatch remains available while update is paused.

### 8. `publicationResponsesMatchSqliteAndFrameworkTruth`
- Type: Real management HTTP plus framework/SQLite fault injection.
- Location: `ManagementConfigurationHttpIntegrationTest.java`, `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`, and `RuntimeConfigurationRecoveryIntegrationTest.java` where restart matters.
- Proves: Success returns B running/intended and invalidated drafts. Commit trigger failure leaves A running/intended and no B history. Publish failure with successful revert leaves A running/intended and failed B retained. Failed revert leaves A running, intended pending B, mutation fault and blocked configuration mutation while reads/cleanup continue. Failed outcome recording leaves B running/intended, pending status unknown, mutation fault and blocked mutations. Responses carry distinct nonsecret stage codes/IDs; no blind retry. Resources retain A/B appropriately; account administration remains independent of configuration mutation fault.
- Inputs/fixture: Existing SQLite `fail_switch` trigger and runtime hooks; real `SkillReloader` catalog; query submitted rows/status.
- Doubles or boundary isolation: Local SQLite and framework only.
- Edge cases: Pruning fault, inspection storage-read failure fallback, restart selection of pending intended B (existing recovery policy), successful invalidation preceding later bookkeeping failure.

### 9. `executionAndArchitectureRegressions`
- Type: Existing integration/architecture suite.
- Location: `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`, existing execution/JWT, `RestHandlerLifecycleIntegrationTest.java`, `RuntimeConfigurationIntegrationTest.java` and shutdown tests.
- Proves: No unsupported framework dependencies, JWT execution identity remains separate, old generation clients live until retirement, no second shutdown drain, and execution remains available while publication is pending/faulted.
- Inputs/fixture: Existing test fixtures.
- Doubles or boundary isolation: Existing local test boundaries.
- Edge cases: Admission during update, post-activation fault.
