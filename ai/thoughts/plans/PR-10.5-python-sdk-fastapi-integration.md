# Python SDK FastAPI Integration Implementation Plan

## Overview

- Ticket [PR 10.5](../tickets/PR-10.5-python-sdk-fastapi-integration.md).
- Research [FastAPI integration](../research/PR-10.5-python-sdk-fastapi-integration.md).
- Deliver one explicit FastAPI integration for reusable invocation resources and
  prefix-wide callback authentication. The developer selected the Full 5-Step
  Pipeline at Step 0. The ticket baseline is clean HEAD `7e1533a`.

## Current State

`sdks/python/src/loomspan_sdk/_async_client.py` owns the reusable async client
and validates client options through `_http._client_options`.
`_issuance.ExecutionTokenIssuer` initializes signing and atomically publishes
public-only JWKS. `_callback.CallbackVerifier.open` validates startup trust and
owns async refresh and cleanup. Its result is an immutable `CallbackPrincipal`.
None of these entry points assumes a web framework. Java
`CallbackProperties` and `CallbackSecurityAutoConfiguration` define the HTTP
prefix, credential and method baseline. FastAPI currently has no integration in
the Python SDK.

## Desired End State

Applications compose their existing lifespan with `Loomspan.lifespan(app)`,
register `CallbackMiddleware` and use standard FastAPI dependencies and routers.
Construction validates typed configuration. Startup initializes the signing
owner, current callback trust and reusable client, then publishes the bundle to
the owning application. Callback authentication occurs before application
middleware and router dispatch. The downstream handler can use the immutable
verified identity and apply its own authority and record checks. The bare
distribution continues to support client-only scripts.

## Scope

### In scope

- The Python SDK FastAPI optional surface, callback HTTP enforcement, installed
  app and signing recipes, focused ASGI/security/lifecycle and distribution tests.
- Mount and deployment root paths, startup ordering, existing browser middleware
  composition, live trust and expiry across callback admission.

### Out of scope

- Maintained-suite adoption and combined platform matrix (PR 10.6), Java/Sidecar
  changes, new remote execution coordination, login providers and authorization
  policy, server/CLI runtime requirements, publication and sync.

## Active Project Guardrails

Apply the [design lens](../design-lens.md#simplicity-and-technical-debt).
Replace superseded development contracts directly. Reuse existing execution
transport, issuer and verifier without a second protocol, settings system or
trust loop. Keep business identity explicit, authorization application-owned
and credentials out of logs and OpenAPI. Trust withdrawal gates new work.
Preserve operator signing inputs and public export ownership. No data reset,
paid provider call, production operation, publication or push is authorized.

## Impact and Risk Analysis

- Starlette routes on a decoded path relative to `root_path`. Mounts extend the
  root while preserving the path, and some deployments supply the local path
  directly. Inconsistent, encoded and normalized aliases can otherwise evade a
  prefix check, especially where browser routes have their own middleware.
- CORS and login middleware can terminate a request before dispatch. Starlette's
  last `add_middleware` call becomes the outermost user middleware. Mounted
  applications do not receive automatic lifespan entry.
- Signer startup publishes an atomic public file before overlap trust can fail.
  Cleanup concerns active owned resources. A successful atomic publication stays
  on disk as specified by the signing contract, even if later startup fails.
- Dependencies must resolve through ordinary overrides without weakening the
  middleware. An authenticated in-flight callback retains its principal across
  trust withdrawal, clock movement, and concurrent requests.

## Implementation Approach

Keep the optional module `loomspan_sdk.fastapi` small. `Loomspan` takes typed
client options, the existing signing and issuance settings, a callback prefix,
optional receiver audience and overlap JWKS path. Reuse core validation for
client options and factor the small verifier option validation out of
`CallbackVerifier.open` so the integration validates those fields without
constructing a verifier or touching files. Leave all private keys, I/O and
trust ownership in the existing classes.

Use one resource bundle on the owning `app.state`, associated with its
integration. Use a separate namespaced ASGI scope key for a verified principal
and its integration association. Request dependency callables return typed
values and use generic errors. A scope key survives normal mount dispatch
where `scope["app"]` changes and lets a router child obtain a principal from
an ancestor guard. Client and issuer resolve only on their owning app.
Do not use globals, context variables or per-request initialization.

Use `app.add_middleware(CallbackMiddleware, loomspan=loomspan)` after the
owner's other user middleware. Check at lifespan entry, before signing side
effects, that the owning app's outermost user registration is its guard.
This catches misregistration or a short-circuiting outer layer on that app.
The SDK can observe the local stack only. Where a parent has middleware that
may terminate requests, the preferred mount composition installs the guard
on that parent and includes the mount segment in the configured prefix. The
child registers its routes relative to the mount and can use the verified
principal dependency. If a child owns the guard and bundle, the main
lifespan explicitly enters `loomspan.lifespan(child)` and the ancestor stack
must forward callback paths to the child. The deployment's `root_path` is
distinct from the owning app's literal callback prefix. Use the inherited
root for mounted apps.

## Phase 1: Lifecycle and Typed Surface

### Changes

- [x] `sdks/python/src/loomspan_sdk/fastapi.py` — implement `Loomspan`,
  `lifespan`, `client`, `issuer` and `principal`. Validate the URL and client
  limits through `_client_options`, the typed signing and issuance objects
  through their existing settings rules, and the prefix through a Java-compatible
  literal check. Reject root, empty/dot segments, explicit blank and
  whitespace/control or Java-disallowed syntax. Normalize one final slash.
- [x] `sdks/python/src/loomspan_sdk/_callback.py` — share receiver audience and
  overlap path validation while preserving `CallbackVerifier.open` behavior.
- [x] `fastapi.py` — enter `ExecutionTokenIssuer` initialization off the
  event loop using existing AnyIO thread support. Enter the verifier and
  client async contexts in the lifespan task using normal context management
  or `AsyncExitStack`. Publish only after all entries complete. Remove the
  bundle before cleanup, release local client/refresh resources, and preserve
  startup and application exceptions. Reserve the owner state synchronously
  before the first await so a concurrent lifespan cannot publish another
  bundle or start a second writer. A startup reservation is not ready state.
  Keep the verifier's task group entry and exit in the same task.

  partial cleanup and unchanged original failure, explicit mount ownership

## Phase 2: ASGI Callback Boundary

### Changes

- [x] `fastapi.py` — implement `CallbackMiddleware` with an exact or
  slash-descendant prefix match. Match Starlette's route path calculation on
  the decoded ASGI path, respecting root segment boundaries. Detect malformed
  protected paths and aliases before authentication. Include repeated slash,
  dot segments, semicolon parameters, backslash, control/invalid encoding,
  percent-encoded structural delimiters/dots and nested percent escapes.
  Inspect optional raw bytes when available, including encoded slash that
  becomes indistinguishable from slash in the decoded scope. Use conservative
  canonical forms only to detect aliases into or out of the protected prefix,
  including ambiguous forms at the root boundary. Never rewrite a path or
  dispatch an alias. Leave ordinary browser paths and similarly named siblings
  alone. For an ambiguity actually seen by the SDK, return 400; document the
  server/proxy and absent-raw-path limits.
- [x] `fastapi.py` — for protected HTTP requests inspect raw header pairs,
  requiring exactly one case-insensitive Authorization field matching the Java
  Bearer syntax. Split query bytes at `&` and the first `=`; reject invalid
  percent escapes in names and exact `access_token` after one form decode,
  including encoded names. Do not inspect query values, cookies, sessions or
  bodies for credentials. Treat absent runtime state like absent authentication.
  Return empty 401 with `WWW-Authenticate: Bearer` for invalid credentials.
  After verification allow GET and POST only, returning 403 for other HTTP
  methods. Deny WebSocket handshakes on the same protected boundary so an
  upgrade cannot make a callback route public.
- [x] `fastapi.py` — set the immutable principal only around the admitted
  downstream call. Forward original headers, `receive` and `send`, and
  remove the binding in `finally`. Propagate application exceptions and
  native cancellation. A dependency override can change downstream application
  input only after middleware admission.

### Automated verification

- [x] Run the focused and full SDK suites from the testing plan. Exercise raw
  headers, exact and similar prefixes, malformed aliases, bodyless and streaming
  POST, method policy, CORS/login, mount and root boundaries, exception and
  cancellation cleanup, and admitted work across withdrawal and expiry.

Use the existing pytest, AnyIO and synthetic signing fixtures. Drive FastAPI via

## Risks and Rollback/Recovery

No operational data or reference pack changes. Startup errors surface before the
app serves callbacks. A newly published public export remains operator-owned
and can be reused by retrying with the same provided identity. A colocated
restart generates a new identity as usual. Resolve a bad input or overlap file
before retrying, preserving operator-owned private material. Final combined
platform runtime evidence and external maintained-suite adoption remain PR 10.6.
If an unexpected intermediate break appears, record the affected check and
resolving ticket without deferring this ticket's acceptance checks.

## Implementation Evidence

- Signer initialization runs in an owned child task so native cancellation of
  the lifespan keeps the app's startup reservation until the export worker has
  stopped. The SDK propagates the original startup failure or cancellation.
  An atomic public export that completed during startup stays on disk.
- Compare decoded ASGI and raw request paths relative to the deployment root.
  This accepts a server-supplied root on one form while retaining encoded
  syntax checks on the raw form. The guard never dispatches a normalized alias.
- The [red-test command](PR-10.5-python-sdk-fastapi-integration-testing.md#safe-verification-commands)
  failed at collection with the expected missing `loomspan_sdk.fastapi` module.
  The native startup cancellation test also reproduced early release of the
  writer reservation before the owned child task was added.
- Focused callback, verifier and trust tests passed (159 on Windows CPython
  3.13.13). The Windows SDK suite passed with 473 tests and two existing POSIX
  skips. An earlier full Windows run reported one timing assertion failure in
  the preexisting sync-client first-read deadline test. The isolated full rerun
  passed. The Linux SDK suite passed with 475 tests on WSL CPython 3.12.16.
  After the final path classifier adjustment, the 36 FastAPI tests passed on
  both platforms. The added composed-startup client cleanup assertion also
  passed with the eight startup cases on Windows.
- Source and example strict typing passed. The installed distribution command
  built and exercised bare wheel and sdist and both web signing recipes from
  isolated Windows environments. Installed consumer typing passed. The web
  install had no Uvicorn or FastAPI CLI.
- The installed example uses synthetic loopback Sidecar requests and an
  in-process ASGI app. No operational files, provider calls, release or sync
  were involved. No temporary integration break or data reset was identified.
