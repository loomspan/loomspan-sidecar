# Integrated acceptance and operational readiness testing plan

## Change Summary

Extend the existing disposable production Compose verification to exercise the remaining cross-feature browser, mail, security, transfer, interruption and recovery journeys. Preserve deterministic Java tests for publication fault boundaries and use real Playwright Chromium for browser behavior. No release operation is part of the test run.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Identity, SMTP and HTTPS | Link origin spoofing, mail outage harming existing access, or fixture leakage | Captured `.test` messages, untrusted forwarded host, stopped fixture SMTP, existing login/JWT during outage, Secure cookie |
| Management security and editing | Role/CSRF bypass, draft exposure, stale candidate accepted, accepted update cancelled | Separate browser contexts and cookie jars, exact HTTP status/state checks, existing management integration suites |
| Export/import and local rollback | Source IDs/history or binding values transferred; destructive rejection | Two Compose projects/volumes, ZIP inspection, destination execution, invalid bundle/binding with unchanged draft/current, fresh local IDs |
| Runtime and startup | Pending pointer not restored before dispatch; invalid selected state admits execution | Sidecar hook tests plus recreated Compose startup/readiness and invalid selection failure |
| Execution/shutdown | Admitted work loses captured generation/resources or outlives shutdown budget | Existing correlation/generation tests plus `verify-shutdown.py` completion and cutoff |
| SQLite recovery | Incomplete file set, wrong UID, lost account/configuration | Stopped full-set copy, present WAL/SHM checks, deliberate stopped-volume fault, restore and login/history/execution |
| Readiness claim | Documentation overstates local or release evidence | Dated exact commands/outcomes; pending gates explicitly marked; no pass for unrun/failed checks |

## Existing Coverage and Environment Constraints

`scripts/verify-production.py` is the only production Compose orchestrator and already uses disposable project names, volumes, local TLS, a fixture host, SMTP capture, Playwright and an image built from the local JAR. `ProductionComposeBrowserIntegrationTest` runs only when `PRODUCTION_TEST_ORIGIN` is supplied by that script. Existing `ManagementMailHttpIntegrationTest`, `ManagementEditorBrowserIntegrationTest`, `ManagementImportBrowserIntegrationTest`, `ManagementHistoryBrowserIntegrationTest`, `RuntimeConfigurationIntegrationTest`, `RuntimeConfigurationRecoveryIntegrationTest`, `ExecutionConfigurationCorrelationIntegrationTest`, `RestGenerationIntegrationTest` and `SupportedLoomspanApiArchitectureTest` provide focused Sidecar evidence. They do not substitute for new Compose checks. The full local run needs Java 21, Maven wrapper, Python, Docker/Compose, OpenSSL and installed Playwright Chromium. The Maven dependency is the developer-installed Loomspan beta 5 snapshot. The verifier must use only temporary `.test` identities, local ports, its own Docker resources and the fixture host; customer SMTP, `production.env` and live endpoints are excluded.

## Tests to Add or Update

- Type: real Chromium against production HTTPS Compose.
- Location: `src/test/java/ai/loomspan/sidecar/deployment/ProductionComposeBrowserIntegrationTest.java`.
- Proves: trusted invitation link, Secure login cookie, private draft and lease ownership, stale browser state after publication; recovery link continues to work.
- Inputs/fixture: verifier-provided `.test` accounts, captured setup/invitation/recovery URLs, separate browser contexts.
- Doubles or boundary isolation: only the disposable fixture SMTP/JWT/model/REST host; actual Sidecar browser and app.
- Edge cases: stale candidate/grant, another role/context, logout or page disconnect while accepted publication completes.

### 2. `verify-production.py` identity and security checkpoints

- Type: production Compose HTTPS integration assertions inside the existing script.
- Location: `scripts/verify-production.py`.
- Proves: fresh volume lock with JWT execution, setup/invitation/recovery via capture, forwarded-host ignored, missing or stopped SMTP blocks mail-dependent actions without disabling existing login/execution, viewer/editor/admin roles and management CSRF separate from JWT.
- Inputs/fixture: unique `.test` addresses, local SMTP sink, fixture JWT, distinct cookie jars.
- Doubles or boundary isolation: stop/restart only the disposable SMTP container; verify messages remain within the fixture.
- Edge cases: wrong/missing CSRF, viewer mutation attempt, bearer token used against management, session cookie used against execution.

### 3. `verify-production.py` two-instance transfer and rollback checkpoints

- Type: end-to-end two-project Compose integration.
- Location: `scripts/verify-production.py`.
- Proves: complete authored YAML/REST ZIP round trip, placeholder remains authored, destination-specific URL binding, independent identities/history/accounts, invalid bundle and invalid destination binding preserve active configuration/draft, successful import and rollback create fresh local snapshots and discard drafts/grants.
- Inputs/fixture: same image, two project names/volumes/HTTPS ports, separately configured fixture host addresses or deterministic host response markers, valid exported ZIP and malformed/bad-binding variants.
- Doubles or boundary isolation: each project is disposable and uses only local fixtures; do not share SQLite storage.
- Edge cases: stale review/confirmation, replacement lease, source history absent in destination, restored local rollback source unchanged.

### 4. `productionSelectedStateFailsClosedAndStoppedRestoreRecovers`

- Type: production Compose startup/recovery assertion within the existing script.

## Safe Verification Commands

- Focused: `.\mvnw.cmd -B -ntp '-Dtest=RuntimeConfigurationRecoveryIntegrationTest,RuntimeConfigurationIntegrationTest,ManagementMailHttpIntegrationTest,ManagementEditorBrowserIntegrationTest,ManagementImportBrowserIntegrationTest,ManagementHistoryBrowserIntegrationTest,ExecutionConfigurationCorrelationIntegrationTest,RestGenerationIntegrationTest' test` — deterministic Sidecar behavior; quote the comma-containing Maven property in PowerShell.
- Related suite: `.\mvnw.cmd -B -ntp verify` — full safe local Sidecar suite, including architecture rules. The Compose-only browser test skips without verifier variables by design.
- Deployment: `.\mvnw.cmd -B -ntp package`; `docker build --tag loomspan-sidecar:sc5-local .`; `python scripts/verify-production.py --image loomspan-sidecar:sc5-local` — build the tested image and run complete disposable local Compose acceptance. The last command invokes its Playwright browser test and shutdown verifier.
- Full safe suite: Maven `verify` plus the image build and production verifier above. No release profile, publication or live customer check belongs here.
