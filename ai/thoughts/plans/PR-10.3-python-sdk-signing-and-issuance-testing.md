# Python SDK signing and issuance testing plan

## Change summary

Verify the Python issuer at its public API, key input and publication at real
temporary filesystem boundaries, and cross-language acceptance through the
actual production Java SDK and Sidecar decoders. See the [implementation
plan](PR-10.3-python-sdk-signing-and-issuance.md) for API and dependency choices.

## Impacted areas and risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Identity and authorization | User crossover, mutable snapshots, unwanted roles | Wire inspection with multiple independently authenticated identities and copied settings |
| NumericDate and lifetime | Float or integer truncation, overflow, missed reader edge | Exact JSON decimal/clock assertions and both actual Java decoders on Python output |
| Private material | Wrong PEM forms accepted, valid variants rejected, silent fallback | Java synthetic signing vector, deterministic PKCS#8 variants, backend-failure and leak assertions |
| Public trust | Wrong kid/unsafe export, alias overwrite, partial writes | Actual public JWK equivalence, link identities, startup failure injection and real atomic replacement |
| Install boundary | Missing dependencies, accidental web coupling, unusable typing | Fresh wheel/sdist environments, current README usage and strict installed-consumer typing |

## Existing coverage and environment constraints

- Python uses pytest, isolated `uv run`, strict mypy and
  `sdks/python/tests/verify_distribution.py`. Existing sync/async loopback
  tests cover transport of an explicit `CredentialSnapshot`; they must stay
  green without changing the HTTP protocol.
- Java's `SigningKeysTest` and `ExecutionTokenIssuerTest` establish the
  current PEM and wire contracts. Existing tests for `CallbackJwtDecoder`,
  `ExecutionJwtDecoder` and file trust show construction and fixed clocks.
  The cross-language check exercises these production classes on new Python
  output. It requires JDK 21, Maven, and the local Sidecar framework snapshot.
- All files, keys and credentials are synthetic. Maven runs offline and
  tests require no deployed endpoints or model calls. The distribution check
  uses the repository's normal isolated build/dependency resolution and
  loopback peer. Windows local disk and WSL Linux paths must support the
  filesystem operation being verified. Record a concrete symlink capability
  skip only when the host actually forbids links. Use Linux-native scratch
  directories for Linux file-behavior tests.

## Tests to add or update

### 1. Profile, trusted snapshots and identity isolation

- Type focused unit and crypto integration tests in
  `sdks/python/tests/test_issuance.py`.
- Use the new public settings and issuer for an allowlist with literal
  `ROLE_ORDER_EDITOR` and `ORDER_EDITOR`. Verify duplicate identities and
  duplicate extra audiences are removed in first-seen order. One user has
  both exact roles and unlisted entries. Another user has only one, then an
  identity with no roles issues from the same issuer. Reissue for the first
  identity and assert independently verified signatures, separate subject
  and role lists, and distinct UUID JTIs. Change source authority/allowlist/
  audience lists after construction and assert prior snapshots are retained.
  Cover an issuer equal to `loomspan-sidecar`, which leaves one base audience.
- Verify the exact three header members and fixed claim set, and that
  `iat`/`exp` are numbers and `aud`/`roles` arrays even when empty roles
  or only one audience apply. Decode with stdlib JSON using
  `parse_float=Decimal`. Verify signature separately from issuance using the
  export public numbers and `cryptography` verification.
- Reject blank and non-string subject/authority/audience/role values,
  scalar string and mapping in place of collections, and a dict used as
  the identity passed to `issue`. Include a Unicode blank and a literal
  nonbreaking space accepted by Java, without stripping or normalizing
  nonblank names.
- Assert issued credential repr, str, pickle/standard serialization and
  default logging contain no bearer bytes. Also assert issuer state cannot
  be serialized. Inject a sign failure with a synthetic secret-marker
  exception and ensure a generic `LocalFailure` exposes no marker or
  original exception context.

### 2. Exact time representation, startup and runtime bounds

- Type deterministic unit tests in `sdks/python/tests/test_issuance.py`.
- Patch only the internal nanosecond clock. A one-nanosecond lifetime from
  integer second `1792324800` yields a raw unquoted
  `1792324800.000000001` expiry. Test a general fraction and a pre-epoch
  fractional date, including one test with a deliberately small ambient
  decimal precision. Assert the clock is sampled once for each credential
  and the expiry delta is exact. A lifetime of one hour is quiet. A one
  nanosecond longer or much longer representable lifetime logs one safe
  warning per initialized issuer, independent of subsequent issues.
- Reject zero, negative, bool and noninteger duration inputs. Show the last
  representable nanosecond can be emitted exactly and a positive lifetime
  producing the next instant fails, both when initializing and when a
  startup-valid issuer is used with a later clock sample. Test a clock
  outside the supported Instant domain. Startup overflow must leave the
  prior public export or absent destination unchanged.

### 3. Mode lifecycle and complete PKCS#8 parsing

- Type tests using actual synthetic keys in
  `sdks/python/tests/test_signing.py`.
- Reuse `sdks/java/core/src/test/resources/signing/synthetic-rsa.pem`
  and `public-jwks.json`. Compare exact public JSON members and values.
  Provided restarts preserve kid and leave input bytes untouched.
  Replace or remove the provided input and issue successfully using the
  already-initialized signer. Restart with a new synthetic provided key
  to observe its new public identity. Two colocated startups publish
  distinct keys, each 2048 bits, and leave only the public file. Validate
  both keys using each startup's exported public material and signature.
- Accept LF, CRLF and CR, ordinary envelope/body whitespace, standard
  PKCS#8 RSA with NULL or absent algorithm parameters, the Java valid
  attribute shape, matching embedded RSA public key and representative BER
  outer, inner and embedded-public variants. Include v2 without the
  optional public component if constructing version variants.
- Accept well-formed open attribute values including primitive, constructed,
  empty constructed and indefinite-length context-specific values. Reject
  malformed nested open values and invalid version INTEGER encodings in the
  outer and inner structures before any canonicalization.
- Reject empty/missing or invalid UTF-8/ASCII input, missing end-boundary
  newline, incomplete base64, extra text/bundles, certificate/public key,
  encrypted PKCS#8, PKCS#1 both as itself and under a mislabeled envelope,
  non-RSA, weak RSA, malformed/truncated/trailing outer and inner ASN.1,
  wrong RSA parameters, malformed/empty-valued attributes, wrong version,
  misaligned or malformed public component and nonmatching modulus or
  exponent. Use the Java optional-field vectors and library-created
  fixtures, with minimal byte mutations for malformed forms. Assert
  invalid cases keep private input and prior public output intact. Patch
  RSA generation to fail if entered during provided initialization, and
  assert provided read occurs only at startup. Assert a malformed key or
  loader exception marker never appears in failure output.
- Construct both settings types without I/O. Verify unknown/mixed options,
  missing and wrong path types and unexpected signing settings fail before
  key generation/publication.

### 4. Atomic export and path identity

- Type filesystem and deterministic failure tests in
  `sdks/python/tests/test_signing.py`.
- Cover normalized path overlap, an existing hardlink, a symlink to the
  input when supported, and a POSIX symlink-parent plus `..` alias.
  In each case check private bytes remain unchanged. Check missing parent,
  regular-file parent and directory destination fail without creating
  directories.
- Verify staging uses the actual export parent through a POSIX symlink followed
  by `..`, with one rename in that directory.
- Inject temporary creation, write and atomic replacement failures at the
  existing Python stdlib boundaries. At the replace seam verify complete
  staging content, existing destination still contains old public data,
  and staging is in the destination directory. Check exactly one replace
  attempt where reached, no fallback and temp cleanup. Cover both modes
  and provided private-file preservation. Exercise actual create and
  replacement on Windows and Linux with the mode/restart tests.

### 5. Actual Java SDK and Sidecar receiver proof

- Type explicit cross-language integration using
  `sdks/python/tests/verify_java_issuance.py` and the two Java
  `PythonIssuanceInteropTest.java` classes named in the implementation plan.
- The runner uses the installed issuer and fixes its clock at
  `1792324800_000_000_000` ns. In a scoped temporary directory it issues
  a default colocated credential for `bob` and provided-mode credentials
  for `alice` using the existing synthetic PEM. Provided settings include
  a named extra audience and exact `ROLE_ORDER_EDITOR` and `ORDER_EDITOR`
  authorities. Pass only the directory path via
  `LOOMSPAN_PYTHON_ISSUANCE_FIXTURES` to the Maven subprocesses. Use stable,
  test-only file names for each credential and JWKS. Do not print or check
  generated raw token or PEM bytes into source control.
- Both decoders accept the default credential and the same provided
  corpus against the appropriate public trust. Check identity, audiences,
  exact role order and credential purpose. With an integral issuance time,
  check `.125` decodes to 125,000,000 ns, `.123456789` to 123,456,700 ns,
  and `.999999999` to the next second. Both current decoders reject a
  one-nanosecond expiry collapsing to issuance and a decimal expiry at the
  final valid Instant nanosecond rounding out of range. The Python wire
  tests assert the original values, keeping producer precision separate.
- The Java SDK test initializes the Java signer from the same synthetic
  PEM, compares Java and Python actual exported JWK objects/kids, uses
  Java own-key callback trust for provided mode and the Python colocated
  export as overlap. The Sidecar test loads each Python file with actual
  `CurrentFileJwtTrust`. Run with fixed decoder clocks. The Maven output
  must show the two fixture tests executed successfully with zero skips
  when the runner enables them.

### 6. Installed artifact and typing

- Type wheel/sdist integration and static type checks in
  `sdks/python/tests/verify_distribution.py`.
- In fresh external environments assert current metadata and five new
  public API names, packaged `py.typed`, no web dependencies and normal
  import/operation using all resolved crypto/ASN.1/JSON dependencies.
  Exercise the documented settings/issuance forms with temporary paths and
  synthetic app-authenticated inputs, then verify public exports and opaque
  credentials. Strictly type-check usage against the wheel and retain both
  executable sync and async existing-credential examples.

## Implementation verification

The red test failed on the absent `AuthenticatedIdentity` public import. It
then passed with the implementation. On Windows AMD64 CPython 3.13.13, the
focused floor and normal-resolution suites each passed 63 tests and skipped
two POSIX-only symlink-parent traversal tests. The full suite passed 309
tests with those same two skips. On WSL Linux x86-64 CPython 3.12.16, the
floor suite passed all 65 tests and the full suite passed all 311 tests,
including the traversal cases on Linux-native scratch paths. The direct
symbolic-link and hardlink overlap tests passed on both platforms. Strict
source typing passed for all 13 SDK modules.

Fresh wheel and sdist installation, both existing-credential client examples,
both documented issuance modes and strict installed-consumer typing passed
on Windows and WSL. Both installed artifact checks resolved AnyIO 4.16.0,
asn1 3.3.0, cryptography 48.0.1, h11 0.16.0, pyasn1 0.6.5, pyasn1-modules
0.4.2 and simplejson 4.2.0. The floor suite pinned cryptography to 48.0.0
and pinned the other four issuance dependencies to their installed versions.

The installed Python fixture runner used Maven 3.9.6 and Java 21.0.2 with
local framework artifacts. Java SDK ran 24 focused tests and Sidecar ran 10,
including their respective `PythonIssuanceInteropTest` cases. Both runs had
zero skips, errors, or failures. Actual Java output matched the Python public
JWKS for the shared synthetic PEM. Both receivers accepted the default and
representative fractional credentials and exercised the documented rounding
and rejection limits. `git diff --check` and separate checks of the untracked
files passed. No intermediate integration break or development-data reset
was needed. The full support matrix and composed consumer proof are PR 10.6
evidence.
