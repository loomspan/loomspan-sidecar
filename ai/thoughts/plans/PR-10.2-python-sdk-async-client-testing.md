# PR 10.2 Async Python SDK Testing Plan

## Change Summary

Verify that the installed async client can discover, submit, read and wait with the existing protocol and SDK errors. Exercise bounded I/O and native cancellation over real sockets, including client close while requests are active and per-call credentials on a reused client.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Public core and parity | Async methods diverge in defaults, validation, paths or typed payloads | Shared protocol tests, constructor signature comparison and real async workflow |
| Wire security | Shared credentials or cookies leak, redirects/auth challenges replay, a compressed or incomplete frame produces acceptance | Concurrent raw requests, rejection matrix and response framing tests |
| Bounds and TLS | Slow continuous data defeats idle timeouts, unbounded body upload/read, incorrect EOF acceptance | Absolute connect/response/wait checks, early closure, strict TLS shutdown, trust and ALPN coverage |
| Lifecycle and cancellation | Calls survive close or cancellation, an outer timeout becomes `WaitTerminated`, errors lose observed context | Controlled phase barriers, real socket closure, SDK exception attributes, native cancellation and outer asyncio timeout |
| Distribution and support | Source-only imports conceal missing public export/dependency or typing | Fresh wheel and sdist installs, metadata checks, examples, mypy and native Windows/Linux runs |

## Existing Coverage and Environment Constraints

- `sdks/python/tests/test_protocol.py` covers request validation, parsing, diagnostics and error redaction. `test_sync_client.py` exercises actual socket framing, deadlines, TLS, close races, no replay and `KeyboardInterrupt`. Keep both passing after extracting shared helpers.
- `sdks/python/tests/wire_fixture.py` provides bounded threaded `WirePeer`, raw-socket and TLS handlers, request/connection counts, JSON replies and a peer-closure helper. Share fixture payload/certificate helpers where this avoids duplicating setup. Do not add a server framework or a pytest async plugin. Plain pytest tests can run an `asyncio.run` test coroutine.
- Use loopback only. Use synthetic execution UUIDs/credentials and generated test certificates. Dependency resolution and local build are allowed. No configured Sidecar, app credentials, provider calls or production files are needed.
- Required focused cells are Windows x86-64 CPython 3.13 and Linux x86-64 CPython 3.12 via the existing WSL environment. Record actual interpreter and dependency versions. AnyIO 4.16.0 is the lower bound and was the current version found during research. Verify the minimum explicitly and the current compatible resolution through normal artifact installs. If both resolve to the same version, identify the shared evidence. PR 10.6 owns outstanding Linux 3.13–3.15 and macOS ARM64 release cells and the combined end-to-end matrix.

## Tests to Add or Update

### 1. Public async workflow, validation and model fidelity

- **Type** Protocol unit tests and loopback integration
- **Location** `sdks/python/tests/test_protocol.py`, `sdks/python/tests/test_async_client.py`
- **Proves** Both constructors validate origins, timeout/size limits and contexts with the same public defaults. Run representative rejected async skill, JSON input, UUID, wait option and credential calls without opening a socket. A valid async workflow preserves the locally built base path, encoded name and accepted UUID despite a misleading `Location`.
- **Inputs and edge cases** Assert shared return types, descriptor schemas, result text including empty/non-JSON/Unicode, original timestamp precision, absent vs present empty diagnostics, event content and a normal terminal FAILED snapshot. Use existing protocol unit cases for exhaustive envelope fields, duplicate/trailing JSON, redaction and defensive copying. Verify standalone status error context and first-read termination.

### 2. Concurrent credential isolation and single-attempt requests

- **Type** Loopback wire integration
- **Location** `sdks/python/tests/test_async_client.py`
- **Proves** Two concurrent tasks on one client progress independently while one peer response is held. Compare each captured Authorization value to the originating call. A prior Set-Cookie is absent on a later call. Assert `Accept` and explicit POST framing, and no Cookie or compression negotiation. Verify no extra attempt on redirect, authentication/proxy challenge, compressed content or dropped connection.
- **Inputs and edge cases** Use 302/307 and 401/407 representatives across GET and POST and a wrong-origin `Location`. The peer asserts one request for each explicitly initiated exchange and no follow-up after an unusable response. Keep the credential out of failure text and displayed exception chains.

### 3. Exchange budgets and advertised/streamed limits

- **Type** Loopback wire integration with bounded timing assertions
- **Location** `sdks/python/tests/test_async_client.py`, `sdks/python/tests/wire_fixture.py` only for reusable peer helpers if needed
- **Proves** DNS/connection/TLS are charged to connect and overall deadlines. A stalled header, stalled body and continuing body trickle all hit a total exchange deadline. Outbound writes respect backpressure and cannot outlive that deadline. An over-limit length or actual streamed body is rejected and the socket closes before the peer ends the response.
- **Inputs and edge cases** Stall TLS after reading ClientHello on a raw peer and check peer closure. For pending DNS, instrument the running loop's public resolver or the async connector at its boundary and hold it without relying on external DNS. A connection that times out before HTTP cannot dispatch after it is released. Test upload using a loopback peer that withholds reads and bounded socket buffers, or a controlled public stream backpressure double if needed to avoid platform-dependent send buffering. Use real stalled/trickled body and fixed/chunked/close-delimited frames for the read side. Cover advertised and streamed overflow, exact bound accepted, informational response followed by a final response, and early cleanup. Assert observed 503 remains `HttpFailure` with no unusable problem while unusable 202 remains `AcceptanceUnknown` and no ID is inferred.

### 4. Remaining wait budget and SDK error context

- **Type** Loopback wire integration
- **Location** `sdks/python/tests/test_async_client.py`
- **Proves** Status polls immediately and only after a valid nonterminal response. An awaited sleep uses the remaining budget and cannot start an extra poll. A second stalled read uses the remaining wait budget, with ID and last RUNNING snapshot. A failed first read has no last snapshot. A shorter response/connect deadline under a still-live wait is classified as a protocol failure. After a valid status read, HTTP and malformed/mismatched status failures stop the wait and preserve both ID and the last valid snapshot. A final non-success status observed before its body stalls survives expiry.
- **Inputs and edge cases** Separate wait and exchange timeouts enough to discriminate ownership. Include malformed or mismatched ID, ordinary 403 with a usable bounded problem, and a stalled 503 after one valid snapshot. Assert bounded cleanup and request counts. Use the existing shared `decode_response` tests for wider payload variants.

### 5. Native cancellation and outer application timeout

- **Type** Native asyncio task behavior over loopback
- **Location** `sdks/python/tests/test_async_client.py`
- **Proves** `Task.cancel("caller cancellation")` surfaces native `asyncio.CancelledError` carrying the original message and no SDK execution state, including when native cancellation and client close overlap. Cover cancellation during polling sleep, stalled status headers/body and after the peer observes a POST. Verify cancellation closes the socket and there is no replay or hidden poll. A shorter `asyncio.timeout` around a long SDK wait or exchange raises the outer built-in `TimeoutError` and closes the active socket.
- **Inputs and edge cases** For sleep, signal entry through a narrowly instrumented poll-sleep boundary after the first valid status. For network, coordinate the server's reached phase with `loop.call_soon_threadsafe` and an `asyncio.Event`. Use a known UUID for the wait retry/recovery case and check a later explicitly requested status works. For the cancelled POST, let the peer model successful admission before withholding the acceptance body, then assert the caller obtains only native cancellation, while the captured wire has exactly one POST. The test's synthetic server ID is fixture knowledge and must not be passed to the cancelled caller as an inferred acceptance ID. Exercise native cancellation during a pending handshake and verify no HTTP request or leaked stream.

### 6. Client lifecycle and peer-observed release

- **Type** Loopback integration and focused lifecycle boundary test
- **Location** `sdks/python/tests/test_async_client.py`
- **Proves** Context-manager exit and concurrent `aclose()` release active connections and reject new valid operations and reentry. Cover closing during a pending connection/TLS handshake, a body read and a polling sleep. Verify an active read error keeps ID and context. Repeated close returns once local resources are released. Close causes no HTTP cancellation, status query or submission replay.
- **Inputs and edge cases** Stall a close-delimited 202 body after writing complete JSON but before authenticated/remote framing end. Local close must not turn it into a valid acceptance. Keep a first status snapshot for the polling sleep close case and verify a separate client can explicitly fetch the known ID after close. If adding a narrowly controlled pending connector, assert closing prevents it from subsequently dispatching and that any returned stream is closed.

### 7. Verified TLS and default trust setup

- **Type** Loopback TLS integration and trust-initialization boundary test
- **Location** `sdks/python/tests/test_async_client.py`
- **Proves** Verify hostnames and private CA trust, accept a client identity through an explicit standard context, and reject untrusted/mismatched peers before HTTP. A length-framed response can finish without a TLS shutdown exchange. A close-delimited response requires `close_notify` and abrupt EOF cannot establish a 202 body or a problem document. Non-HTTP/1.1 ALPN is rejected before HTTP. Verify default trust creation is off the event loop, cached for successful concurrent HTTPS use and included in the first connection budget.
- **Inputs and edge cases** Use `trustme` and the existing verified-context patterns. For off-loop initialization, instrument the standard trust factory with thread identity and a bounded gate while observing an independent async task progress. Simulate setup failure and assert sanitized `LocalFailure` with the requested ID when applicable. A local wait/close must still release any raw transport immediately without peer TLS shutdown.

### 8. Installed examples and direct dependency metadata

- **Type** Artifact integration and static typing
- **Location** `sdks/python/tests/verify_distribution.py`, `sdks/python/examples/existing_credential_async.py`
- **Proves** Fresh external wheel and sdist installations expose `AsyncSidecarClient` and `py.typed`, preserve package name/version/Python floor and require h11 plus AnyIO directly. Both installed examples exercise five calls against synthetic loopback and produce expected execution/status text without showing the credential. Core imports with no web, signing or ASGI-server dependencies installed. Type-check the installed examples against the wheel and record actual dependency versions.
