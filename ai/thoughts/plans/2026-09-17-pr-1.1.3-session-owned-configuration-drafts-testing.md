# Session-owned configuration drafts testing plan

## Change Summary

Add an in-memory draft over a supplied `ConfigurationSnapshot`, with complete immutable authored-content replacement, frozen candidates, and validation attached only to the currently frozen candidate. Documentation must state that session ownership and runtime lifecycle integration are later work.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Authored content | Parsing, normalization, aliasing, or document reordering changes invalid YAML, literals, placeholders, or labels | In-memory model test compares exact `ManagedConfiguration`, source order, and raw strings before and after edits |
| Isolation | An edit mutates the source snapshot or another draft | Two drafts from one source; edit each independently; inspect source and peer after each edit |
| Validation | A late response or A → B → A text edit attaches stale success | Identity-gated candidate test with distinct-content and equal-content edits; foreign candidate test |
| Frozen candidate | Subsequent edit or draft loss changes publication input | Freeze, edit, discard draft reference, inspect retained candidate content/base |
| Diagnostics | Error source and available location disappear or caller mutates returned issues | Result issue round trip and defensive-list-copy assertions |
| Framework/storage boundary | Model accidentally reads intended pointer, persists drafts, or uses unsupported framework types | Model tests need no store or Spring; diff inspection; existing storage and ArchUnit tests |

## Existing Coverage and Environment Constraints

`ConfigurationSnapshotRepositoryTest` already verifies exact persisted skill/REST text, source labels, and list immutability. `ConfigurationSnapshotStoreTest` covers the SQLite intended pointer and history; it is regression coverage, not proof of runtime-published base selection. `SupportedLoomspanApiArchitectureTest` forbids Loomspan internal/autoconfigure dependencies. There is no current draft test or managed-configuration validation result. JUnit 5 and AssertJ are established in `src/test/java`; Maven Surefire is configured in `pom.xml`. The wrapper and local Java 21/beta 5 snapshot are the normal environment (`README.md`). Routine tests use local temporary files and loopback configuration and require no live model provider or external service.

## Failing Test First

- Name: `createsIndependentDraftsFromSuppliedRuntimeSnapshot`
- Type: plain JUnit model test
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`

Construct two drafts from that same supplied snapshot, replace one draft's complete content, and assert the other and the source still expose exact original strings and order while both retain the source `localId`.

## Tests to Add or Update

### 1. `createsIndependentDraftsFromSuppliedRuntimeSnapshot`

- Type: JUnit model test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`.
- Proves: Each draft starts from the complete supplied snapshot, retains its durable base ID, and neither edit changes the source or peer. The draft constructor has no store dependency.
- Inputs/fixture: Direct `ConfigurationSnapshot` with distinct local/source IDs, ordered differently cased source labels, invalid YAML, `${URL}` placeholder, literal value, and raw REST comments. Mutable caller list may be changed after `ManagedConfiguration` construction to confirm copy behavior.
- Doubles or boundary isolation: None; no Spring or SQLite.
- Edge cases: Empty skill list with valid raw REST text; replacing with unchanged text still counts as an edit for validation invalidation (tested below).

### 2. `freezingRetainsExactContentAfterDraftChanges`

- Type: JUnit model test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`.
- Proves: Frozen candidate retains base ID, named YAML order/text, and REST text after multiple replacements and after the test drops its draft reference. It cannot mutate the document list.
- Inputs/fixture: Same snapshot with an edited content value.
- Doubles or boundary isolation: No store or runtime service.
- Edge cases: Freeze the same current content twice if supported; verify subsequent edit creates a distinct candidate even when text is equal.

### 3. `validationBelongsOnlyToCurrentCandidate`

- Type: JUnit model test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`.
- Proves: A success result attached to the current candidate is visible for it; replacing content clears it; late results for old candidates return rejected and do not appear current. A → B → A cannot resurrect the original result; a candidate from another draft cannot attach even with equal content.
- Inputs/fixture: Three successive candidates and a successful `ConfigurationValidationResult`.
- Doubles or boundary isolation: Validator is represented by a supplied value; no YAML validator or framework preparation.
- Edge cases: Equal-content replacement; foreign candidate; stale failure and stale success.

### 4. `preservesSourceLabelAndAvailableErrorLocation`

- Type: JUnit model test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`.
- Proves: A failed result stores each error's exact source label, message, and optional location; caller-owned issue lists cannot later change the stored result and exposed lists are unmodifiable. A general failed result with no structured errors remains representable.
- Inputs/fixture: Skill and REST source labels; a path/line/column location string supplied verbatim; null location for an unlocated error.
- Doubles or boundary isolation: No framework API mapping yet; Phase 2 owns that integration.
- Edge cases: Null or blank labels/messages rejected according to the value type contract.

### 5. Existing storage and architecture regression

- Type: Existing JUnit SQLite and ArchUnit tests.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`, `ConfigurationSnapshotStoreTest.java`, and `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`.
- Proves: The authored-content and intended-pointer contract still works, and production/test Java imports remain on the supported framework API.
- Inputs/fixture: Existing temporary SQLite database fixtures; no new draft persistence fixture.
- Doubles or boundary isolation: Local temporary files only.
- Edge cases: Existing retained/history cases remain as-is; do not add storage tests that imply draft persistence.
