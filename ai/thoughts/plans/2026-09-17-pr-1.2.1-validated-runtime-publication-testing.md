# Validated Runtime Publication Testing Plan

## Change Summary

Replace mounted startup configuration with SQLite-selected runtime activation and exact-candidate validated publication. REST resources become generation-keyed; URL base bindings come only from an allowlisted process environment variable; execution records retain the captured durable snapshot ID. Startup, publication, status faults, retirement, pruning, shutdown and recovery cross real framework/SQLite boundaries.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Startup | Mounted fallback, early dispatch, invalid selected content or bookkeeping silently tolerated | Real context and temporary SQLite startup/restart tests; latch admission while activation is blocked |
| Publication | Stale/equal-content draft validation or racing base checks publishes wrong content | Exact-candidate unit and serialized competing-update integration tests |
| Database/framework boundary | Commit, publish, revert or status faults misstate runtime, history or fault gate | Inject one operation failure at a time around real SQLite and framework transitions; inspect runtime, pointer, row status and resources |
| REST | Cross-generation routing or early close breaks nested work; callback blocks framework thread | Loopback callback/server and public retirement tests with pending admissions, nested work, concurrent callbacks and shutdown cutoff |
| URL binding | Spring property injection, composed templates, secret leakage or accidental rewrite | Parser matrix with process environment injection seam, safe errors and persisted authored YAML assertions |
| Execution | Handoff races publication; observer choice or missing mapping yields false ID/leaked admission | Real framework handoff/correlation test plus targeted injected missing-mapping test |
| Retention | Pruning deletes selected/live/in-flight history or permanent over-retention | Real SQLite overflow/race tests and later explicit prune trigger; no retirement-driven delete |
| Recovery | Reopen chooses status or prior A rather than committed B | Stopped/reopened database and full-set backup/restore tests |

## Existing Coverage and Environment Constraints

`pom.xml` uses Maven Surefire, JUnit 5, Spring Boot test, Java 21, the locally installed `1.0.0-beta.5-SNAPSHOT` framework starter, SQLite JDBC and ArchUnit. Existing `ConfigurationSnapshotStoreTest` covers storage transactions/reopen/prune but never activates framework state. `ConfigurationDraftTest` covers exact candidate/equal edit and stale results with supplied outcomes. Existing mounted startup and REST tests must be updated to database-authored fixtures, not counted as Phase 2 evidence as-is. `SidecarApplicationFixture` offers a loopback model and callback HTTP server, JWT fixture and blocking latches; use it without live services or credentials. Existing execution/shutdown/security/TLS tests guard regressions.

Use only public `ai.loomspan.api` types in tests. Create isolated `@TempDir` SQLite databases and loopback servers; never point tests at the default `/sidecar/data/sidecar.db`. Context tests can use `SpringApplicationBuilder` with `server.port=0` or `WebApplicationType.NONE` and a temporary `loomspan-sidecar.storage.database-path`. To seed a selected snapshot before context startup, use Phase 1 storage helpers against that temporary database, then close that setup connection/context. Restart tests close the context and reopen the same database set. Control asynchronous tests with barriers/latches and bounded waits. Fault seams should be narrow service/store collaborators or test configuration bean overrides; they must not replace framework internals or production beans through unsupported APIs.

The actual HttpClient 5.6.1 API has `CloseMode.IMMEDIATE`; tests should assert prompt idempotent close and no close before retirement/completion, rather than relying on a second wait budget. Docker/image checks need a configured local environment and are optional.

## Failing Test First

- Name: `newDatabaseStartsWithPublishedEmptySelectionAndClosedDispatchUntilActivation`
- Type: real Sidecar integration with installed framework and temporary SQLite.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Arrange/Act/Assert: start a new database; hold activation at an injectable boundary, assert execution admission refuses and current framework baseline is empty; release activation; assert selected empty snapshot becomes `PUBLISHED`, its durable ID maps to the active process generation, and dispatch opens.
- Expected pre-fix failure: no runtime activation service exists, `ExecutionCoordinator` is initially open and database selection has no generation mapping. This is the first missing-capability test; continue with selected-content startup before building all publication cases.

## Tests to Add or Update

### 1. `selectedSnapshotActivatesAcrossRestartAndReplacesCompleteCatalog`

- Type: real framework/SQLite integration.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Proves: new/initialized selection, pending-status startup activation, durable ID preservation/new generation ID, additions, updates, deletions, empty replacement, model-backed and REST declarations, route-only replacement, current discovery and POST advisory checks, and startup status `PUBLISHED` before admission.
- Inputs/fixture: named YAML documents from test resources and authored REST YAML; seed using real store; loopback model/callback as needed.
- Doubles or boundary isolation: no framework mock for acceptance path; use temporary database and loopback endpoints.
- Edge cases: invalid selected YAML, route/catalog mismatch, bad client stage and status write each fail startup with dispatch closed and secret-free error; no empty/older fallback. A configured nonempty startup source is rejected by baseline check.

### 2. `validateCandidateHasNoDurableOrRuntimeEffectAndClosesResources`

- Type: service integration plus draft unit.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`; update `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java` only for changed API.
- Proves: framework `prepare` receives the complete named documents, route validation uses candidate catalog, clients are released on success/failure, no submitted row/pointer/current-generation change, source labels/locations are returned, and no prepared object is retained.
- Inputs/fixture: valid model/REST pair, invalid YAML, missing/extra REST route, malformed target/SSL bundle/client staging fault, invalid URL binding.
- Doubles or boundary isolation: real framework prepare and SQLite; narrow client-construction failure injection for partial cleanup.
- Edge cases: edit with identical bytes invalidates, late validation result ignored, Publish without exact successful result rejected, successful Validate followed by changed external setup can fail fresh Publish preparation without modifying A.

### 3. `urlBindingsRequireExactAllowedProcessVariable`

- Type: parser unit with integration persisted-text check.
- Location: `src/test/java/ai/loomspan/sidecar/rest/RestRouteLoaderTest.java` and `RuntimeConfigurationIntegrationTest.java`.
- Proves: literal valid URL, multiple declared variables, empty/absent allowlist, undeclared/missing/blank/invalid value, `${NAME}` whole-value rule, no Spring property substitution, unused declarations require no value, authored YAML remains byte-for-byte stored.
- Inputs/fixture: sanitized process-environment map injected through a small resolver seam; Spring test property with same key and a conflicting value.
- Doubles or boundary isolation: parser's process-environment lookup seam only; production delegates to `System.getenv`; no process-wide environment mutation.
- Edge cases: `${NAME}/path`, prefix/suffix templates, `${NAME:default}`, nested/extra braces, fragments, user-info, query, unsupported scheme, empty allowlist. Existing non-base-url placeholder tests remain intact. Phase 5 owns export/import round trip.

### 4. `serializedPublicationRechecksBaseAndRetainsFrozenAcceptedContent`

- Type: real framework/SQLite concurrency integration.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Proves: one accepted update holds the full serialization boundary; a waiting request only starts on turn and rechecks runtime-published base; later draft edits/discarded reference do not change accepted content; another session can edit A while B prepares; dispatch remains available during preparation.
- Inputs/fixture: two drafts from A, latches at preparation/staging/commit; compare B/C authored content and outcomes.
- Doubles or boundary isolation: injectable before-operation hooks for deterministic ordering, real store/reloader.
- Edge cases: equal-content edit; stale validation; pointer-only failed/reverted attempt does not invalidate A-based draft. Phase 3 covers actual session/lease/account events and short post-success invalidation; this test proves the coordinator boundary only.

### 5. `publicationFaultMatrixMaintainsCorrectPointersAndFaultGate`

- Type: real SQLite/framework integration with operation-level injected failures.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Proves: commit failure leaves A active/selected and no B history required; publish failure + successful revert leaves A active/selected, immutable B `FAILED`; revert failure leaves A active, intended B pending and mutations rejected; status failure after successful publish leaves B active/intended, pending/unknown and mutations rejected; inspection exposes both IDs/status/fault and execution still works on A or B. No successful B is undone or its resources closed.
- Inputs/fixture: valid A/B snapshots; one-shot fault at submit, framework publication seam, revert or status update. Capture client state and row contents.
- Doubles or boundary isolation: inject failures at Sidecar-owned call sites while real framework/SQLite establish actual state; no direct internal framework access.
- Edge cases: prune/store unusable after fault is surfaced safely; repeated mutation rejected without new history; no fake failed/published outcome after ambiguous write.

### 6. `oldAndNewNestedRestUseCapturedGenerationUntilRetirement`

- Type: real framework integration with loopback REST/model.
- Location: `src/test/java/ai/loomspan/sidecar/rest/RestGenerationIntegrationTest.java`.
- Proves: route-only publish changes new calls while old admitted/nested work uses A route and open A clients; public retirement occurs after pending admission and physically running descendants; prompt callback can run before `publish` returns and concurrently; retired resources close idempotently off callback thread.
- Inputs/fixture: A/B loopback targets with distinct responses, blocked callback and nested model tool call, public `SkillInvocationHandoff` admissions.
- Doubles or boundary isolation: real framework; local HTTP servers; observable client wrapper/registry state.
- Edge cases: unused A retired promptly, validation-only/partial/rejected candidate cleanup direct without callback, multiple notifications/cleanup races harmless, no arbitrary TTL/count eviction of live A.

### 7. `shutdownClosesAllGenerationsAfterFrameworkCompletionOrCutoff`

- Type: real context shutdown integration.
- Location: update `src/test/java/ai/loomspan/sidecar/rest/RestHandlerLifecycleIntegrationTest.java` and `src/test/java/ai/loomspan/sidecar/execution/ExecutionShutdownIntegrationTest.java`.
- Proves: close event rejects/discards queued work promptly; A/B clients remain open through admitted work, then all remaining active resources close after framework completion/cutoff using one budget; callback omission during shutdown does not leak.
- Inputs/fixture: blocked loopback callback, short configured framework timeout, parent/management child contexts.
- Doubles or boundary isolation: local server only.
- Edge cases: normal completion and cutoff, active never-retired generation, multiple generations, asynchronous events and management child close. Assert elapsed time within the existing budget tolerance, not an added cleanup wait.

### 8. `capturedExecutionSnapshotIdSurvivesPublicationAndRetirement`

- Type: real API/framework/SQLite integration, plus coordinator unit failure.
- Location: `src/test/java/ai/loomspan/sidecar/execution/ExecutionConfigurationCorrelationIntegrationTest.java`, `ExecutionCoordinatorTest.java`.
- Proves: model-only and REST records and GET response hold the admitted generation's durable UUID; queued record has null; publication between handoff capture and return does not change correlation; result persists after completion/retirement, including diagnostics `NEVER`.
- Inputs/fixture: A/B snapshots, loopback model/callback, barrier around handoff return and publication.
- Doubles or boundary isolation: real framework for race; unit handoff double and registry seam for missing mapping.
- Edge cases: pre-capture failure stays null, missing mapping fails explicitly/logs without current-pointer substitution, admission released, no observer wait, expired execution record disappears without pinning snapshot history.

### 9. `pruneProtectsLiveAndInflightSnapshotsThenAllowsEligibility`

- Type: real SQLite integration with concurrency barriers.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`.
- Proves: selected plus live generation and accepted in-flight IDs are protected; retention default ten, oldest eligible deleted, protected overflow allowed; failed history inspectable until eligible; retirement does not itself delete rows; later startup/completed attempt prunes eligible rows.
- Inputs/fixture: more than ten distinct snapshots, blocked nested A and staged B, faulted row, explicit prune triggers.
- Doubles or boundary isolation: real store; framework admissions/latches for live protection.
- Edge cases: prune concurrent with publication admission; retired A drops protection but no immediate database deletion; retained execution ID does not pin forever.

### 10. `restartActivatesCommittedSelectionAndStoppedBackupRecoversA`

- Type: process/context restart with real SQLite database-set copy.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationRecoveryIntegrationTest.java`.
- Proves: interruption before commit reopens A; after B commit before publish/revert reopens B irrespective of `PENDING`; successful revert reopens A; unreverted A/B failure reopens B; successful publish/status failure reopens B; startup marks selected published and opens readiness, leaving unrelated pending rows unknown. Stopped full database backup restore reopens prior A and rolls all database state back.
- Inputs/fixture: temporary database and copied `db`, `-wal`, `-shm` set after context stop; service operation hooks to stop at each boundary.
- Doubles or boundary isolation: real framework and store on each reopened context; controlled failure hook only to simulate boundary interruption.
- Edge cases: invalid selected content/status update failure abort startup with no management-only fallback; inspection after restart agrees with active catalog.

### 11. `existingSecurityTlsDiagnosticsAndArchitectureRegressions`

- Focused red/development: `mvn -Dtest=RuntimeConfigurationIntegrationTest test`
- Focused REST: `mvn -Dtest=RestRouteLoaderTest,GenericRestSkillHandlerTest,RestGenerationIntegrationTest test`
- Focused execution/recovery: `mvn -Dtest=ExecutionCoordinatorTest,ExecutionConfigurationCorrelationIntegrationTest,RuntimeConfigurationRecoveryIntegrationTest test`
- Related suite: `mvn -Dtest=RuntimeConfigurationIntegrationTest,RuntimeConfigurationRecoveryIntegrationTest,RestGenerationIntegrationTest,ExecutionConfigurationCorrelationIntegrationTest,RestHandlerLifecycleIntegrationTest,ExecutionShutdownIntegrationTest,SupportedLoomspanApiArchitectureTest test`
- Full safe suite: `mvn test`
- Script syntax/CLI: `python scripts/verify-image.py --help`

Use the installed local Maven snapshot and do not run framework builds. Maven tests may access Maven Central only for already declared dependencies if local cache is incomplete; no test should contact a model provider or production service. Prefer targeted reruns only when a concrete failure requires them. Do not count Docker image verification as a required automated gate without a configured local image/environment.
