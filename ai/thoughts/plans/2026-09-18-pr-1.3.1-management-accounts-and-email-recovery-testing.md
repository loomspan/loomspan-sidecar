# Management Accounts and Email Recovery Testing Plan

## Change Summary

PR 1.3.1 introduces SQLite-backed management accounts and bootstrap state, email password-set/reset links, session-based local login, CSRF-protected management routes, account administration, and idle/session invalidation. It must preserve stateless JWT execution, owner-scoped polling, REST passthrough and framework observability isolation.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| SQLite bootstrap | Configuration initialization mistaken for account bootstrap; race creates two first admins; restart reopens setup | Real SQLite reopen and simultaneous setup tests |
| Account state | Duplicate normalized emails or concurrent changes remove the last usable administrator | Unique-index test and barrier-controlled concurrent disable/demotion |
| Password/token security | Plaintext or truncated credentials; token replay, wrong purpose or disabled account grants access | Direct database inspection, policy boundary cases and transaction tests |
| Email | Wrong sender or untrusted Host in link; failed send strands setup or invalidates working password | Loopback SMTP capture/failure, configured origin and retry flow |
| Browser security | Session fixation, absent CSRF, unauthorized account change, idle polling refresh, stale session after security change | Loopback HTTP cookie/CSRF/role/timeout scenarios |
| Attempt bounds | Brute-force login/request/token submissions or unbounded counter memory | Limiter unit tests and HTTP rejection cases |
| Auth isolation | Session accesses `/v1`, JWT accesses management, or observability API key crosses boundaries | Existing and expanded `ConsoleSecurityIntegrationTest`, execution suite |
| Configuration/docs | New settings omitted or secrets included in snapshots/docs | `ConfigurationReferenceTest`, storage assertions, documentation review |

## Existing Coverage and Environment Constraints

`ConfigurationSnapshotRepositoryTest` and `ConfigurationSnapshotStoreTest` show the real temporary SQLite and Flyway pattern. `JwtStartupIntegrationTest`, `AuthenticatedExecutionApiIntegrationTest` and `ConsoleSecurityIntegrationTest` use loopback HTTP with fixture JWTs. `SupportedLoomspanApiArchitectureTest` enforces the public framework boundary. `ConfigurationReferenceTest` checks the README configuration table and YAML. The Maven wrapper command is `.\mvnw.cmd -B -ntp verify` on this Windows checkout. Tests run against the locally installed Loomspan beta 5 snapshot and must not rebuild the framework or reach external mail/model services. Use an in-process SMTP server bound to `127.0.0.1`, temporary databases, fixture JWT keys and test addresses under `.test`; no production email is sent. Inject `Clock` and setup-token source in service tests; HTTP setup tests should supply the test credential through controlled test configuration or a child process environment, never depend on a real operator token. Ensure service/controller tests do not print passwords, links or SMTP authentication values in failure messages.

## Failing Test First

- Name: `configurationInitializationDoesNotConsumeManagementBootstrap`
- Type: real SQLite repository/service integration test.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Arrange/Act/Assert: migrate a fresh temporary SQLite database, initialize its configuration snapshot, observe management setup still unreserved, reserve one initial admin with the test setup credential, close/reopen the database, and assert the reservation remains consumed and another email cannot reserve it even while the credential remains present.
- Expected pre-fix failure: no management account/bootstrap tables, repository or reservation operation exists. This establishes the missing independent persistence capability before implementation.

## Tests to Add or Update

### 1. `configurationInitializationDoesNotConsumeManagementBootstrap`
- Type: real SQLite integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Proves: configuration and account initialization are independent; reserved setup stays consumed across restart.
- Inputs/fixture: migrated temporary SQLite file, fixture setup credential.
- Doubles or boundary isolation: only clock/token generation may be injected; SQL uses the real database.
- Edge cases: setup token still configured on restart; blank/bad credential cannot reserve.

### 2. `concurrentSetupCannotCreateCompetingAdministrators`
- Type: real SQLite concurrency integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Proves: two synchronized setup attempts yield one reserved email/account, with no second admin or partially completed bootstrap.
- Inputs/fixture: two service/repository instances on one temporary SQLite file, coordinated start barrier.
- Doubles or boundary isolation: no SMTP; inspect committed rows after both finish.
- Edge cases: competing different emails and repeated same email, including SQLite busy/conflict handling.

### 3. `accountEmailAndLastAdminInvariantsSurviveRestartAndRaces`
- Type: real SQLite integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Proves: case/outer-space normalization and uniqueness; immutable address; pending admin does not count; two concurrent changes cannot demote/disable the final enabled activated admin.
- Inputs/fixture: activated admin accounts, pending invite and simultaneous conditional updates.
- Doubles or boundary isolation: real transaction manager and SQL constraints.
- Edge cases: re-enable, role promotion, replacement account activated then old disabled.

### 4. `passwordPolicyAndStoredSecretsAreSafe`
- Type: policy unit plus real SQLite inspection.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Proves: exactly 15/128-code-point boundaries, uppercase/lowercase/digit/symbol rules, Unicode classification, spaces, long UTF-8 passwords without truncation, distinct salted PBKDF2 hashes, and token digests rather than plaintext.
- Inputs/fixture: synthetic passwords at each boundary, fixed fixture tokens for inspection only.
- Doubles or boundary isolation: no network.
- Edge cases: whitespace alone is not a special; overlong input is rejected, no common-password/blocklist or expiration behavior is added.

### 5. `passwordLinksArePurposeBoundSingleUseAndTransactional`
- Type: real SQLite integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementIdentityStoreTest.java`
- Proves: wrong-purpose, expired, invalid, reused and disabled-account tokens fail; successful set/reset stores new hash, consumes token once, invalidates other outstanding recovery tokens and bumps credential version atomically.
- Inputs/fixture: injected mutable clock, set/reset fixture tokens and activated/disabled accounts.
- Doubles or boundary isolation: real SQLite; no SMTP required.
- Edge cases: reset does not enable an account, old password remains valid after failed reset, failed token attempts do not mutate rows.

### 6. `setupAndInvitationMailAreTrustedAndRetryable`
- Type: loopback SMTP and HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementMailIntegrationTest.java` and `ManagementMailHttpIntegrationTest.java`.
- Proves: initial setup and admin invitation send from configured sender, links use configured external base URL despite forged Host/forwarded headers, pending accounts cannot log in, and password setting enables normal login.
- Inputs/fixture: local SMTP receiver, configured test base URL and sender, fixture setup token; messages are captured in memory.
- Doubles or boundary isolation: local SMTP only; never route to Internet.
- Edge cases: missing SMTP/sender/base URL, SMTP reject/disconnect/timeout, resend to reserved initial email, old password preserved on failed recovery send, no account existence leak from forgot requests.

### 7. `resetMailAndSessionLifecycle`
- Type: loopback SMTP and HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementMailIntegrationTest.java` and `ManagementMailHttpIntegrationTest.java`.
- Proves: generic forgot response for known/unknown address, valid reset email, once-only password reset, normal login required afterward, and existing sessions rejected.
- Inputs/fixture: local SMTP fixture and cookie-aware HTTP client.
- Doubles or boundary isolation: temporary SQLite and loopback services.
- Edge cases: expired/replayed link, disabled account, no SMTP, fixed secret-free response/log content.

### 8. `managementAuthenticationAndCsrfStaySeparateFromExecution`
- Type: loopback HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`; update `src/test/java/ai/loomspan/sidecar/security/ConsoleSecurityIntegrationTest.java`.
- Proves: login session/role grants management routes only; JWT and framework observability API key do not authenticate management; management cookie never authenticates `/v1`; CSRF is required for login/setup/change/admin mutations; logout invalidates the session; session id rotates on login; sensitive pages/JSON carry no-store/no-referrer and secure cookie attributes.
- Inputs/fixture: fixture JWT, test accounts, HTTP cookie jar and CSRF extraction.
- Doubles or boundary isolation: no external calls.
- Edge cases: viewer/editor/admin matrix, pending/disabled logins, unsafe methods without/wrong CSRF, forged role/account id in body.

### 9. `securityChangesAndIdleDeadlineInvalidateSessions`
- Type: loopback HTTP integration with controllable time.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`
- Proves: password change/reset, disable and role change revoke affected sessions; normal login needed afterward. Polling `GET /api/management/session` cannot extend the 30-minute idle deadline, while `POST /api/management/session/activity` with CSRF extends it.
- Inputs/fixture: multiple browser sessions for one account, mutable clock, short test timeout property.
- Doubles or boundary isolation: no sleeps beyond local request coordination.
- Edge cases: old roles cannot persist in stale sessions; logout and rejected activity do not extend idle time; accepted execution is unaffected.

### 10. `attemptLimitsAreBoundedAndResponsesAreGeneric`
- Type: limiter unit plus HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementAttemptLimiterTest.java`, `ManagementHttpIntegrationTest.java`.
- Proves: five per-account and 20 per-IP login failures in 15 minutes; three per-email and 20 per-IP forgot requests per hour; ten per-IP token attempts in 15 minutes; bounded counter storage and fail-closed capacity behavior.
- Inputs/fixture: mutable clock and explicit socket client addresses where possible.
- Doubles or boundary isolation: no external service; do not trust `X-Forwarded-For` sent by the client.
- Edge cases: reset window, successful login, unknown account, multiple keys and full table.

### 11. `configurationAndFrameworkBoundaryRemainValid`
- Type: existing unit/architecture suites.
- Location: update `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java`; retain `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`.
- Proves: new management bound keys appear once in the README table and YAML; no unsupported framework Java types are introduced.
- Inputs/fixture: checked-in docs/YAML and compiled classes.
- Doubles or boundary isolation: none.
- Edge cases: mail credentials and setup credential are not included in snapshot/configuration export fields.
