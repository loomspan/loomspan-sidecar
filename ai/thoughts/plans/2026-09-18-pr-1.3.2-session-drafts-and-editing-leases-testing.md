# Session Drafts and Editing Leases Testing Plan

## Change Summary

Management sessions gain private in-memory drafts and a single instance editing lease scoped to one tab/grant. Real framework publication changes the runtime base and invalidates old editing state in a short coordinated transition. The protected JSON API must enforce roles, CSRF, session privacy, activity deadlines and stale-write conflicts.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Session privacy | A second account, admin, or second session of the same account reads draft text or validation | Separate real cookie clients reading status/draft routes; service-level validation-state isolation |
| Authorization/CSRF | Viewer acquires or writes, JWT caller reaches management API, unsafe request lacks CSRF | Real HTTP role/CSRF/JWT cases |
| Tab/grant authority | Old tab, expired grant, replaced grant, out-of-order save changes content | Exact candidate and grant assertions before/after 409 responses |
| Runtime base | Draft is seeded from SQLite intended B while runtime A is active, or pruning removes the base mid-capture | Publication hook/latch and real store snapshots |
| Publication transition | Success leaves a stale lease or draft; status failure obscures success; failure incorrectly clears state | Real runtime publication integration with latches and existing fault hooks |
| Activity clocks | Polling/automatic traffic renews idle state, early or late activity revives ownership | Mutable clock assertions at 15m and 30m thresholds |
| Session lifecycle | Logout, account change, container expiry, or restart leaves private state or lease | HTTP/session invalidation and context-restart tests |
| Fault gate | Fault permits writes/renewal or blocks cleanup/inspection | Post-publication bookkeeping fault test plus HTTP/service checks |
| Execution continuity | Preparation blocks edits or lease loss cancels accepted frozen publication/dispatch | Latch-driven preparation and framework handoff assertions |

## Existing Coverage and Environment Constraints

`ConfigurationDraftTest` already verifies literal YAML/REST preservation, equal-content edit invalidation, foreign/late candidate rejection and freezing; keep those assertions. `ManagementHttpIntegrationTest` uses `@SpringBootTest` with a random port, temp SQLite, separate `HttpClient` cookie jars, real form login/CSRF and a mutable `Clock`. `RuntimeConfigurationIntegrationTest` starts the actual Sidecar context with the installed beta 5 snapshot, uses hooks around commit/publish/status and already tests ordinary failure/reversion, fault, serialization, pruning and admitted generations. `RuntimeConfigurationRecoveryIntegrationTest` covers restart selection. `SupportedLoomspanApiArchitectureTest` checks the closed framework API boundary.

The repository command is `.\mvnw.cmd -B -ntp verify` on Windows with Java 21 and the locally installed `ai.loomspan:loomspan-spring-boot-starter:1.0.0-beta.5-SNAPSHOT`. Integration fixtures use local temporary SQLite files and loopback servers. No live SMTP, production database, hosted CI, framework rebuild, or release artifact is needed for this ticket. Use deterministic latches/clock advances; avoid timing-sensitive sleeps except bounded polling for existing framework resource retirement.

## Tests to Add or Update

### 1. `draftAcquisitionIsPrivateToItsManagementSession`
- Type: real HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementEditingHttpIntegrationTest.java`
- Proves: cross-account/admin/same-account-session privacy and safe public lease status.
- Inputs/fixture: editor A, editor B, admin and second A browser; authored YAML/REST sentinels and a private validation result placed through the service test seam.
- Doubles or boundary isolation: real security/session/SQLite/runtime; fixture account seeding only.
- Edge cases: no draft before acquisition, no foreign content after release/takeover.

### 2. `onlyCurrentTabAndGrantCanReplaceExactCandidate`
- Type: real HTTP integration plus focused service test
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementEditingHttpIntegrationTest.java` and `ManagementEditingServiceTest.java`
- Proves: one writable tab and instance lease; foreign session, same-session second tab, old grant and old candidate receive 409 without mutation.
- Inputs/fixture: two tab IDs under one cookie, another browser, grant IDs before/after reacquisition; equal-content replacement.
- Doubles or boundary isolation: real HTTP for authorization, direct service for exact candidate association.
- Edge cases: replacement with identical text rotates candidate ID and clears validation; late validation for prior candidate cannot attach.

### 3. `leaseLifecyclePreservesOnlyEligiblePrivateDraft`
- Type: focused service and real HTTP integration
- Location: `ManagementEditingServiceTest.java` and `ManagementEditingHttpIntegrationTest.java`
- Proves: acquire, contention, renewal identity preservation, explicit release, expiry, resume with a fresh grant, discard, admin takeover from runtime production.
- Inputs/fixture: mutable clock; distinct literal A/B draft text and tabs.
- Doubles or boundary isolation: local runtime integration fixture; no live services.
- Edge cases: same holder reacquisition does not silently rotate grant; takeover never adopts former draft; runtime base change prevents resume and clears stale text.

### 4. `activityReportsRespectLeaseAndLoginDeadlines`
- Type: real HTTP integration with controlled clock
- Location: `ManagementEditingHttpIntegrationTest.java`
- Proves: positive configured 15m lease and 30m login deadlines; accepted reports at least 30 seconds apart renew both; premature report does not extend either deadline; late report cannot revive expired ownership/login.
- Inputs/fixture: clock at 14m/15m and 29m/30m boundaries; status GETs and a service-level validation invocation between reports (the public validation endpoint belongs to PR 1.3.3).
- Doubles or boundary isolation: fake clock, real sessions and security chain.
- Edge cases: one active login may reacquire after lease expiry; unauthenticated/expired login cannot; status polling does not mark activity.

### 5. `sessionAndAccountInvalidationClearPrivateState`
- Type: real HTTP and context integration
- Location: `ManagementEditingHttpIntegrationTest.java`
- Proves: API/form logout, guard idle invalidation, account disable/role/password version changes and servlet session destruction remove that session's draft and lease; restart starts with no editing state.
- Inputs/fixture: separate cookie clients, account update endpoints or identity service, context restart over same temp SQLite.
- Doubles or boundary isolation: real local server/database, no email delivery.
- Edge cases: other unaffected sessions keep their own drafts; stale cookie cannot read old text; container expiry releases an idle holder.

### 6. `draftStartsFromRuntimeSnapshotWhileIntendedPointerIsPending`
- Type: real runtime integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`
- Proves: complete runtime A content and durable ID are used while SQLite points to B; snapshot capture remains safe through publication/pruning.
- Inputs/fixture: `beforeFrameworkPublish` latch after B commit, temporary SQLite with low retention, literal YAML/REST A.
- Doubles or boundary isolation: actual `SkillReloader`, store and editing coordinator; hooks only pause known phases.
- Edge cases: creation racing success yields either an invalidated A draft or a valid B draft, never a persistent stale A draft or missing-content result.

### 7. `successfulPublicationInvalidatesAtomicallyEvenIfBookkeepingFails`
- Type: real runtime integration
- Location: `RuntimeConfigurationIntegrationTest.java`
- Proves: success revokes old grant and draft before publish return, including post-publication status/pruning failure; competing save/create/renew cannot escape transition.
- Inputs/fixture: existing `beforeStatus` fault hook, latches around framework publish and competing editing operations.
- Doubles or boundary isolation: real framework and SQLite, test hooks only.
- Edge cases: one old-base operation may complete before transition but is then invalidated; none can complete against A after transition; new creation uses B.

### 8. `rejectedPublicationPreservesEditingAndPreparationDoesNotBlockIt`
- Type: real runtime integration
- Location: `RuntimeConfigurationIntegrationTest.java`
- Proves: ordinary framework publish failure/reversion retains valid A drafts/leases; editing completes while candidate preparation is held; losing lease does not cancel frozen accepted publication or execution dispatch.
- Inputs/fixture: failure and preparation hooks/latches; framework handoff/dispatch fixture.
- Doubles or boundary isolation: real runtime coordinator, temporary database.
- Edge cases: commit failure and failed reversion fault state; check fault blocks edits/renewal but permits inspection/release/discard.

### 9. `editingRoutesHonorRoleCsrfAndErrorPrivacy`
- Type: real HTTP integration
- Location: `ManagementEditingHttpIntegrationTest.java`
- Proves: viewer read/status permissions versus forbidden mutations, editor acquisition, admin-only takeover, 401 without management session, 403 without CSRF, 409 stale/conflict, 400 malformed text, no leaked private data in errors.
- Inputs/fixture: viewer/editor/admin/JWT-only clients; valid and invalid JSON bodies.
- Doubles or boundary isolation: normal Spring Security chains and real HTTP.
- Edge cases: caller-supplied account ID is ignored/rejected; `Cache-Control: no-store` on private responses.

### 10. Existing model, recovery and architecture regression
- Type: existing unit/integration/ArchUnit suites
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationDraftTest.java`, `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationRecoveryIntegrationTest.java`, `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`
- Proves: exact authored content, persisted selection recovery and supported public framework dependency remain intact.
- Inputs/fixture: current sanitized local fixtures.
- Doubles or boundary isolation: existing tests unchanged unless required by direct implementation edits.
- Edge cases: full suite catches unrelated execution/management regressions.
