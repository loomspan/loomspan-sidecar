# Validated Configuration Import Testing Plan

## Change Summary

An editor/admin reviews an uploaded format-1 current-configuration bundle against destination validation, then confirms the exact reviewed bytes and observed runtime/lease state before import clears editing state and publishes a new local snapshot. The upload and review remain temporary; publication uses the existing database-first policy and framework generation lifecycle.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Bundle/HTTP bounds | Multipart defaults reject legal bundles or permit excess data; temp files survive rejection | Exact compressed/entry/expanded boundary tests, HTTP 413/invalid cases, temp cleanup checks |
| Review and validation | Tampered/changed bundle or stale environment bypasses review | Digest/review-ID conflict tests, confirm revalidation, placeholder matrix, no side effects before cutover |
| Authorization/privacy | Viewer can upload; missing CSRF or stale session can mutate; review exposes private draft | Authenticated HTTP/browser role/CSRF tests, owner-only identity without draft content |
| Confirmation/concurrency | Replacement grant or runtime publication slips through; lease renewal wrongly conflicts | Latch-driven grant/runtime/editing tests, refreshed conflict observation, renewal success |
| Destructive cutover | Preparation failure loses drafts or post-cutover failure restores them | Injected preparation/staging/commit/activation/revert/status failures, editing state assertions |
| Persistence and execution | Import reuses source ID, history/status, or interrupts admitted generation | Two-context transfer, repeat IDs/provenance/history, generation-specific execution and restart tests |
| Browser outcome | Disconnect is interpreted as failure or retried; hostile strings become markup | Playwright safe rendering, success/known failure/unknown outcome and history-link tests |

## Existing Coverage and Environment Constraints

`ConfigurationBundleV1Test` already covers format-1 fixtures, exact authored/empty round trips, corruption, checksum, entry/expanded and compressed boundaries. `RestRouteLoaderTest` checks exact allowlisted process-environment URL resolution. `RuntimeConfigurationIntegrationTest` has fault hooks, latches, restart, ordinary publication, and generation-resource patterns. `ManagementConfigurationHttpIntegrationTest` has temporary SQLite, management auth/CSRF and publication HTTP patterns. `ManagementEditorBrowserIntegrationTest` and `ManagementHistoryBrowserIntegrationTest` use local Chromium Playwright and UI/fault conventions. `SupportedLoomspanApiArchitectureTest` is the supported framework surface gate.

Maven tests require the developer-installed `ai.loomspan:loomspan-spring-boot-starter:1.0.0-beta.5-SNAPSHOT` aligned with the local framework checkout. Browser tests require installed Playwright Chromium. HTTP tests use local dynamic ports/databases and local fixtures; no external service or production credential should be used. For process environment binding, use the repository's injectable `RestRouteLoader` fixture where possible; for full destination transfer, launch two isolated application contexts with separate database paths and destination configuration, using controlled local environment or injectable route loader setup rather than changing the host's real environment globally.

## Tests to Add or Update

### 1. `reviewAcceptsOnlyCompleteBoundedFormatOneBundle`
- Type: parser and HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/bundle/ConfigurationBundleV1Test.java`; `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: documented fixture/empty bundle and a valid large compressed upload reach validation; unsupported format, malformed ZIP/YAML, checksum mismatch, wrong/extra parts, >100 MiB compressed, >512 MiB expanded, and >10,000 entries reject before editing/history change. Exact limits remain inclusive.
- Inputs/fixture: generated format-1 ZIPs and existing bundle fixtures; use sparse/repetitive data where possible to avoid giant checked-in fixtures.
- Doubles or boundary isolation: local MockMvc or real multipart server for container limit behavior; temporary filesystem for cleanup.
- Edge cases: 100 MiB ZIP exactly versus one byte more, multipart envelope overhead, reader-created and servlet-created temp files after success/rejection.

### 2. `reviewReportsDestinationValidationAndAuthoredMetadata`
- Type: integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/rest/RestRouteLoaderTest.java`
- Proves: public framework skill validation and matching route checks run on the complete bundle; warnings and errors appear; authored YAML/placeholders remain exact; literal URLs and empty complete configuration work.
- Inputs/fixture: valid/invalid skill documents, REST routes, destination allowlist with present valid, absent, undeclared, blank and invalid HTTP(S) URL values.
- Doubles or boundary isolation: use local injectable process-environment lookup and local REST target; no external endpoint.
- Edge cases: validation failure cannot produce a confirmable review; route counts distinguish parsed routes from source YAML documents, and a document containing multiple skills is counted correctly.

### 3. `importEndpointsRequireEditorSessionAndCsrf`
- Type: real HTTP integration and browser
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/management/ManagementImportBrowserIntegrationTest.java`
- Proves: unauthenticated requests fail, viewer upload/confirm and page access fail, editor/admin without lease may import, missing/wrong CSRF fails, stale role/session fails at admission; execution JWT does not authorize management import.
- Inputs/fixture: local viewer, editor, admin accounts and authenticated browser sessions.
- Doubles or boundary isolation: existing local mail/auth fixture and temporary SQLite.
- Edge cases: logout/idle expiration before acceptance; foreign draft remains private in review.

### 4. `confirmationBindsReviewedBytesRuntimeAndGrant`
- Type: HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: wrong/replaced review ID, changed ZIP byte, stale published ID, acquired/replaced/released/expired grant, and changed destination validation all reject without draft loss, and return fresh runtime/owner/grant observation. Same-grant activity renewal succeeds. Repeated identical import requires a new review.
- Inputs/fixture: two bundles with distinct content, two accounts/tabs, clock-controlled lease and review sessions.
- Doubles or boundary isolation: existing management clock/lease fixture and local DB.
- Edge cases: replacement grant by same owner/tab/session; absent lease becoming present; `PENDING` intended pointer while runtime ID remains previous; second review in same session supersedes first.

### 5. `importCutoverSerializesEditingAndPublication`
- Type: runtime integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/management/ManagementEditingServiceTest.java`
- Proves: ordinary publication cannot pass import; lease acquisition, activity, save, release, discard, session destruction and account invalidation defer from confirmation through completion. No new owner is admitted mid-import. Preparation/staging failure leaves drafts/lease intact subject to ordinary expiry; success clears all.
- Inputs/fixture: hook latches at preparation, commit and framework publication with two threads/sessions.
- Doubles or boundary isolation: existing injectable hooks and local framework snapshot; use bounded waits and release latches in `finally`.
- Edge cases: accepted attempt continues after initiating browser disconnect, logout or expiry; subsequent editing requests receive conflict/status refresh rather than a silently valid old grant.

### 6. `importUsesFreshLocalIdentityAndDestinationBindings`
- Type: multi-context runtime/HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: export from instance A and import into B preserves all authored skills/routes/targets, source ID is provenance, each repeated import gets a distinct B local ID, B history/status and account/installation configuration remain local, and identical `${NAME}` authored text resolves to each destination's own allowlisted URL. No restart is required.
- Inputs/fixture: two isolated databases and local HTTP target servers with distinct destination settings.
- Doubles or boundary isolation: isolated application contexts, loopback endpoints and controlled environment lookup.
- Edge cases: zero-skill/zero-route complete replacement; source has retained failed history that is absent on destination.

### 7. `importFaultOutcomesMatchDatabaseFirstPolicy`
- Type: runtime and HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationRecoveryIntegrationTest.java`
- Proves: preparation/staging failure has no submission or draft loss; commit failure keeps predecessor pointer/runtime but drafts stay cleared; activation failure marks submitted snapshot `FAILED` and restores predecessor; revert failure leaves pending intended pointer and mutation fault; status/prune failure does not undo active runtime; restart follows committed pointer. Failure HTTP body identifies code, published ID, intended ID/status, and fault without leaking authored secrets.
- Inputs/fixture: existing phase hooks and DB fault injection.
- Doubles or boundary isolation: temporary SQLite and local framework.
- Edge cases: `PENDING` is unknown outcome, not success/failure; inspection/execution remain available under mutation fault, configuration mutations stop.

### 8. `importPreservesGenerationResourcesAndBrowserOutcomes`
- Type: runtime generation integration and Playwright browser
- Location: `src/test/java/ai/loomspan/sidecar/rest/RestGenerationIntegrationTest.java`; `src/test/java/ai/loomspan/sidecar/management/ManagementImportBrowserIntegrationTest.java`
- Proves: work admitted before import uses old route/target generation while new work uses the imported one. Browser review shows source, versions, counts, feedback and owner warning as text; file change invalidates confirmation; conflict refreshes observation; success links to local history; known failure and disconnected unknown outcome differ; no automatic retry.
- Inputs/fixture: loopback REST handlers, HTML-like source labels/issue messages, two logged-in sessions, simulated dropped response.
- Doubles or boundary isolation: local Playwright Chromium and loopback HTTP targets.
- Edge cases: viewer cannot see import action; editor without lease can complete; invalidated editing tab receives existing conflict/refresh response.

### 9. `supportedApiBoundaryStillHolds`
- Type: architecture
- Location: `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`
- Proves: new production and test code depend on the closed supported `ai.loomspan.api` surface only, without `ai.loomspan.internal..` or `ai.loomspan.autoconfigure..`.
- Inputs/fixture: compiled classes.
- Doubles or boundary isolation: none.
- Edge cases: new import-specific framework calls remain public.
