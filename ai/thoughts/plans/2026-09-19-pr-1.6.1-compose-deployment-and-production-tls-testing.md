# Compose Deployment and Production TLS Testing Plan

## Change Summary

Add a production Compose path with direct Spring Boot PEM HTTPS, durable single-instance SQLite, non-root mounts, customer-supplied SMTP and external URL, and internal-only health. Remove active Kubernetes deployment support artifacts. Verify the actual runtime image and browser flow against the locally installed Loomspan beta 5 snapshot.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| TLS and browser session | HTTPS may fail from key permissions or issue a non-Secure cookie | Generated test PEM, real HTTPS Playwright setup/login, cookie attribute and certificate checks |
| Port exposure | Health might be published publicly, or HTTP remain on the application port | Compose render and container port inspection; HTTPS request succeeds, plain HTTP does not; in-container health succeeds |
| Persistent state | Mount may be unwritable by UID 10001 or recreation may lose accounts/config | Container UID/file ownership and DB write checks; stop/recreate with same volume, sign in without setup credential, read selected configuration |
| Startup and auth | Dispatch could open before DB activation or management lock could deny execution | Fresh empty/locked runs; readiness after activation; JWT-protected `/v1/skills`, authenticated execution independent of setup credential |
| Mail and URL | Generated links may use request Host, SMTP may contact a real address, REST variable may bypass allowlist | Test-only local SMTP capture; `.test` recipients; setup/recovery link origin assertions; publish/use allowlisted fixture REST target; reject undeclared variable |
| Shutdown and recovery | Container may be killed before admitted work finishes; restored files may have wrong ownership | Measured SIGTERM completion/cutoff fixture and Compose grace; stopped DB/WAL/SHM copy/restore under UID 10001 |
| Documentation/release | Docs may conflict with Compose or imply Kubernetes support; CI may assume an unpublished artifact locally | Source-reference tests, Compose render, targeted `rg`; local Maven/image verification on snapshot only |

## Existing Coverage and Environment Constraints

`ManagementMailHttpIntegrationTest` already covers setup, invitation and recovery link contents through a local SMTP server, but not a container. `ManagementEditorBrowserIntegrationTest` establishes Playwright Java conventions but runs a local Spring test server, not the production image. `ManagementLockedExecutionIntegrationTest`, `MountedSkillRegistrationIntegrationTest`, `RestRouteLoaderTest`, `ExecutionShutdownIntegrationTest`, and `RuntimeConfigurationRecoveryIntegrationTest` cover their respective application contracts. They remain useful regressions, not deployment proof. `scripts/verify-image.py` launches quickstart Compose and currently contains a Kubernetes structural assertion; `scripts/verify-shutdown.py` can exercise admitted work with a stopped populated test database. `ConfigurationReferenceTest` reads configuration examples and README; `ReleasePreparationTest` reads CI/verifier source.

Local prerequisites for the end-to-end gate are Docker Engine/Compose, Python 3, Java 21/Maven wrapper, a local image built after the snapshot-backed JAR, and the existing Playwright Chromium installation. The harness must use ephemeral project/volume names, loopback host ports, fixture issuer/model/SMTP, `.test` addresses, and generated disposable PEM material. It must time out commands and always remove its own containers/volumes. It must never touch the operator's production env file, data volume, real SMTP service, or recipients. Hosted CI's Maven dependency is the later published beta 5; its execution is deferred until publication.

## Failing Test First

- Name: `productionComposeRendersHttpsOnlyAndKeepsHealthInternal` (or equivalent initial assertion in the production verifier).
- Type: deployment configuration/integration test.
- Location: `scripts/verify-production.py`, supported by `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java`.
- Arrange/Act/Assert: render `examples/production/compose.yaml` with the checked-in example configuration and temporary test paths; assert one Sidecar service, non-root identity, writable persistent `/sidecar/data`, read-only PEM/JWT material, required HTTPS certificate/key settings, Secure cookie, a published HTTPS application mapping, no published 9091 mapping, and a finite stop grace greater than the framework timeout.
- Expected pre-fix failure: the production Compose file and verifier do not exist. This directly demonstrates the missing deployment capability before implementation; subsequent browser/container cases may be added as the fixture is assembled.

## Tests to Add or Update

### 1. `productionComposeRendersHttpsOnlyAndKeepsHealthInternal`

- Type: static Compose render/reference check.
- Location: `scripts/verify-production.py` and `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java`.
- Proves: the documented production service has the intended TLS, mounts, UID, health, and exposure shape; Kubernetes sample assertions are gone.
- Inputs/fixture: sample env values and disposable fixture paths; run `docker compose config` without starting containers.
- Doubles or boundary isolation: no external services.
- Edge cases: missing required TLS/JWT/model/SMTP values should fail rendering or fail the documented preflight, without silently falling back to insecure defaults.

### 2. `productionHttpsSetupLoginAndRecovery`

- Type: container plus real Chromium browser test.
- Location: `src/test/java/ai/loomspan/sidecar/deployment/ProductionComposeBrowserIntegrationTest.java`, driven by `scripts/verify-production.py`.
- Proves: browser reaches HTTPS console with generated trusted-in-test certificate, one-time setup sends a captured mail link using the configured external HTTPS origin, password setup and login succeed, session cookie has Secure, and recovery mail link uses the same origin. Invitation can be checked in this flow with a `.test` address if the fixture is already active.
- Inputs/fixture: generated disposable PEM, explicit harness URL, random setup credential, local SMTP capture, `.test` addresses. Browser test runs only when the harness supplies its URL and credentials; it must not silently skip during the production verifier.
- Doubles or boundary isolation: fixture SMTP/model/JWT only; no real recipients or network services.
- Edge cases: Host-header spoof does not change mail origin; an HTTPS cookie is not sent over plain HTTP.

### 3. `productionVolumeSurvivesRecreateWithoutSetupCredential`

- Type: container/database integration test.
- Location: `scripts/verify-production.py` with browser assertions above.
- Proves: image runs as 10001:10001, SQLite DB and auxiliary files are writable, initialized accounts and a published database-selected configuration survive `up --force-recreate` after removing setup credential. Mounted skill/route files cannot become active; an empty database begins with an empty snapshot.
- Inputs/fixture: uniquely named local Compose volume, fixture JWT/model, test-authored configuration.
- Doubles or boundary isolation: only the harness-owned volume is removed in cleanup.
- Edge cases: new volume with no setup credential leaves management setup locked but JWT-authenticated execution available; a bad data ownership setup fails visibly.

### 4. `productionJwtModelAndUrlVariableRoute`

- Type: container HTTP integration test.
- Location: `scripts/verify-production.py`.
- Proves: no token is rejected, fixture JWT is accepted, configured model connection executes, and a REST `base-url: ${TARGET_URL}` resolves only when `TARGET_URL` is declared by `LOOMSPAN_SIDECAR_URL_VARIABLES` and supplied in the container environment.
- Inputs/fixture: deterministic issuer/model/REST host, authored skill/route YAML published through management, synthetic payloads.
- Doubles or boundary isolation: all outbound calls stay inside the fixture Compose network.
- Edge cases: undeclared or absent target variable is rejected at validation/publication and cannot silently use arbitrary process environment.

### 5. `productionHealthShutdownAndRecovery`

- Type: container lifecycle/integration test.
- Location: `scripts/verify-production.py`, reusing `scripts/verify-shutdown.py` and `scripts/fixtures/shutdown-host.py` where appropriate.
- Proves: readiness goes UP only after activation, liveness remains meaningful, new dispatch refuses during close, already admitted work completes or reaches the framework timeout, and Compose allows enough time before kill. A stopped database copy including existing WAL/SHM can be restored with UID/GID 10001 ownership and reactivated.
- Inputs/fixture: isolated populated stopped test database from the harness; callback gate; 3-second framework timeout in the test only.
- Doubles or boundary isolation: local callback host and harness-owned volume/data directory.
- Edge cases: do not infer active shutdown from an empty database or `--validate-only`; report actual completion/cutoff outcomes. Cleanup must not delete operator data.

### 6. `configurationReferenceMatchesBoundPropertiesAndExamples` and release checks

- Type: existing JUnit source-reference tests plus targeted source search.
- Location: `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java`, `src/test/java/ai/loomspan/sidecar/release/ReleasePreparationTest.java`.
- Proves: production README/Compose/example values agree, quickstart is explicitly development-only, production image has no SMTP capture service, current Kubernetes example and CI flag are removed, CI invokes the supported verifier without publishing an image.
- Inputs/fixture: repository files only.
- Doubles or boundary isolation: no Docker needed for the JUnit source checks.
- Edge cases: historical ticket/evidence records are outside the removal search; explicit Kubernetes deferral text is allowed.

## Safe Verification Commands

- Focused red/config test: `.\mvnw.cmd -B -ntp -Dtest=ConfigurationReferenceTest,ReleasePreparationTest test` and `docker compose --env-file examples/production/production.env.example -f examples/production/compose.yaml config --quiet`.
- Related application suite: `.\mvnw.cmd -B -ntp -Dtest=ManagementMailHttpIntegrationTest,ManagementLockedExecutionIntegrationTest,MountedSkillRegistrationIntegrationTest,RestRouteLoaderTest,ExecutionShutdownIntegrationTest,RuntimeConfigurationRecoveryIntegrationTest test`.
- Full safe suite: `.\mvnw.cmd -B -ntp verify` against the developer-installed `1.0.0-beta.5-SNAPSHOT` dependency.
- Image/deployment: `.\mvnw.cmd -B -ntp package`; `docker build --tag loomspan-sidecar:sc5-local .`; `python scripts/verify-image.py --image loomspan-sidecar:sc5-local`; `python scripts/verify-production.py --image loomspan-sidecar:sc5-local`.
- Shutdown fixture: `python scripts/verify-production.py --image loomspan-sidecar:sc5-local` must run active admitted-work completion/cutoff itself or invoke `verify-shutdown.py` with its generated stopped database. `--validate-only` is insufficient proof.
- Reference search: `rg -n -i 'kubernetes|kubectl|verify-kubernetes' README.md examples scripts .github src/test` and inspect remaining matches for only explicit deferral/history.

The production verifier may invoke the focused Playwright JUnit class using `.\mvnw.cmd -B -ntp -Dtest=ProductionComposeBrowserIntegrationTest test` with explicit harness environment. On POSIX it uses `./mvnw`. The final harness command, not a standalone skipped browser test, is the required end-to-end gate.
