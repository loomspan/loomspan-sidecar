# Embedded Console and Account Flows Testing Plan

## Change Summary

Add embedded browser pages/assets for account lifecycle, admin account operations and read-only runtime configuration. Preserve the existing Spring session, CSRF, role, idle-timeout and JWT boundaries while verifying client interaction and packaged delivery.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Browser entry/recovery | Setup lock/reservation or used links could imply access is ready or expose account existence | Form/HTTP and loopback SMTP lifecycle; browser feedback inspection |
| Passwords | UI guidance or native input limits could disagree with Unicode/byte/composition policy or block paste | Existing `ManagementPolicy` tests plus form assertions and browser paste/autofill check |
| Admin operations | Stale role/session or missing CSRF could allow an unintended mutation; mail could fail after invite persisted | HTTP role/CSRF/session/last-admin assertions and browser 401/403/retry path |
| Published configuration | Viewer might see intended selection as running, omit documents, or execute authored HTML | Exact API content assertion and browser text-node/inert-markup check |
| Privacy/identity | Anonymous/JWT users could access management data; another session's draft could leak | Existing management/configuration/editing HTTP suites plus protected-page assertions |
| Idle/execution | Passive refresh could renew management login or management lock could affect JWT execution | Clock-based idle test; browser network observation for no passive activity; existing JWT execution checks |
| Packaging/accessibility | Asset missing from JAR/image or controls unusable by keyboard | JAR entry listing, asset HTTP checks and real-browser keyboard/feedback walkthrough |

## Existing Coverage and Environment Constraints

`ManagementHttpIntegrationTest` uses a real random-port server, cookies, fixture JWT keys, a mutable clock and temporary SQLite. `ManagementMailHttpIntegrationTest` and `ManagementMailIntegrationTest` use controlled loopback SMTP for setup, invitation, retry and reset. `ManagementConfigurationHttpIntegrationTest` verifies published snapshot semantics, viewer/role/JWT access and draft publication. `ManagementEditingHttpIntegrationTest` covers private draft ownership and idle behavior. `SupportedLoomspanApiArchitectureTest` enforces the public framework API boundary. No installed JavaScript test framework or browser automation is part of `pom.xml`; Node is available, but a separate frontend build is unnecessary. Use the locally installed beta 5 snapshot. Tests must use temporary storage, fixture JWTs, and loopback mail only. Browser verification needs an isolated local instance/fixture and must not contact a production account or SMTP service.

## Tests to Add or Update

### 1. `setupAndRecoveryPagesExplainStateWithoutLeakingSecrets`

- Type: Random-port HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`
- Proves: Locked/unreserved/reserved/complete setup language is accurate, setup credential is never embedded, native forms carry CSRF, invalid/used-link guidance names safe next steps, and known/unknown forgot responses are identical.
- Inputs/fixture: Existing temporary SQLite and setup-supplier fixture; loopback SMTP lifecycle where reservation/activation is required.
- Doubles or boundary isolation: Test credential and loopback mail only.
- Edge cases: Credential absent/malformed; email delivery unavailable; reused token; no automatic session on set/reset.

### 2. `passwordFormsMatchServerPolicyAndAllowLongPastedValues`

- Type: HTTP form and policy test, followed by browser interaction.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java` plus browser verification record in Step 4.
- Proves: Every set/reset/change page states 15–128 Unicode code points and 512 UTF-8 bytes, upper/lower/digit/non-whitespace punctuation-or-symbol composition, spaces allowed, and no UI prevention of paste/autofill. Server still rejects 14-character/space-as-symbol passwords and accepts a long valid one; extend `ManagementIdentityStoreTest` for the UTF-8 byte cap and code-point boundary.
- Inputs/fixture: Representative Unicode and ASCII passwords; no live credentials.
- Doubles or boundary isolation: Existing `ManagementPolicy` and local account fixture.
- Edge cases: Spaces, multibyte code points, upper byte cap, no browser `maxlength` mismatch.

### 3. `managementConsolePagesAndAssetsRespectRolesAndCsrf`

- Type: Random-port HTTP integration.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`
- Proves: Authenticated viewer/editor/admin can open the shell/current page, only admin opens account page/API, anonymous/JWT-only clients cannot obtain protected content, and unsafe account requests without CSRF are 403. CSS/JS are served by the same application port with no-store/no-referrer management headers; valid JWT execution remains available while management setup is locked.
- Inputs/fixture: Seed one account per role and fixture JWT.
- Doubles or boundary isolation: Cookie-backed local HTTP clients.
- Edge cases: Stale session after disable or role change; management cookie does not authenticate `/v1/**`; health port does not serve console assets.

### 4. `adminBrowserActionsUseExistingAccountContract`

- Type: Loopback SMTP plus random-port HTTP integration, and real-browser walkthrough.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementMailHttpIntegrationTest.java` plus Step 4 browser verification record.
- Proves: Invite creates a pending immutable-email account and sends a set link; role changes and disable/re-enable work; last enabled activated admin cannot be demoted/disabled; delivery failure supports resend after SMTP recovery; a changed account's old session loses access.
- Inputs/fixture: Temporary SQLite, fixture admin/viewer, local SMTP messages.
- Doubles or boundary isolation: Controlled SMTP server, never real recipients.
- Edge cases: Failure after invite persistence, pending-account resend, self-demotion, disabled invitee, stale CSRF/session.

### 5. `viewerSeesExactRuntimePublishedSnapshotOnly`

- Type: Existing configuration random-port HTTP integration plus real-browser rendering check.
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java` plus Step 4 browser verification record.
- Proves: Viewer obtains all `skillDocuments` and `restRoutesYaml` authored bytes/placeholders from `published`, displayed with runtime `localId/status`; `intendedId/intendedStatus/mutationFault` are separate, not substituted for execution state. Authored markup and diagnostic strings remain inert text. Another session's private draft and validation remain unavailable.
- Inputs/fixture: Published fixture with multiple source labels, placeholder text, and inert markup-like YAML; intended-selection difference when safely constructible through existing test hooks.
- Doubles or boundary isolation: Temporary database and existing runtime fixture; no production configuration.
- Edge cases: Empty document list, null source ID, differing intended pointer/fault, literal `<script>` string.

### 6. `passiveConsoleReadsDoNotRenewIdleSession`

- Type: Clock-based random-port HTTP integration and browser network inspection.
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java` (extend existing idle test).
- Proves: Opening/refreshing the current view and calling session/current GET do not advance `ManagementSessionGuard.ACTIVITY`; after timeout the API returns 401 and browser stops actions. Intentional activity can renew only through `/session/activity` at the server's 30-second cadence.
- Inputs/fixture: Existing mutable clock and logged-in viewer.
- Doubles or boundary isolation: Local HTTP only.
- Edge cases: Idle tab, explicit Refresh, role/credential version change, no activity request on load or fetch completion.

### 7. Browser interaction and delivery walkthrough

- Type: Required real-browser verification of the delivered console against an isolated local Sidecar instance.
- Location: Step 4 verification record (no new test framework required unless a maintainable browser runner is already available during implementation).
- Proves: Keyboard-only entry, focus visibility, labels and status text; setup/emailed-link/login/logout/recovery/change/admin paths; paste/autofill; role-based navigation; 401/403 stale-state handling; current YAML and `<script>`-like content render as inert text; no background `/session/activity` traffic; UI works with assets from the packaged JAR.
- Inputs/fixture: Disposable SQLite, generated setup credential, controlled loopback SMTP, fixture JWT; browser DevTools/network observations where useful.
- Doubles or boundary isolation: No live mail, execution service, accounts or production data.
- Edge cases: Disabled/changed account, failed SMTP invite followed by resend, used reset link, keyboard submit and feedback after errors.

## Step 4 browser verification record

The repackaged JAR ran on `127.0.0.1:18088` with a disposable SQLite file under
`%TEMP%`, health port `19091`, the repository's fixture JWT public key, a fixture
setup credential, and a Python loopback-only SMTP receiver on `127.0.0.1:25252`.
SMTP, sender, and external console URL were set to local fixture values; no live
recipient or service was contacted. Chrome opened the packaged console on the
application port. The fixture process and SMTP receiver were stopped afterward.

The browser showed keyboard Tab/Enter entry and a visible focus ring; setup,
login/logout, change-password, and recovery forms had labels and text feedback.
The initial setup request produced a loopback email; the one-time password set
was completed through local HTTP fixture requests, then the browser signed in.
Known and unknown recovery requests displayed identical text. Administrator
actions in the browser invited an account, resent its setup link, changed its
role, disabled and re-enabled it, and showed the last-admin rejection. Stopping
SMTP caused an invite failure while the pending account remained visible;
restarting loopback SMTP allowed the browser's resend action to succeed.
After a role change through a second fixture session, the stale browser's
Refresh action returned to login; a fresh viewer login omitted admin navigation.
The current view rendered an authored `${EXAMPLE}` placeholder and
`<script>window.__sidecarInjected=1</script>` literally: its `pre` contained the
exact text, while the DOM had zero script descendants there and no injected
global. The password field accepted a long pasted value, retained
`autocomplete=new-password`, and had no `maxlength` or `onpaste` restriction.
Opening the current page did not trigger a client activity report in code;
the clock-based HTTP idle test supplies executable evidence that reads do not
renew the session. Browser tooling did not expose network timing entries, so a
direct browser network trace of passive activity was not recorded.
