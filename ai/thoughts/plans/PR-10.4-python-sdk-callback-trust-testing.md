# Python SDK Callback Trust Testing Plan

## Change Summary

Prove callback authentication against the startup signer's public key and a
complete current local overlap JWKS. Exercise the explicit async lifecycle
without a web framework. Separately verify an actual Java-issued credential
with Java's exported key through the installed Python verifier.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| JWT profile and crypto | Wrong issuer/audience/authority, unsupported critical extension, or forged signature gets admitted | Real RSA signature tests with independently signed malformed and valid profiles |
| NumericDate | Double rounding or extra default JWT policies change acceptance | Exact wire decimals, nanosecond boundary assertions, and actual Java issuance |
| Runtime trust | Partial or obsolete keys are admitted after a bad file | Initial-invalid matrix, same-metadata replacement, complete withdrawal and recovery tests |
| Lifecycle | Flood triggers reads per kid, async loop blocks, or closing leaks owned refresh | Event barriers, deterministic miss timer, real periodic poll, scoped cancellation |
| Secret handling | Bad input leaks through errors, log records or identity serialization | Exact category messages and marker checks in errors, logs and serialized principal |
| Package surface | Wheel/sdist or typing smoke misses core verifier and its lifetime | Fresh installed consumer in existing distribution runner |

## Existing Coverage and Environment Constraints

`sdks/python/tests/test_issuance.py` and `test_signing.py` prove producer
behavior and signing startup. `sdks/python/tests/verify_java_issuance.py` proves
the reverse direction through Java receivers. The Java starter unit tests
establish baseline decoder and overlap behavior. None verifies the new Python
receiver. Use pytest, existing AnyIO and cryptography, the repository synthetic
RSA fixture if a shared key is useful, and `tmp_path` for generated files.
Tests in the async client already use async runs with bounded test waits.

Local Windows x86-64 CPython 3.13, WSL x86-64 CPython 3.12 and offline Maven
with Java 21 are available. The standalone Java SDK core reactor requires no
Framework snapshot to emit these fixtures. No live or deployed environment
is necessary. PR 10.5 owns router/lifespan composition tests and PR 10.6 owns
the full support and deployment matrix.

## Tests to Add or Update

### 1. Profile, trust selection and credential safety

`sdks/python/tests/test_callback_verifier.py` uses an independently constructed
compact JWS helper and real RSA private keys for targeted header and claims
tests. Use raw JSON fixtures when object mutation cannot express the bad wire
form. Keep signing and verification test clocks fixed separately.

- Admit Python-issued default audience and exact configured issuer, plus an
  explicit receiver audience. Admit one matching string and a string-array
  containing the receiver. Reject absent/empty/wrong audiences and lists with
  nonstring entries even if the receiver is also present. Reject wrong issuer,
  required missing claims, wrong purpose, blank/incorrect subject and wrong
  roles shapes. Accept empty roles and preserve ordered spelling without
  deriving authority from `scope` or extras.
- Reject missing or incorrect `alg`, `typ` and `kid`, unknown critical headers,
  non-boolean/false `b64`, malformed compact token and Base64URL, duplicate
  fields, invalid UTF-8/JSON, signatures altered or made by an untrusted key,
  and any attempt to substitute an embedded public key for local trust. A
  supported encoded `b64` declaration must still use ordinary signing input.
- Check that optional absent `iat`, `nbf`, `jti` pass and that present null or
  wrong types fail. Accept any `jti` string and future `iat` preceding `exp`.
  Reject invalid audience settings and overlap types safely.
- Assert the returned object and its authority tuple are immutable and ordinary
  serialization includes only the three expected identity fields. Check the
  same typed error and fixed safe message across malformed, expired, unknown-key
  and bad-signature cases. Check no cause/context or input marker in ordinary
  traceback and exception formatting.

### 2. Exact timestamps

`sdks/python/tests/test_callback_verifier.py` also signs raw wire decimals for
`exp`, `nbf`, and `iat` at exact fractional skew edges. Use a contemporary
fixed nanosecond clock and a pre-epoch value to verify floor semantics.

- Accept `exp` at `now - 60s` and `nbf` at `now + 60s`, reject each one
  nanosecond outside, and prove the opposite side passes. Include signed
  fractions at and below nanosecond precision to catch rounding and double
  rounding. The converter should be independent of application Decimal context.
- Accept a 1 ns lifetime, reject equal or earlier `exp` when `iat` is present,
  and avoid adding a separate `nbf`/`exp` ordering constraint. Include a Java
  `Instant` boundary and an out-of-range number in either direction. Reject
  boolean, string, null, nonfinite values and large exponent overflow. Cover
  `iat` and `nbf` range/type checks as well as `exp`.

### 3. Startup and complete current snapshots

`sdks/python/tests/test_callback_trust.py` uses actual temporary JWKS files,
tokens for own/old/new keys and a controlled reader for races. Avoid changing
real file permissions on shared files to simulate unavailability. Raise
`PermissionError` at the read boundary for the unreadable case.

- Opening with missing, unreadable, malformed UTF-8/JSON, duplicate JSON keys,
  empty and structurally invalid overlap must fail safely before scheduling the
  poll. A normal no-overlap lifecycle reads no file and schedules no work,
  even on unknown kid. Place read/schedule spies after issuer construction so
  the signing export is separate from the measured behavior.
- Parameterize partial-looking key sets with a valid first candidate and a bad
  second candidate, including non-RSA, duplicate kid, blank/missing kid,
  weak/even modulus, exponent too small/even/out of range, private members
  (even null), illegal Base64URL, and incompatible optional `use`/`alg`. Reject
  conflicting own kid. Accept identical own public numbers and omitted
  optional use/alg. No key from a rejected set becomes current.
- Across ready, unavailable, invalid and restored categories, prove own and
  overlap credentials both fail on withdrawal and only current keys return.
  Keep a previously verified principal and verify its immutable identity still
  reads correctly after withdrawal and expiry. Handler lifecycle is PR 10.5.
  Verify same-size, same-mtime replacement is visible by changing actual file
  bytes. Keep one bounded real one-second periodic poll test that observes
  withdrawal and restoration independently of unknown-kid triggers.
- Use event barriers to pause a single read while verifications run. The old
  complete snapshot remains usable before a changed candidate is published.
  After publication only the complete replacement is usable, with no mixed
  state. Assert one safe record per runtime category change, no repeated
  unchanged failure, no valid-to-valid restoration record and no sensitive
  file path, parser diagnostics, key value or token marker in logs.

### 4. Throttle, shutdown and async scheduling

`sdks/python/tests/test_callback_trust.py` uses an internal monotonic clock
patch and event barriers. Use bounded test waits with generous scheduling
headroom. Leave enough distance from the actual poll timer in isolated miss
tests or control its wait in the test, so periodic reads do not mask per-miss
count assertions.

- The first eligible miss requests at most one refresh. A concurrent flood of
  distinct unknown kids starts one worker read, consumes one time window and
  never queues work per kid. Repeated misses before the boundary do no new
  read. A corrected file and an eligible miss at the one-second boundary can
  validate the new key in that call. Known-key traffic does not request refresh.
- While a reader waits on a finite test gate, a known-key verification and an
  unrelated coroutine can proceed. Cancel a waiting request without cancelling
  the shared refresh or blocking another waiter. On close, wake or release
  pending verification waiters and prevent any post-close publication or read.
  Exercise normal exit, cancelled lifetime and an exception leaving the context.
  Assert no worker starts after failed initialization. Use event/timeout
  bounds and read counts rather than process-global thread counts, since AnyIO
  can keep its own reusable thread pool.

### 5. Actual Java-issued credentials

`sdks/java/core/src/test/java/ai/loomspan/sdk/JavaCallbackIssuanceFixtureTest.java`
generates tokens using production Java `SigningKeys.initialize` and
`ExecutionTokenIssuer`, with `Clock.fixed` and `CredentialSnapshot`'s
package-local accessor. Gate the fixture producer with
`LOOMSPAN_JAVA_CALLBACK_FIXTURES`. Use the real public export and an explicitly
named additional audience. Issue a normal credential for exact mixed-prefix
authorities and a credential with a one-nanosecond lifetime at a fractional
modern epoch. Use an ephemeral Java colocated key so trust cannot accidentally
come from Python's own key.

`sdks/python/tests/verify_java_callbacks.py` opens scratch storage, calls
the Maven test and requires the resulting JWTs and public export to exist.
Use a separate Python startup issuer and its verifier. Show rejection without
Java public overlap and acceptance with it, check issuer, subject and exact
authorities, and verify default plus explicit audiences. Move the Python clock
to the tiny token's exact skew limit and one nanosecond past. Clean scratch
files and avoid displaying credentials on failure or success. No skipped
fixture test counts as interoperability evidence.

### 6. Installed package and documentation

Extend `sdks/python/tests/verify_distribution.py` to exercise the README
verifier example and new public API in fresh wheel and sdist environments.
Continue to check `py.typed`, strict installed-consumer typing and the absence
of web dependencies. Preserve existing examples and response/issuance tests.

## Safe Verification Commands

From the repository root. The Windows runner and WSL `uv` are the same local
tooling used for the preceding ticket. On a separate Linux host use its
installed `uv`. An isolated `uv` environment may resolve build and dev
packages. Maven runs offline and application network traffic is local test
fixtures only.

- Red test `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests/test_callback_verifier.py -k test_verifies_own_issued_credential`
- Focused `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests/test_callback_verifier.py sdks/python/tests/test_callback_trust.py`
- Full Windows SDK suite `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests`
- Full WSL SDK suite `wsl -- /tmp/tmp.BAtdz0ltv1/uv run --no-project --isolated --python 3.12 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests`
- Strict source typing `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m mypy --strict sdks/python/src/loomspan_sdk`
- Installed wheel/sdist and consumer typing `uv run --no-project --isolated --python 3.13 python sdks/python/tests/verify_distribution.py`
- Java fixture to newly installed Python package `uv run --no-cache --no-project --isolated --python 3.13 --with ./sdks/python python sdks/python/tests/verify_java_callbacks.py`
