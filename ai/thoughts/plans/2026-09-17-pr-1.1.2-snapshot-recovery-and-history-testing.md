# Snapshot Recovery and History Testing Plan

## Change Summary

Submission will atomically append pending B and switch the intended pointer from expected A to B. Reversion will atomically point back to A and mark B failed. Startup will load the pointer-selected complete snapshot regardless of status and prune eligible history to a configurable target. A stopped-instance full-database copy will be documented and tested for recovery.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Transaction and concurrency | Partial B or stale writer changes pointer | SQL failure triggers, guarded expected-current test, actual SQLite reopen |
| Crash recovery | Pending B misread as failed or A/B YAML mixed | Forked JVM interruption and committed/reverted reopen cases with distinct sentinels |
| Corrupt selected state | Startup silently reseeds/falls back or leaks authored secret | Direct SQL corruption and sanitized-failure assertions |
| Retention | Current/live protected rows deleted, failed/pending rows excluded, target treated incorrectly | Real SQLite multirow pruning with statuses, protection sets, and later release |
| Configuration | Nonpositive limit accepted or documented default diverges | Properties tests, defaults and reference tests |
| Backup and restore | Copy omits committed WAL content or history | Stopped-instance database/WAL/SHM copy and restored reopen comparison |

## Existing Coverage and Environment Constraints

`ConfigurationSnapshotStoreTest` and `ConfigurationSnapshotRepositoryTest` already use `@TempDir` file-backed SQLite, actual Flyway migrations, Spring JDBC, and `DataSourceTransactionManager`; they cover first-store initialization, incomplete insert rollback, corruption, immutability, and status bookkeeping. Extend these fixtures rather than introducing repository mocks. `SidecarDefaultsTest` reads `application.yml`; `ConfigurationReferenceTest` checks every bound getter has one README reference row. Maven Wrapper and Java 21 are the repository-standard tools. The local beta 5 snapshot must be installed in Maven; no network service, production database, framework rebuild, or hosted CI is required for these tests. Forked-process testing needs the local Java executable and Surefire's test classpath; fail clearly if the child cannot launch, and bound every wait.

## Tests to Add or Update

### 1. `submitsAndRevertsCompleteCandidateAtomically`

- Type: real SQLite store test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`.
- Proves: A-to-B insertion/pointer switch, B-to-A reversion/failed status, B retained, complete selected skill/REST pairing on each reopen.
- Inputs/fixture: A and B use different ordered skill documents and different REST target/route sentinels; B has a source UUID.
- Doubles or boundary isolation: Temporary SQLite file; new datasource/store on each reopen.
- Edge cases: B remains pending immediately after commit; A identity/content unchanged; B identity/content unchanged after failure.

### 2. `failedSubmissionOrReversionLeavesCommittedStateIntact`

- Type: real SQLite store test with SQL abort triggers.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`.
- Proves: Document-insert or pointer-update failure rolls back all B rows; failure while marking B failed rolls back reversion, leaving B current/pending and surfacing error.
- Inputs/fixture: SQL triggers on document, state, and status writes, installed one at a time.
- Doubles or boundary isolation: Temporary SQLite file only.
- Edge cases: `submit` rejects stale/nonexistent expected A without leaving B; `revert` rejects unexpected current B or missing A without changing status.

### 3. `statusRecordingDoesNotChangeIdentityContentOrSelection`

- Type: real SQLite store test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`.
- Proves: `updateStatus` can mark the selected B published after activation or a historical record failed without changing pointer/content/IDs; unknown ID errors propagate.
- Inputs/fixture: A/B with local and source IDs, authored text including a literal secret sentinel.
- Doubles or boundary isolation: Temporary SQLite file.
- Edge cases: Older pending history stays pending after selected B is marked published; SQL triggers still reject content updates.

### 4. `interruptedUncommittedCandidateReopensAtA`

- Type: forked-process real SQLite recovery test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java` plus a small child `main` fixture under `src/test/java/ai/loomspan/sidecar/storage/`.
- Proves: OS process termination with a transaction containing B rows and pointer update but no commit leaves A selected and no partial B on reopen.
- Inputs/fixture: Parent initializes A. Child opens same DB, starts a JDBC transaction, writes complete B and pointer, flushes a readiness signal, then waits; parent forcibly terminates child and reopens. Parent asserts A's full content, no B ID, and no B rows.
- Doubles or boundary isolation: The child is a local JVM using the test classpath; bounded readiness/exit waits and cleanup in `finally` prevent leaked processes.
- Edge cases: Child must signal only after its writes, ensuring the test actually interrupts an uncommitted write. A separate committed-B reopen case covers the opposite boundary.

### 5. `selectedLoadRejectsDamageWithoutFallbackOrSecretLeak`

- Type: real SQLite store/startup test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`.
- Proves: Initialized state with missing pointer/status/document or invalid selected content fails rather than reseeding or choosing older history; error names recovery action but no literal authored secret.
- Inputs/fixture: A and current B, with a distinctive secret sentinel in B's YAML; direct SQL deletion/corruption of B only.
- Doubles or boundary isolation: Temporary SQLite file; avoid inserting real credentials.
- Edge cases: B pending still loads when intact; historical pending status remains unknown; failed load does not trigger startup pruning.

### 6. `prunesOldestEligibleAcrossStatusesAndProtectionSets`

- Type: real SQLite store test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`.
- Proves: Default 10 and configured small target, status-neutral newest retention, oldest-eligible deletion, protected current even when caller omits it, protected count toward target, over-target when protection exceeds target, and later deletion after caller releases an ID.
- Inputs/fixture: Eleven or more snapshots with mixed pending/published/failed status, known sequence order, a small configured limit, and explicit caller-protected UUIDs.
- Doubles or boundary isolation: Temporary SQLite file; query all three tables to confirm FK cascade and use `findByLocalId` to prove expired history is absent.
- Edge cases: Fresh initialization, startup invocation after reopen, repeated prune/idempotence, missing protected ID, and one over-target current/protected set.

### 7. `rejectsNonpositiveRetentionAndDocumentsDefault`

- Type: properties and configuration-reference tests.
- Location: `src/test/java/ai/loomspan/sidecar/config/SidecarDefaultsTest.java` and `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java` (plus focused property setter/binding test if needed).
- Proves: `loomspan-sidecar.snapshots.max-retained` defaults to 10, is represented once in the README reference, accepts a positive configured value, and rejects zero/negative values at startup binding.
- Inputs/fixture: Isolated Spring config data/context or direct properties binding; no external service.
- Doubles or boundary isolation: No database needed for property validation.
- Edge cases: Default and custom values are distinct from execution-record `max-retained`.

### 8. `restoredStoppedDatabaseRetainsCurrentAndHistory`

- Type: real SQLite file backup/restore integration test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/StorageBackupRestoreTest.java` (or the store test class if simpler).
- Proves: Consistent stopped-instance copy of DB plus present WAL/SHM files restores the exact selected snapshot, authored skill/REST content, and retained IDs/statuses. Restoring after damage to the original selected state recovers from the backup.
- Inputs/fixture: A/B/C, including failed and pending history and literal YAML placeholders; close activity, copy database set to backup, damage original, restore to a clean path, then reopen with Flyway validation.
- Doubles or boundary isolation: Temporary directories and ordinary filesystem copies; no live volume or production instance.
- Edge cases: Compare the full set of retained local IDs/statuses, not just selected YAML; exclude transient post-backup writes from restored state.

### 9. `startupPrunesOnlyAfterValidSelection`

- Type: storage bean or store startup test.
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java` (or a focused `StorageConfiguration` context test).
- Proves: Startup invocation reduces eligible history while retaining current, and invalid selected state fails before any pruning.
- Inputs/fixture: Preloaded temporary DB over limit; separate corrupt selected-state DB.
- Doubles or boundary isolation: Use actual `StorageConfiguration` bean method or equivalent wiring that exercises its call order, rather than calling `prune` manually to stand in for startup.
- Edge cases: Migration completes before load/prune; fresh store still has its initial selected snapshot.
