# Python SDK FastAPI Integration Testing Plan

## Change Summary

Verify the optional FastAPI integration's startup, callback admission and
request identity behavior using ordinary application configuration. Prove the
documented colocated and provided-key recipes from isolated installations.
The [implementation plan](PR-10.5-python-sdk-fastapi-integration.md) maps
these tests to ticket acceptance criteria.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Resource lifetime | Signer or verifier starts too soon, partially started resources leak, dependency fails open | I/O guards, forced startup failure at each ownership boundary, teardown and omitted lifespan |
| HTTP boundary | Prefix aliases, duplicates, query tokens, browser identity, or short-circuit middleware bypass auth | Real route/middleware tests using raw ASGI scopes and direct response inspection |
| Request isolation | Shared or stale identity on concurrent requests, application error or cancellation | Overlapped requests and inspection of scope after downstream cleanup |
| Runtime changes | Revoked or expired credentials admit fresh requests, or accepted work loses its identity | Held callback, real overlap file refresh, deterministic clocks, fresh admission probes |
| Distribution | Base SDK gains web/server packages or runnable example diverges from docs | Installed wheel/sdist metadata, core smoke and installed FastAPI app smoke with both signing modes |

## Existing Coverage and Environment Constraints

Use pytest, AnyIO, the current wire fixture and the repository's synthetic
RSA PEM/JWKS fixture. `test_callback_verifier.py` establishes core JWT shapes,
audiences and time boundaries. `test_callback_trust.py` establishes trust
transitions and task ownership. `test_async_client.py` establishes local
transport, cancellation and close. None currently protects an ASGI route.
Keep those tests and `verify_distribution.py`'s core wheel/sdist checks.

Use a small async ASGI harness with explicit HTTP/lifespan scopes, queued
receive messages and collected responses so duplicate raw headers, malformed
raw targets and body receipt are observable. No HTTP test client/server
dependency is needed. Callers can use real FastAPI router, session-style and
CSRF policy, CORS and mounts. Clock seams already used by the trust tests
are sufficient. Tests should fail on bounded gates, never sleep through the
production polling interval. Use temporary directories and loopback only.

Windows CPython 3.13 and WSL Linux CPython 3.12 are available. The final
runtime/platform matrix and maintained application adoption belong to PR 10.6.
PyPI resolution for the web extra is setup, not an external runtime call.
No production files, provider requests, remote publication or shared keys.

## Tests to Add or Update

### 1. `test_lifespan_resources_and_fastapi_overrides`

- Type FastAPI/lifespan integration in `sdks/python/tests/test_fastapi.py`.
- Proves validation-only construction, app-owned instances reused by requests,
  independent owner app state, startup and shutdown ordering with an existing
  lifespan, and generic failure before/after initialization. Exercise the real
  lifespan protocol so a startup exception becomes startup failure. Check
  ordinary overrides for all three dependencies and still challenge an
  unauthenticated callback with a principal override active.
- Validate wrong signing/issuance types, invalid client options, explicit
  blank audience and invalid overlap path, and representative valid/invalid
  Java-compatible prefixes. Use file/key/network/refresh tripwires for
  construction, then prove a real signer initializes at startup. Use a fake
  client that fails on entry only for the partial-failure test, observe the
  already-open verifier close, and retain the original failure. Cover bad
  provided signer, bad initial overlap, failure in a composed app lifespan
  after resources are published, and duplicate/concurrent entry for one owner.
- Assert no ready bundle remains on failure/exit, a new callback fails
  closed, captured closed resources cannot do new work, and existing public
  signing output, once successfully published, stays on disk. Reuse the core
  issuer/verifier in all normal test paths. Use synthetic credentials and check
  redacted responses/logs.

### 2. `test_callback_boundary_credentials_methods_paths_and_body`

- Type parameterized raw ASGI integration in `sdks/python/tests/test_fastapi.py`.
- Exercise the exact prefix, trailing slash, descendants including a route
  without the principal dependency, sibling paths, and a normalized custom
  prefix. Exercise duplicate mixed-case Authorization names, comma-merged
  and malformed bearer values, cookies/session alone, literal and encoded
  query names, malformed percent syntax in names and harmless query values.
  Require a bearer challenge with no redirect, body access or route call.
- For a verified credential, GET and POST reach the handler. HEAD, OPTIONS,
  PUT, PATCH, DELETE and TRACE are 403 when the SDK receives them and 401
  without authentication. Protected WebSocket scopes cannot reach an upgrade
  route. Exercise malformed aliases of exact prefix and descendants with
  slash duplication, encoded separators/dots, semicolon, backslash,
  traversal both into and out of the boundary, nested escapes and absent
  `raw_path` where the decoded form carries the ambiguity. Assert 400 when
  the guard sees an ambiguous protected form and that ordinary paths and
  similarly named sibling routes still dispatch.
- With authentication, record the untouched ASGI body frames and business
  headers through a normal FastAPI handler. Cover empty and nonempty POST,
  form fields named `access_token` as ordinary data with a valid bearer,
  and a multi-frame JSON or binary payload. A body sentinel must fail any
  middleware receive before the allowed handler takes control.

### 3. `test_callback_mount_root_and_browser_middleware`

- Type routing and middleware integration in `sdks/python/tests/test_fastapi.py`.
- Test the root owner protecting a mounted child's callback path with the
  mount segment in its configured prefix. The ordinary child router can read
  the already verified principal after the scope app changes. Separately
  enter a mounted child's own integration from the parent lifespan and prove
  it fails closed when this entry is omitted.
- Exercise deployment-root-prefixed and local-path ASGI shapes and real mount
  routing using an inherited root. Include root string appearing only as a
  partial segment, malformed aliases crossing a mount/root boundary, and
  unrelated sibling routes. Use explicit raw and decoded scopes.
- Register real CORS and a browser login/CSRF test layer inside the guard.
  Assert callback preflights receive the required 401/403, callback requests
  do not redirect to login, browser routes retain redirects, session
  behavior and unsafe-method CSRF denial, and ordinary browser preflights
  still get application CORS behavior. Verify owner startup fails before
  export if the local registration is omitted or placed inside a layer that
  can answer independently.

### 4. `test_callback_principal_isolation_and_trust_changes`

- Type async boundary and trust integration in `sdks/python/tests/test_fastapi.py`.
- Use two simultaneous requests with distinct issued identities and exact
  authorities. Exercise success, business 403 for role/record mismatch,
  application exception and native cancellation. Inspect each scope after
  exit to verify the principal is gone and original exceptions/cancellation
  are preserved. Prove a callback requiring a principal fails closed without
  a verified binding and unrelated browser requests cannot read a prior one.
- Hold a callback after admission, invalidate its overlap file, await the
  actual refresh's observable trust transition and assert new requests fail.
  Complete the held request with its original issuer, subject and authorities,
  then restore valid trust and assert fresh requests recover. Use the existing
  clock test seam to move beyond token expiry plus skew while another callback
  is held and assert the same new-versus-admitted split. Keep Sidecar's strict
  pre-forward expiry distinct in assertions and product docs. Use temporary
  files, real signed JWTs and bounded AnyIO gates.

### 5. `verify_distribution` and installed app smoke

- Type installed package integration in `sdks/python/tests/verify_distribution.py`
  and `sdks/python/tests/verify_fastapi_example.py`.
- Split core and extra-marked requirement assertions. Preserve bare wheel and
  sdist install, core usage, no web packages and installed type checks.
  Build/install the extra without an ASGI server or CLI. Confirm the
  installed module and type declarations are from the fresh environment.
- Copy `sdks/python/examples/fastapi_app.py` and the smoke helper into an
  external temp directory, with no project/PYTHONPATH imports. Drive the
  documented app factory/config with both signing modes. Use `WirePeer`
  for real loopback submit and capture its issued bearer only in the fixture.
  Exercise the documented callback routes with that bearer, invalid/no
  bearer, and an application authority/record denial. Exercise the demo
  submission authentication and strict typing of the installed example.
- Compare the provided export's public key with its source identity and
  an independent provided process's export location where practical. Assert
  colocated identity changes across restarts and file contents stay public.
  Prove the example, OpenAPI and expected error output do not reveal synthetic
  password, execution bearer or private key. No new runtime server dependency.

## Exit Criteria

- [x] First FastAPI behavior test fails for the missing SDK integration before
  implementation and passes afterward.
- [x] The focused and safe related SDK suites pass. Record actual environment
  and existing platform-specific skips.
- [x] Every acceptance criterion maps to executable evidence and current
  documentation, including the installed app in both signing modes.
- [x] Strict typing and installed isolation checks pass. Core remains usable
  without the extra. The web extra adds no server or CLI.
- [x] Trust, expiry, body and identity cleanup tests are bounded, use only
  synthetic data, and leave operational files alone.
- [ ] Middleware ordering, root paths, and observed ASGI upstream limitations
  agree with the executable coverage. A fresh independent review returns clean.
