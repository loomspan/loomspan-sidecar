# Publication History and Outcome Inspection Testing Plan

## Change Summary

Add protected history and recovery pages to the embedded console, render retained snapshot metadata and exact detail safely, and explain recorded status, runtime/intended state, expiration, and mutation restrictions from the existing inspection APIs. The change leaves publication, storage, retention, authorization, private-draft ownership, and framework contracts intact.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Outcome semantics | Pending is shown as success/failure, or a historical failure stage is invented. | Playwright assertions for active pending, retained failed, matching published, and runtime/intended mismatch wording using only current API fields. |
| Snapshot consistency | UI pairs one UUID with another snapshot's content during publication/pruning. | Exact detail request/response UUID assertion, real ordered API coverage, and deterministic prune/404 browser recovery. |
| Sensitive rendering | Authored HTML-like YAML executes or disappears; literals/placeholders are redacted. | Browser fixture containing markup, a script side effect, a literal secret-shaped value, and `${PLACEHOLDER}`; assert text is exact and script side effect is absent. |
| Authorization/privacy | A role loses intended history access, anonymous/JWT gains it, or another session's private draft appears. | Authenticated viewer/editor/admin page/API cases, anonymous redirect/401 and existing JWT denial, plus two-session draft/history comparison. |
| Session/lease behavior | Inspection polling or page load renews login/edit ownership. | Browser request instrumentation and controllable-clock HTTP coverage showing only deliberate activity reports renew a session; history uses no background polling. |
| Fault recovery | UI understates mutation restrictions, implies online repair, or links nowhere useful. | Browser and shell tests assert precise restrictions, protected recovery link/page, and absence of repair/rollback/import/cancel controls. |
| Accessibility | Status is color-only or detail cannot be selected/recovered by keyboard. | Playwright keyboard activation/focus assertions, visible textual labels, ARIA live status, and native control checks. |
| Regression boundary | UI work changes server contracts or imports unsupported framework internals. | Existing configuration HTTP/runtime/store suites, `SupportedLoomspanApiArchitectureTest`, and full Maven verification. |

## Existing Coverage and Environment Constraints

`ManagementConfigurationHttpIntegrationTest` already proves complete current/history payloads, viewer access, no-store, explicit `history_not_found`, admitted publication after disconnect, pending bookkeeping faults, failed submissions, and runtime/intended mismatch. `ConfigurationSnapshotStoreTest` and `RuntimeConfigurationIntegrationTest` cover authoritative order, retention, serialization, protected overflow, pruning, and fault truth. `ManagementEditorBrowserIntegrationTest` covers real authenticated Playwright rendering, private drafts, disconnect/no retry, immediate outcome wording, and meaningful-activity cadence. `ManagementHttpIntegrationTest` covers protected page shells, headers, roles, CSRF separation, and idle expiry.

No browser test covers a history page today. Tests run a real random-port Spring Boot application, local temporary SQLite database, locally seeded accounts, and headless Chromium through Playwright 1.55.0. They need the Playwright Chromium runtime and the developer-installed `ai.loomspan:loomspan-spring-boot-starter:1.0.0-beta.5-SNAPSHOT`, but no external credentials, service, network target, or framework rebuild. Test fixtures must use sanitized fake secrets only.

## Tests to Add or Update

### 1. `viewerBrowsesOrderedHistoryAndExactSnapshotDetail`
- Type: Real authenticated Playwright integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: Viewer navigation, authoritative list order, durable local/source identity, runtime marker, complete exact detail, sensitive literal/placeholder preservation, text-only markup rendering, native keyboard selection, and textual status.
- Inputs/fixture: Multiple retained snapshots with unique sequence/UUID/source UUID and sanitized authored skill/REST strings including `<script>window.__historyInjected=1</script>`, `${HISTORY_TARGET}`, and `fixture-secret-value`.
- Doubles or boundary isolation: Real application/API/database; local seeded account and local framework fixture only.
- Edge cases: Nullable source UUID displays as none; empty skill list; markup is visible but `window.__historyInjected` remains unset; detail UUID equals selected UUID.

### 2. `allManagementRolesReachHistoryButUnauthenticatedAndJwtCallersCannot`
- Type: Parameterized authenticated Playwright workflow plus HTTP security integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`, `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`, and `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Viewer/editor/admin can open history/recovery and GET list/detail; shared navigation includes history; anonymous page access redirects, anonymous/JWT API access fails, account administration stays admin-only, and responses stay no-store/no-referrer.
- Inputs/fixture: One seeded account per role and a known retained UUID.
- Doubles or boundary isolation: Real Spring Security chains and loopback HTTP clients.
- Edge cases: Execution JWT does not authenticate management; shells contain no authored values before API load.

### 3. `recordedStatusesAndCurrentStateUseTruthfulText`
- Type: Real authenticated Playwright integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: `PENDING` always says outcome unknown, `FAILED` remains inspectable and recorded failed, `PUBLISHED` is recorded bookkeeping, current runtime is independent from intended restart selection, and a running pending snapshot is not silently relabeled.
- Inputs/fixture: Real service/store fault fixtures for active pending after outcome-recording failure, retained failed after reverted activation, and published matching state.
- Doubles or boundary isolation: Use existing `RuntimeConfigurationService.Hooks`/publication fixture patterns and reset hooks; do not infer or create a durable operation record.
- Edge cases: Runtime UUID equals intended UUID with pending status; runtime UUID differs from pending intended UUID; older pending entry is neither marked current nor declared failed/succeeded.

### 4. `mutationFaultExplainsRestrictionsAndOfflineRecovery`
- Type: Authenticated Playwright plus protected-page HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java` and `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java`
- Proves: Fault text remains visible; acquisition/save/activity renewal/validation/publication are described as blocked; inspection, release/discard, and account administration are described as available; recovery link opens a protected read-only page consistent with the README.
- Inputs/fixture: Matching active-pending bookkeeping fault and mismatched runtime/intended revert fault.
- Doubles or boundary isolation: Real fault hooks where stable; a routed current response is acceptable only for a narrowly isolated visual branch already proved at HTTP/runtime level.
- Edge cases: Recovery page has no mutation form, live SQL, retry, rollback, import/export, or cancel control; mismatch guidance says restart follows intended state and recovering the old runtime needs a known-good stopped backup.

### 5. `expiredSelectedSnapshotClearsDetailAndOffersFreshState`
- Type: Authenticated Playwright integration with deterministic network boundary
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: A row pruned between list and detail never leaves or displays stale/mixed content; `history_not_found` is announced; the retained list/current state refreshes; current configuration remains reachable.
- Inputs/fixture: Real initial list/current responses and a one-shot Playwright route fulfillment returning the controller's 404 `history_not_found` shape for the selected UUID, or a deterministic real pruning hook if implementation makes it stable.
- Doubles or boundary isolation: Isolate only the timing-dependent detail response; separately retain real store/runtime pruning tests as authoritative server evidence.
- Edge cases: Prior detail container is cleared before the error; refreshed list no longer offers the expired UUID; no history pinning or invented outcome.

### 6. `reloginInspectsAcceptedPublicationWithoutRecoveringPrivateDraft`
- Type: Real authenticated Playwright integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: After logout/disconnect and a new login, the user reaches current/history, sees accepted runtime/history evidence, and is not prompted to restore, retry, or cancel a lost session-private draft.
- Inputs/fixture: Accepted publication with connection result hidden/aborted using the existing editor-browser pattern, followed by a fresh authenticated browser context.
- Doubles or boundary isolation: Abort only the original browser response; let the real accepted server operation finish and inspect it through real current/history endpoints.
- Edge cases: Exactly one publish request; no browser storage draft; inspection contains no publish/cancel action.

### 7. `otherSessionsPrivateDraftNeverAppearsInHistory`
- Type: Real multi-context Playwright integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`

- Inputs/fixture: Editor session with unique private marker, separate viewer/admin contexts, then an explicitly submitted sanitized snapshot for the positive case.
- Doubles or boundary isolation: Real session-derived draft and configuration APIs.
- Edge cases: Admin does not gain draft visibility; history remains unchanged until submission.

### 8. `backgroundHistoryInspectionDoesNotKeepIdleSessionAlive`
- Type: HTTP session-clock integration plus Playwright request/activity assertion
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHttpIntegrationTest.java` and `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: Current/list/detail reads and an open history page do not call the activity endpoint or advance the idle deadline; expiry causes the next read to redirect to login, while deliberate keyboard/click activity retains the established throttled behavior.
- Inputs/fixture: Controllable 30-minute clock HTTP context and Playwright fetch instrumentation.
- Doubles or boundary isolation: Local mutable clock; no wall-clock 30-minute wait.
- Edge cases: Initial load and any automatic inspection remain passive; clicking Refresh is a deliberate user event and may report activity at the established cadence, but the GET itself and an untouched open page may not.
