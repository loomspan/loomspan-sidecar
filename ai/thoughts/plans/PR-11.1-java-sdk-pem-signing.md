## Current State

`sdks/java/core/src/main/java/ai/loomspan/sdk/SigningSettings.java` exposes seven
provided options. `SigningKeys` branches between PEM and keystores, handles signing
certificates, and publishes with a useful deterministic `FileOperations` seam.
`SecretReference` is used only by this obsolete signing path. PEM currently uses
prefix/suffix matching and permissive MIME decoding. Spring `SigningProperties`
exposes these options; `ExecutionTokenAutoConfiguration` rejects only literal
passwords. The root Sidecar reads public RSA JWKS, never these private files.

`SigningKeysTest` and its `SigningTestMaterial` helper mix required export/key
behavior with removed keytool/certificate/password cases. Issuance and callback
tests already exercise RS256 and exact roles. The sibling maintained suite's
`RotationProbe`, `remote.py` and `remote_material.py` consume signing certificates,
but the private files are already PKCS#8. Its Local, Standard and Hardened SDK
lanes run actual SDK consumers, Sidecar and authenticated callbacks offline.

## Desired End State

Core provided settings contain just `keyLocation` and `jwksExport`; explicit modes
and mixed-mode rejection remain. Provided input contains exactly one valid
unencrypted `PRIVATE KEY` block, RSA >=2048 bits, with ordinary surrounding
whitespace and line endings. Invalid input never generates a substitute signer
or replaces an existing export. Colocated startup generates a new in-memory RSA
key and writes only `jwks.json` into an existing directory.

Both modes export precisely public RSA signing fields (`kty,n,e,kid,use,alg`),
retain RFC 7638 identity and sign the existing token profile. Export publication
requires atomic replacement; private-input collisions fail before any write.
Spring rejects every removed signing property with fixed actionable text that
names the setting but never its value. TLS/mTLS and SSL bundles retain their
certificate/keystore facilities. Actual maintained consumers prove the protocol.

## Impact and Risk Analysis

The supported Provided constructor changes intentionally; update all verified
consumers directly. Removing the last SecretReference/signing fixture consumers
permits deletion; re-search before removing dependencies or helpers. Root BC test
dependencies and SDK keytool/PKCS12 usage supporting TLS are retained.

Permissive PEM decoding can admit bundles or junk. Validate the whole envelope,
strict Base64 content, complete ASN.1 framing and runtime RSA key parsing. JCA
can ignore optional PKCS#8 fields, so validate their structure separately.
Equivalent existing file paths require `Files.isSameFile`, including a hard-link
test that works on Windows without symlink privilege. Atomic move failure must
preserve the prior export and clean temporary public files.

Generic Spring unknown-property binding errors can expose supplied values. Use a
small explicit obsolete-name guard before signer initialization, with Spring's
configuration-property source/name APIs for relaxed names and environment sources;
do not retain deprecated setters or turn rejected options into supported APIs.
Errors must not attach raw provider/parser exceptions.

## Implementation Approach

Keep the existing signing and transport owners. Simplify
`SigningSettings.Provided` to two paths and remove format, alias, password and
certificate branches from `SigningKeys`. A private PEM loader checks exactly
one full envelope, requires the footer on its own line and complete Base64
quanta, and decodes through the JDK Base64 decoder. Use Bouncy Castle 1.86 ASN.1
types for whole-input framing and to validate optional PKCS#8 fields. JCA
can skip malformed attributes, the optional public field and invalid
`rsaEncryption` parameters. Reject present non-NULL parameters for that
identifier and validate any supplied public field against the signer. Derive
JWKS from the signer.
The dependency keeps valid input usable and avoids a custom ASN.1 parser. JCA `KeyFactory`
owns RSA key decoding and JCA `Signature` owns signing. Require usable RSA CRT
material for public derivation, minimum modulus strength and the existing
sign/verify proof. Zero the decoded private byte array in `finally`.

Retain `LocalSource`, direct RSA `n/e` public derivation, Nimbus thumbprint and
atomic `publish`/`FileOperations`. Remove the certificate clock/logger plumbing;
the package-private test initializer needs only settings and file operations.
Simplify collision validation to the private key path, normalized equality plus
same-file checks, failing safely if equivalence cannot be checked.

Spring exposes only mode, colocated directory and the two provided paths. Guard
all seven obsolete names: `format`, `key-alias`, `keystore-password-reference`,
`key-password-reference`, `certificate-location`, `keystore-password`, `key-password`.
Reject their presence even with empty values or in colocated mode. Use fixed text
directing operators to unencrypted PKCS#8 and the two required provided paths.

Create one explicitly synthetic, fixed >=2048-bit PEM key with expected public
JWKS/kid under the core test resources, plus a short fixture contract. These are
language-neutral files reusable by future SDKs, never production credentials.
Use JCA-generated temporary weak/non-RSA material and mutations for negative cases.
Use existing maintained end-to-end lanes for real SDK/Sidecar interoperability;
avoid coupling the independently built root and SDK reactors through new test
dependencies solely to duplicate an existing integration boundary.

## Risks and Rollback/Recovery

No reset, private-key conversion or deployed-data modification is needed. A failed
initialization leaves private input and prior public export unchanged; operators
fix material/paths/permissions/atomic-filesystem support and restart. Reverting
source changes is possible without data migration. Existing tokens can cease to
validate after colocated restart as before; do not add coordination machinery.

If environment/tool failures prevent a required lane, report the exact failure
and keep that acceptance evidence pending; do not claim completion. The ticket
allows temporary failures specifically caused by PR 11.2/11.3 boundaries, which
must name the cause/resolving ticket and remain pending until the series checks
pass. It does not waive signing interoperability or authorize unrelated breakage.
