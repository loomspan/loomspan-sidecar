# Automatic Draft Editing and Publication Testing Plan

## Change Summary

The browser gains complete YAML authoring, serialized automatic draft saves, delayed validation, lease/session activity handling and exact-candidate Publish. Existing server APIs continue to own admission, validation and activation; the small session response addition exposes configured inactivity durations.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Browser draft state | A late PUT/validation response marks newer text saved/valid or replaces it | Delayed/reordered response browser tests with exact textarea and button assertions |
| Candidate admission | Publish sends an old saved/validated candidate while a newer save is queued | Browser eligibility test plus existing 409/candidate HTTP integration |
| Privacy and ownership | Same-session second tab edits with the first tab's lease; another user sees private draft | Real two-tab/two-user browser flows and existing private-draft HTTP test |
| Activity deadlines | Background requests or mouse movement extend login/lease; warning assumes defaults | Event/cadence browser test and mutable-clock HTTP regression |
| Lifecycle | Release/expiry preserves valid text, but changed base/logout/discard must clear it | Browser lifecycle scenarios and server HTTP checks |
| Publication result | Disconnect treated as failure or retried; activation/bookkeeping fault misreported | Intercepted disconnect, phase failures and current-state browser assertions |
| Safety/accessibility | Authored markup executes or validation steals focus; controls unusable by keyboard | Markup-like source/YAML case, collapsed details and keyboard workflow |
| Execution boundary | Draft mutation changes live catalog; publication damages security/shutdown behavior | Runtime/catalog HTTP integration, security and shutdown suites |

## Existing Coverage and Environment Constraints

`ManagementEditingHttpIntegrationTest`, `ManagementEditingServiceTest`, `ManagementConfigurationHttpIntegrationTest` and `RuntimeConfigurationIntegrationTest` already cover server-private drafts, candidate rotation, late server validation, admission and publication phases. `ConsoleSecurityIntegrationTest` and `SupportedLoomspanApiArchitectureTest` cover protected boundaries. The repository uses Maven/JUnit 5 and has no browser harness. Add test-scoped Playwright Java to run Chromium against `@SpringBootTest(webEnvironment=RANDOM_PORT)` with fixture accounts and local SQLite, reusing the management HTTP fixture pattern. The test environment needs a Playwright-compatible Chromium installation; no real remote REST target, mail service or production credentials are involved. Use the locally installed beta 5 framework snapshot, not a framework rebuild.

### 2. `lateSaveAndValidationCannotCertifyNewerText`
- Type: browser integration with deterministic route interception
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementEditorBrowserIntegrationTest.java`

### 3. `saveFailureKeepsLocalTextUntilExplicitRetryOrNewEdit`

### 4. `ownershipAndDraftLifecycleAcrossUsersAndTabs`
