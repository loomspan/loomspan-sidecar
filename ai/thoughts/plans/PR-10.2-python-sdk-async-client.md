## Current State

`sdks/python/src/loomspan_sdk/_client.py` defines `SidecarClient` and owns constructor validation, URL assembly, explicit credentials and the polling loop. `_protocol.py` owns JSON, request input and origin validation, result models and `decode_response`. `_sync_transport.py` owns h11 HTTP framing and TCP/TLS, reads one bounded response on one connection, and records the final status before reading its body. `_models.py` and `_errors.py` already express the whole client contract. `sdks/python/tests/wire_fixture.py` provides a raw loopback HTTP peer and TLS fixtures use synthetic certificates. `tests/verify_distribution.py` builds and installs both distributions into external environments.

## Desired End State

`from loomspan_sdk import AsyncSidecarClient` exposes typed `list_skills`, `get_skill`, `submit`, `get_execution` and `wait_for_completion` coroutines. It takes the same constructor keywords and defaults as `SidecarClient`, shares the existing model and error types, supports `async with` and exposes `aclose`. Direct use followed by explicit `aclose` is also supported. One client can serve concurrent tasks within one async application runtime. Each exchange owns its connection until cleanup. Polling stops when its awaited call ends. An accepted ID already held by the caller works for a later explicit status request.

## Scope

### In scope

- Async core client, shared private HTTP/configuration policy, bounded native async I/O and lifespan shutdown.
- Direct runtime dependency metadata, current-behavior documentation, an installed async example and focused local verification.

### Out of scope

## Active Project Guardrails

- Sidecar development replaces superseded code directly. Keep one set of protocol rules, with separate sync and async I/O. No compatibility shims, schema changes or development-data reset. Apply the [design lens](../design-lens.md#simplicity-and-technical-debt).
- Keep trust configuration operator-owned. Verify TLS and release local connections without treating local shutdown as a complete remote HTTP response or as cancellation of Sidecar work. Preserve diagnostics and opaque per-call credentials.
- Keep product docs focused on available behavior. Keep work tracking and test receipts in the internal artifacts. Leave Framework boundaries and existing data untouched.

## Impact and Risk Analysis

- Cancellation can arrive while resolving, connecting, handshaking, uploading, receiving or sleeping. Both pending connections and active streams need a local owner. Repeated close calls must wait for the same cleanup without waiting on unrelated caller tasks or draining a peer body.
- A response can disclose a final status without a usable body. Preserve that distinction across timeout, oversize, broken framing and TLS errors. Local close and TLS truncation cannot establish a 202 body. Transport exceptions can contain untrusted peer text, so classify outside those exception handlers using the existing SDK policy.
- Libraries can hide retries, cookies, decompression and unverified TLS EOF behavior. Keep HTTP policy explicit and reuse h11. Shared framing must preserve existing sync behavior, including interruption and close races.
- Windows and Linux tests will verify native asyncio cancellation and installed artifacts. Dependency metadata and the bounded probes justify the selected approach. The rest of the release matrix remains governed by PR 10.6.

## Implementation Approach

### Share policy and keep distinct I/O owners

Use AnyIO public byte streams alongside h11, adding a direct `anyio>=4.16,<5` requirement. Version 4.16.0 fixes cleanup when cancellation strikes a selected TCP stream during connection racing. Its strict `TLSStream` differentiates a TLS alert from raw EOF and its asyncio raw stream aborts without waiting on the peer. The research records package and loopback evidence. Standard asyncio's TLS streams did not distinguish the two EOFs in the probe. HTTPX's default transport uses non-strict EOF handling and the client captures cookies. aiohttp's relevant retry flag is private. The selected composition needs one existing HTTP parser and no transport plugins or new wire parser.

Use a private shared constructor-options helper and constants for origin, limits and SSL context validation. Preserve the existing public constructor signatures and 2 s / 10 s / 8 MiB defaults. Keep `WaitOptions` as the only wait settings type with its existing 60 s / 250 ms defaults. Shared path helpers and validation should cover credential type, execution ID and wait options. Keep `parse_*`, `encode_input` and `decode_response` as the only payload and error policies. The sync and async clients may each keep their small operation and polling adapters for their native call style.

Move h11 request construction and response framing into one private sans-I/O helper. Each attempt gets a fresh h11 client. Use the existing explicit headers and paths. Encode send parts in bounded chunks of at most 64 KiB, and feed received chunks of at most 8192 bytes. The helper records the first final status before evaluating the body and checks both advertised length and streamed bytes. Preserve `None` for an incomplete/unusable body and `b""` for a complete empty body. Informational responses leave the final status unset. A connection-close-delimited response completes only on valid remote EOF. Keep sync's current socket ownership, TLS validation and deadline/close checks when wiring it to the helper.

### Async exchange, deadline and close ownership

Use `anyio.connect_tcp` for DNS/TCP and strict `anyio.streams.tls.TLSStream.wrap` for TLS. Once TCP returns, hold the raw stream in the exchange owner before entering any further await. Check ALPN via the public TLS attribute and accept only absent ALPN or `http/1.1`. Pass the parsed host as the connection target and strip a scoped IPv6 zone only for TLS verification. Revalidate the SSL context immediately before wrapping. Supplied contexts validate at construction. For the default HTTPS context, lazily cache the verified context behind a per-client async lock and load standard system trust off the event loop with `anyio.to_thread.run_sync(..., abandon_on_cancel=True)`. Charge the first lookup and lock wait to the connect budget. A bounded caller await can end before the OS trust load or DNS resolution finishes. A late OS result holds no SDK socket and cannot dispatch HTTP. A system trust configuration failure is a sanitized local pre-dispatch error with status/wait context. Perform in-memory JSON conversion and parsing via the shared helpers.

Register each exchange before its first await in an owner-controlled cancel scope. Apply independent nested scopes for `min(now + connect_timeout, exchange_deadline)` and `min(now + response_timeout, wait_deadline)` when waiting. Derive scope delays from the remaining absolute monotonic budget so header/body progress cannot reset a deadline. Check remaining time before dispatch and while consuming ready h11 events, including the final event. This also bounds buffered fast paths when the runtime has not fired a timer yet. Use bounded asynchronous writes and reads with backpressure. Record an observed final status before a deadline check can discard the body. Map only normal transport/TLS/framing/budget errors to `_Response` and let `decode_response` classify them. End-of-stream is distinct from a broken stream. Native task cancellation and outer application timeouts propagate after cleanup. SDK wait timeout is decided by the shared decoder and wait loop. A recorded non-2xx status wins over timeout fallback for an incomplete response. A response deadline before the wait deadline preserves the HTTP or protocol failure category. An expired wait without a final HTTP error raises `WaitTerminated` with the last valid snapshot.

In `finally`, force-close the raw stream through public AnyIO facilities without calling graceful TLS shutdown or draining. Do not mask cancellation with cleanup errors. When closing, mark the client closed before awaiting, wake polling sleeps, cancel the active exchange scopes and wait for the registered owners to release their resources. Use a close event to end polling sleep and an event or completion signals to join exchange cleanup. Keep lifecycle state on one runtime. Each exchange and interruptible sleep runs in a child that the caller joins through an AnyIO task group. This keeps SDK close and deadline cancellation off the caller task, where asyncio could combine it with simultaneous native cancellation and replace the caller's message. The polling loop stays in the caller and issues requests only while awaited. If `aclose` is itself externally cancelled, owners are already signaled and still release their resources. Only SDK-owned scope cancellation is consumed. On SDK close, reject work known to be closed before dispatch with `LocalFailure` and context. Once HTTP sending starts, use the observed status or missing-response classification, including `AcceptanceUnknown` for unresolved submissions. Ordinary transport failure keeps the sync classification even if a socket never finishes connecting. Check closure before treating EOF as successful framing. Closed wait sleepers surface `LocalFailure` with the last valid snapshot. An explicitly awaited polling sleep is capped by remaining wait time and takes no further wire action after close or cancellation.

## Step 4 Implementation Handoff

`AsyncSidecarClient` uses the same model, validation, framing and response decoder
as the synchronous client. The transports retain their own lifecycle and timing
mechanisms. A shutdown scope owns each active exchange, and separate timers bound
connect and exchange work. Default TLS trust initializes lazily in a worker and
its successful result is cached per client. The transport closes the owned raw
stream directly, including when handshake or TLS body I/O is interrupted. TLS
handshake cancellation can carry the SSL stack's implicit Python exception
context. The SDK preserves that native cancellation object and adds no state.

The async client's trust worker holds a separate nonblocking lock for the
physical load. If its caller times out or is cancelled, the worker can finish
and cache the verified context. Until then, a new exchange that reaches the
loader fails before dispatch using the ordinary connection-failure category.
This bounds overlapping OS trust loads to one per client without extending any
caller deadline or tying the client to a particular async backend.
