## Current State

`apps/python/infrastructure/security.py::identity` verifies Keycloak JWTs. `execution_identity.py` adds a second signing/validation implementation and `sidecar_client.py` opens HTTPX per call. `apps/python/app.py` mounts the same equipment callback router twice. The nine executor declarations and authoring generator all target `/skills/<name>`. The maintained runner uses public routes and the callback declarations; no current caller of the prefixed callback duplicate was found. The eight lookups and approval callback have JSON bodies. Bodyless callbacks belong to the installed SDK reference proof and should not acquire an equipment operation or declaration.

`ExecutionController.execute/execution` and the suite's common adapter expose admission ID, exact result text, structured failure and available diagnostics. `equipment_service/workflow.py::complete` adds assessment evidence after one status read. `typesafe_ai/api.py` uses the same adapter and adds an application decision view. Suite business code persists request ownership as `iss|sub`; a change in JWKS kid must not relabel owners.

`Loomspan` already owns lifespan resources, prefix guarding and dependency injection. `ProvidedSigning` preserves an existing PKCS#8 PEM and atomically exports a derived-kid JWKS. The existing file binds would pin the old public inode. `CurrentFileJwtTrust` accepts a missing startup file as waiting, rescans periodically and reloads on an unknown kid. The lock and Python image currently cannot consume the `fastapi` extra, and portable packaging carries two JARs with no wheel.

## Desired End State

The app authenticates public requests with Keycloak, issues SDK execution credentials for verified subjects and exact allowed roles, uses one lifespan-owned async client, and authenticates callbacks under one `/skills` prefix. The same operation bodies, names, business authorization, public result/failure behavior, issuer/subject ownership and frozen accepted cases are retained. Execution expiry is independent of the Keycloak credential after successful public authentication and uses a configurable default of 900 seconds. Plain maintained execution and bounded installed reference compositions provide complementary evidence. The complete native matrix and fresh review determine sync readiness separately from publication.

## Active Project Guardrails

- Maintain exact roles and verified issuer/subject outside business input. Retain application authorization, current trust and unchanged Sidecar bearer passthrough. Transport peer trust remains independent of JWT trust.
- The Framework owns authorization, skill execution and lifetime. Use the existing supported `@SkillExecutor` boundary and only `ai.loomspan.api` Java types. Use the installed beta.9 snapshot and matching local docs. Keep ArchUnit in the final Sidecar verification.
- Reuse existing fixture, build and deployment mechanics. Product docs describe current behavior and actually tested platforms. Record adoption changes, run results and gaps under `ai/thoughts/`.

## Impact and Risk Analysis

- Key identity and continuity. Keep `.runtime/execution-key.pem` at its existing host location. The same RSA public numbers produce a new SDK-derived kid. Current-file trust must observe the replacement entry. Old in-flight literal-kid credentials expire or fail verification after switching trust. Use an ordinary stopped/restarted workspace for replacement and retain private key and databases. No dual-kid publishing or reset is planned.
- Adapter fidelity. SDK typed results and safe errors replace arbitrary raw replies. Preserve the existing supported success shape and genuine Sidecar problem responses. Dispatch uncertainty is an explicit outcome without automatic resubmission. Test decimal-bearing diagnostic details and actual wire timestamp/null/omission shapes. Application-added assessment/impact fields stay at their existing boundary.
- Isolation. Shared Docker state and the retained suite runtime require uniquely named, fresh projects and isolated ports/volumes. Synthetic trust and TLS mutations must affect only their own fixtures.
- Platform risk. Linux 3.13–3.15 package and tooling viability is unproven. Native macOS ARM64 access is presently unidentified. Neither cache resolution nor another OS proves support. Record install/run failures and dependency constraints with the exact environment.

## Implementation Approach

Use the SDK's public FastAPI integration directly. Keep a small suite-local response projection at the existing HTTP boundary and use existing authorization routines. Preserve the canonical deployed `/skills` callback paths and remove the unused second mount; public named and generic execution routes continue to serve their existing roles. Keep the Python-issued trust export distinct from external callback overlap. For composed negative/fault proof reuse the Java lane's low-level material and test peers where their interfaces fit, with a small installed Python reference consumer. Keep fault settings and test-only GET/bodyless declarations out of the business app. Execute maintained app business parity in the ordinary isolated provider-free stack.

## Phase 1 — Adopt the installed SDK in the application

### Changes

- [x] `apps/python/infrastructure/security.py::identity` retains Keycloak signature, issuer, audience and time verification. Return verified claims without carrying the raw Authorization header into business code. Validate a usable string subject and roles list and pass exact nonblank role names into `AuthenticatedIdentity`. Preserve existing acceptance of empty/unknown roles as no allowed authority; use `IssuanceSettings` to intersect the two equipment authorities, without normalization or relying on request body roles.
- [x] `apps/python/app.py` and `apps/python/infrastructure/sidecar_client.py` configure one `Loomspan` with `ProvidedSigning`, issuer `equipment-app`, audience `equipment-service` for Sidecar and callback acceptance, and default 900-second configurable lifetime (`EXECUTION_LIFETIME_SECONDS`, positive integer converted to SDK nanoseconds). Retain the existing 30-second exchange policy where the SDK exposes timeouts. Compose existing DB startup with the SDK lifespan and install `CallbackMiddleware` last. Bind client/issuer to the request with the public SDK dependencies. Each submit or poll issues a fresh credential from verified claims, with no Keycloak expiry forwarded and no background polling/retry.
- [x] `apps/python/infrastructure/sidecar_client.py::submit/poll` call `AsyncSidecarClient.submit/get_execution`. Return 202 `id` and 200 public snapshot fields (`id`, `skillName`, `status`, `createdAt`, `completedAt`, `result`, `failure`, `configurationSnapshotId`, and conditional `events`). Preserve exact result text, issue fields and event details. Include `failure: null` when absent and `issues` only when nonempty, distinguish missing events from empty, and follow actual `SkillExecutionEvent` wire fields. Use a JSON encoder that preserves supported Decimal detail numbers if needed and declare it directly. Keep `HttpFailure.status_code` and available sanitized `.problem`. For missing problem bodies use a fixed safe description. Report malformed UUID or local request validation as 400, unusable upstream reads as 502 and `AcceptanceUnknown` as an explicit 502 outcome with a stable `ACCEPTANCE_UNKNOWN` marker and no replay. Never echo credentials or exception internals.
- [x] `apps/python/app.py`, `apps/python/suites/equipment_service/{api,workflow,skill_routes}.py`, and `apps/python/suites/typesafe_ai/api.py` update callers and retain assessment completion and impact behavior. Use `Loomspan.principal` for `deterministic`, projecting verified principal claims to the existing business helper shape (`iss`, `sub`, `roles`). Preserve recovery with the same `equipment-app` issuer and verified subject. Delete `apps/python/infrastructure/execution_identity.py` and the duplicate named callback mount. Keep the existing nine executor YAML paths and authoring output, roles, envelopes, names and business logic. HTTPX remains for unrelated fixture or tooling requests.

## Risks and Rollback/Recovery

If export or trust setup fails, repair the public directory or restart the owner with the same private PEM. Keep retained workspaces and databases in place. If disposable runtime verification fails, retain its sanitized result and tear down only that project's resources. A package/dependency or supported-API gap is investigated at its owning component; escalate a necessary behavior, dependency-contract or platform-target tradeoff with evidence. Use the approved full route and proceed through the available work if a native runner is missing. Publication and released dependency pinning stay separate.
