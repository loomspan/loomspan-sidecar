# Synchronous Python SDK Testing Plan

## Change Summary

Verify the standalone blocking Python client from local request parsing through
actual HTTP/TLS, waits, and installation of both distribution formats. Test the
existing Java-compatible contract using Python behavior and synthetic loopback
fixtures. The [implementation plan](PR-10.1-python-sdk-package-and-sync-client.md)
defines shared protocol ownership and transport lifecycle.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Package isolation | Build succeeds only from checkout or types/web absence are unverified | Build once, install wheel and sdist separately from external cwd, run example and installed consumer type check |
| Protocol fidelity | Lost fields, JSON coercion, silently truncated timestamps, failure mistakenly treated as exception | Model/envelope table, actual wire workflow with FAILED, optional history and nested details |
| Deadline and resource ownership | Stalled/trickling peer extends I/O or incomplete response drains | Peer-observed closure within deadline, exact overflow/body framing cases, active close and native interruption |
| Security and replay | Credential cross-talk, unverified TLS, redirects/rechallenge, serialized secrets | Concurrent requests, one-attempt counters, standard mTLS contexts and safe error assertions |
| Wait context | Fresh per-read budget, masked HTTP error or polling after failure | Scripted successful reads followed by budget/HTTP/protocol failures, matching requested UUID and previous snapshot |

## Existing Coverage and Environment Constraints

- Java `SidecarClientTest`, `SidecarClientEdgeTest`, `SidecarClientTlsTest`, and
  the public Sidecar integration tests are reference evidence only. There is no
  existing Python package or SDK suite. `sdks/java/tests/test_build_boundary.py`
  uses disposable artifacts, a pattern to reuse for the isolated Python checks.
- The repository's development constraints apply. Loopback hosts only, no Sidecar
  process or credentials, providers, publication, Git sync, or destructive data
  operations. Temporary fixture TLS material is generated with pinned `trustme`.
- Windows x86-64 CPython 3.13.13 and uv 0.11.7 are available. Python 3.13 is the
  selected native test interpreter. WSL Ubuntu x86-64 has system Python 3.8.2
  and requires a disposable supported interpreter for verification. Run one
  initial Linux x86-64 CPython 3.12 cell via WSL if its supported interpreter and
  normal dependency resolution are available. Attempt that setup during Step 4
  and record actual versions and outcomes. The Linux 3.13–3.15 cells, macOS ARM64
  and the full combined SDK stack are explicit follow-up coverage for PR 10.6.
  A missing platform is recorded as unrun, never a pass or a claim of support.
- Use the only currently tested h11 minor series for both minimum and current
  dependency environments, with h11 0.16.0 as the initial artifact proof.
  Verify the resolved version rather than assuming it from metadata.

## Tests to Add or Update

### 1. `test_protocol.py` — strict envelopes, request validation and copies

- Type is unit and public API contract. Location is
  `sdks/python/tests/test_protocol.py`.
- Table cases cover invalid URL schemes/authorities/ports, userinfo, empty and
  nonempty query/fragment, malformed escapes and controls. Preserve a valid
  percent-encoded base path. Reject prohibited names, preserve accepted Unicode
  UTF-8 path encoding and Java whitespace semantics. Reject zero, negative,
  boolean, NaN, infinity and unrepresentable limits. Validate POST input as an
  object, including nested invalid keys, nonfinite values, unsupported types and
  cycles. Assert no request on invalid local input in the wire fixture.
- Validate descriptor, acceptance, status, failure, issue and event envelopes
  with type and shape cases for every required field and representative invalid
  optional fields. Assert unknown additive fields are tolerated, case-insensitive
  canonical UUIDs are accepted, and status mismatches are rejected. Verify
  nanosecond timestamp fidelity, invalid date, representative extended and
  offset forms, terminal completion requirement and required FAILED failure.
- Exercise missing/null/present-empty history, optional configuration identity,
  failure issue defaults and multiple events. Assert exact null, empty, Unicode,
  non-JSON and malformed-JSON-looking result text. Mutate source and returned
  nested data to prove retained event/problem data has independent copies.
- Reject nested duplicates, trailing JSON, nonstandard constants, invalid UTF-8
  and wrong top-level types. A nested duplicate even in an additive field is still
  invalid JSON for SDK purposes.
- Credential tests exercise `str`/`repr`, JSON and pickle serialization attempts,
  all prohibited transport character categories and valid punctuation. Use a
  distinctive synthetic secret in response keys/strings, including in arrays.
  Assert HTTP problems redact it and SDK failures contain no credential or raw
  body in messages, normal traceback or `__cause__`/`__context__`.

### 2. `test_sync_client.py` — existing-credential wire workflow

- Type is loopback integration. Location is `sdks/python/tests/test_sync_client.py`.
- A threaded raw loopback server in `sdks/python/tests/conftest.py` or small test
  helper records method, path, headers, request bytes and ordered request count.
  Provide response scripts for deliberate stalls, invalid/truncated framing,
  chunked bodies, redirects and error headers. Register bounded peer cleanup and
  surface fixture failures. Use synchronization events for response start/close
  and bounded joins, with test-wide fixture guard timeouts.
- Drive `list_skills`, `get_skill`, `submit`, `get_execution` and
  `wait_for_completion`. Check descriptor returned under a short name, qualified
  status skill name, exact base prefix and encoded name, request JSON and all
  credential headers. Include QUEUED/RUNNING/FAILED and separately COMPLETED.
  Give a 202 a foreign Location and prove the SDK uses only its body UUID and
  local status path. A missing/invalid 202 ID, unexpected 2xx, incomplete body,
  extra JSON or post-dispatch disconnect yields `AcceptanceUnknown` with exactly
  one recorded POST. Reads require 200 and get the appropriate protocol error.
- Run simultaneous users on the same client. Match observed Authorization to
  each individual request. A prior Set-Cookie must yield no Cookie on a later
  request. Assert redirects and `WWW-Authenticate` do not cause another call,
  including POST, and no compression is negotiated/decompressed. A valid gzip
  response is unusable as JSON and cannot create accepted work evidence.

### 3. `test_sync_client.py` — transport deadlines and body bounds

- Type is loopback integration. Use a fixture with TCP accepted and headers
  never completed, a stalled body, and a peer sending chunks faster than the
  configured inactivity timeout. Use a short absolute response budget, such as
  300 ms, and a wider upper assertion for host scheduling. The peer should stay
  active considerably longer than the upper assertion without local closure.
  Assert it observes client EOF or reset before its independent guard timeout.
  A test using only the caller's elapsed time is insufficient.
- Demonstrate TLS handshake timeout using a TCP peer that accepts and never
  supplies TLS handshake data. Demonstrate upload timeout using a synchronized
  peer that accepts but does not read a request larger than socket buffers, and
  observe closure without an automatic replay. Use small configurable response
  limits for exact-bound, over-bound, declared oversized, chunked overflow and
  lengthless or truncated bodies. Include an invalid chunk or premature EOF
  after an observed error status, which must remain `HttpFailure`.
- Send headers for 503 plus an unusable body, covering stalled, oversize and
  malformed cases. Assert status remains 503, optional `problem` is absent, and
  peer resources are released. Use an invalid 202 and a valid acceptance envelope
  sent without message completion to verify uncertainty and no inferred ID.
- Stub only `getaddrinfo` with a controlled delay in a separate test. Verify
  lookup consumes the existing budget, expiry prevents any dispatch, and no
  resolver cancellation guarantee is inferred from this case. Repeat a valid
  request after recoverable timeout, protocol failure or overflow.

### 4. `test_sync_client.py` — wait context, close and interruption

- Type is loopback integration with a focused sleep/interruption seam where
  required. Return one valid nonterminal snapshot, then a mismatched ID,
  malformed response, HTTP error, or stalled response. Assert the precise error
  type, requested ID, and unchanged last valid snapshot, and prove no further
  polls. For a standalone status failure, assert the requested ID and absent
  last snapshot. Cover timeout before first valid read, expiry during poll
  interval, and a wait shorter than the normal response timeout. Preserve an
  observed 503 if the wait expires while consuming the error body.
- Close during a blocked response from a separate caller. Confirm EOF/reset at
  the peer, bounded release, repeat `close`, rejection of new operations and
  absence of a remote cancellation request. Exercise context-manager cleanup.
- On POSIX, use a temporary real signal or subprocess signal to raise native
  `KeyboardInterrupt` while blocked in a real read and verify peer cleanup.
  On Windows use a deterministic native `KeyboardInterrupt` injected at a
  blocking call seam with a real open fixture socket if portable console signal
  delivery is unavailable. In a poll sleep interruption case, assert native
  propagation and no further requests. Check that interruption after a POST
  leaves possible acceptance and never causes replay. No SDK wait state is
  attached to the interrupt. Verify recoverability with the retained ID where
  available.

### 5. `test_sync_client.py` — verified private CA and client identity

- Type is loopback TLS integration. Generate one ephemeral CA and server/client
  certificate/key material with pinned `trustme`. Require client identity at the
  server. Supply a standard `ssl.create_default_context` with CA trust and
  `load_cert_chain` on the client. Verify successful authenticated HTTPS and
  failure before HTTP for untrusted CA, hostname mismatch and missing client
  identity. Also reject an explicitly non-verifying context. No credential or
  raw TLS/parser details in the SDK error chain.

### 6. `verify_distribution.py` — installed consumer evidence

- Type is artifact/consumer integration. Location is
  `sdks/python/tests/verify_distribution.py`.
- Build a wheel and sdist with uv from the standalone project into a disposable
  directory. Install each artifact in its own fresh interpreter environment with
  no checkout on `PYTHONPATH` and an external cwd. Copy and run
  `examples/existing_credential.py` against a synthetic loopback Sidecar-shaped
  fixture. Check imports, distribution name/version/requires-python, h11 only as
  a core runtime dependency, `py.typed` and absence of FastAPI, Starlette, ASGI
  server and signer imports. Inspect the imported package path for install origin.
- Type-check the installed consumer example from the external directory in a
  separate wheel environment with pinned mypy. Do not use checkout source paths
  to satisfy typing. Exercise the installed example in both runtime environments
  without dev/web/signing libraries. `py.typed` file presence alone is insufficient.

## Safe Verification Commands

Run from the repository root unless the command specifies the installed verifier.
`uv` resolves standard development/build dependencies and, where necessary, the
selected local verification interpreter. Its child execution uses loopback only.

- Red before package exists `uv run --no-project --isolated --python 3.13 --with pytest==9.0.2 python -m pytest sdks/python/tests/test_protocol.py`.
- Focused protocol `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests/test_protocol.py`.
- Focused wire `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests/test_sync_client.py`.
- Full Windows SDK suite `uv run --no-project --isolated --python 3.13 --with-requirements sdks/python/requirements-dev.txt --with-editable ./sdks/python python -m pytest sdks/python/tests`.
- Windows artifact verification `uv run --no-project --isolated --python 3.13 python sdks/python/tests/verify_distribution.py`.
- Initial Linux SDK suite and artifact verification use the same commands on
  WSL x86-64 with `--python 3.12`. Record setup and exact commands actually used.
- Run `git diff --check` and inspect untracked package, fixtures and docs for
  generated output, operator credentials or unrelated changes. Full Java or
  Framework tests are outside this isolated package diff. The Java reference
  code remains unchanged, with composed verification scoped to PR 10.6.
