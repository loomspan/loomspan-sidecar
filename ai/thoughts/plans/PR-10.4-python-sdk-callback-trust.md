# Python SDK Callback Trust Implementation Plan

## Overview

- Ticket `ai/thoughts/tickets/PR-10.4-python-sdk-callback-trust.md`
- Research `ai/thoughts/research/PR-10.4-python-sdk-callback-trust.md`
- Profile Full 5-Step Pipeline, selected by the developer after triage.
- Outcome — an independently usable async callback verifier with current local public trust.

## Current State

`ExecutionTokenIssuer` in `sdks/python/src/loomspan_sdk/_issuance.py` owns a
startup signer, kid and issuance settings. `_signing._initialize_signing`
derives the public key and publishes a separate JWKS for receivers. Python has
no callback trust or verification entry point. The Java starter's
`CallbackJwtDecoder.decode` and `CallbackJwtTrust` define the acceptance and
trust behaviors. Existing interop sends Python output to Java, so it does not
exercise a Python callback receiver. Baseline is `62853801e41720e25f185f5b4e1941d8474fcae5`
with only the pipeline research artifact present at planning entry.

## Desired End State

A caller opens a `CallbackVerifier` from the initialized issuer in an async
context. The verifier checks compact execution JWTs and returns an immutable
`CallbackPrincipal` containing only issuer, subject and exact authorities. A
nonblank audience override is optional. The issuer cannot be configured
separately from issuance. Invalid input raises one generic typed credential
failure. Missing or unusable configured overlap fails initial opening. Once
open, detected invalidity withdraws even own-key trust, and correction restores
only the complete current candidate. Concurrent checks can finish with the
snapshot they acquired. Later calls consult current trust. See the five
acceptance mappings below for the executable evidence.

## Impact and Risk Analysis

- Treat a bad public key set as one failure. Reading or building candidate keys
  must never expose a partial set or retain a removed key on the next admission.
- Floods must not allocate per-kid caches, spawn reads, or reset the miss throttle.
  Read/parse cancellation must neither strand verification waiters nor publish
  after context exit. Application coroutine scheduling must remain independent of
  file latency.
- JOSE's signing input is the original protected header and payload segments.
  Key material and key-selection URLs in a JWT never select trust. Numeric dates
  must preserve Java's comparison semantics without its reader's Double rounding.
- Returned identity can be serialized normally because it never stores bearer
  material. Keep raw JSON, crypto errors, file paths and input values out of
  authentication failures and transition logs.

## Implementation Approach

Use `async with CallbackVerifier.open(issuer, audience=..., overlap_jwks=...)`
and `await verifier.verify(token)` as the concrete async core entry points.
The input is the compact token string. Parsing the HTTP `Authorization` header
belongs to PR 10.5. `CallbackPrincipal` and `InvalidCallbackCredential` give
callers a typed result and a narrow error to catch. Use one private issuer
accessor returning issuer name, kid and the startup RSA **public** key. Do not
add raw credential, private signer, or mutable settings getters. Own trust
comes from that in-memory key and is independent of the signer export file.

With overlap, a single AnyIO task scoped to `open` owns runtime reads and
publication. A lock-free snapshot lookup on the owning event loop serves known
kids. On a miss an eligible request signals the task and waits for that attempt's
completion. Concurrent misses can join the same attempt. The worker can coalesce
an overlapping poll and miss, using one monotonic one-second admission window
for miss-triggered refresh per verifier. Requests cannot start I/O directly or
queue separate work for different kids. Use a fixed-delay one-second poll when
there is no miss, preserving periodic observation even with no requests. Keep
the first miss eligible independently of the initial load. This scope avoids
abandoned read work when a request is cancelled and allows polling to continue.

Run reads and public-key candidate validation via existing AnyIO worker
offload. Workers only return candidate data. Publish once on the owning event
loop, before waking any waiters. In own-only mode there is no refresh task or
file access. Initial overlap must be valid before entering a task group. Exit
marks the verifier closed, withdraws its snapshot, wakes waiters and cancels the
owned task so idle shutdown does not wait for the polling interval. A read in
flight may complete as shutdown unwinds, with its result discarded. Use normal
local regular files and reject nonregular inputs rather than intentionally
opening a device or FIFO as overlap. Do not add a detached reader or advertise
a deadline for a filesystem call that stalls in the OS. The shared refresh
task never lets a cancelled request leave a detached file read behind.

Keep wire parsing specific to the execution profile. Use strict UTF-8,
duplicate-free JSON objects and strict unpadded Base64URL for compact segments
and JWK numbers. Fail unsupported critical JOSE options. `b64` if present must
be true for an encoded compact JWT, and `crit` may only designate the supported
`b64` parameter. Neither detached nor unencoded payloads are part of this
profile. Ignore unrelated noncritical hints when selecting trusted keys and
authorities. Keep one implementation for RS256 using existing cryptography.

Parse JSON timestamps with `Decimal`, check the Java `Instant` seconds range,
then floor to nanoseconds in a dedicated decimal context with precision enough
for the entire range. Quantize before scaling so there is no intermediate
rounding at the skew or issuance-order boundaries. Small negative fractions
must floor toward the earlier instant. Evaluate the clock after verification.
The exact inclusive boundaries are `exp >= now - 60s` and `nbf <= now + 60s`.
When `iat` is supplied require `exp > iat` after conversion. There is no separate
future-`iat` check or `nbf`/`exp` ordering check. `jti` may be absent or any
string. Preserve role strings and order, including duplicates if received.

## Phase 1 — Trust and execution credential verification

### Changes

- [x] `sdks/python/src/loomspan_sdk/_issuance.py`: share internal execution
  algorithm/type/purpose values and existing timestamp bounds with verification.
  Add `_callback_verification_material` returning the immutable public-only
  inputs from the initialized issuer. Reuse Java nonblank semantics already
  implemented by `_protocol._java_blank`.
- [x] `sdks/python/src/loomspan_sdk/_protocol.py`: reuse strict UTF-8/duplicate
  handling for callback/JWKS parsing with a private exact-number option to
  `decode_json`. Preserve the default response-number behavior.
- [x] `sdks/python/src/loomspan_sdk/_callback_trust.py`: add `_CallbackTrust`
  and a complete overlap reader/validator. Require nonempty `keys` of RSA objects,
  Java nonblank unique kids, no private members, optional exact `alg`/`use`,
  unpadded Base64URL RSA integers, odd modulus at least 2048 bits, and odd
  exponent `3 <= e < n`. Construct all cryptography public keys, compare
  public numbers for collisions with own, and commit immutable snapshots.
  Distinguish unavailable (read failure) from invalid (unusable content), and
  emit fixed log records only on runtime category transitions and restoration.
  Inspect current content every read, optionally skipping unchanged candidate
  validation by byte equality. Do not keep obsolete usable key sets.
- [x] `sdks/python/src/loomspan_sdk/_callback.py`: add `CallbackVerifier.open`,
  `verify` and frozen, slotted `CallbackPrincipal`. Validate `audience` and
  `overlap_jwks` (a `Path` with a nonblank name when supplied). Require exact claims and header values,
  accepted audience shape, trusted RSA signature and time windows. Present
  optional claims with null or wrong types fail. Map expected parse/validation/
  signature failures to `InvalidCallbackCredential` outside their exception
  handlers so no underlying exception is chained. Keep initialization failures
  as category-specific safe `LocalFailure` errors and preserve cancellation.
- [x] `sdks/python/src/loomspan_sdk/_errors.py` and `__init__.py`: expose the
  typed invalid-credential error and the two concrete callback types. No new
  dependencies, registration hooks or protocol SPI.
- [x] `sdks/python/tests/test_callback_verifier.py` and `test_callback_trust.py`:
  add the focused profile, lifecycle, cancellation, integrity and privacy tests
  in the testing plan, including the red own-key acceptance test first.

### Automated verification

  testing plan. Fixed-clock tests distinguish the inclusive edge from the next
  nanosecond. Runtime tests prove one-read coalescing, old-key withdrawal,

## Risks and Rollback/Recovery

Operations recover by replacing the configured overlap with a valid public JWKS.
Correction does not rotate the private signer, change account data or replay any
work. There is no development-data reset or planned intermediate integration
break. The full CPython and OS support matrix and composed deployment proof are
tracked in PR 10.6. Record actual evidence and any discovered break before review.

## Step 4 Evidence and Handoff

- The refresh task records the global miss window when it starts a requested
  attempt. Misses during an active refresh share its completion. The reader
  validates every current candidate without caching raw file contents.
- The Java runner verifies package provenance against installed distribution
  metadata because `uv run --with` can install the wheel in an overlay outside
  `sys.prefix`. Offline Maven executed the fixture producer with zero skips,
  and Python admitted its real Java-issued credentials through overlap and
  rejected the one-nanosecond credential just past the skew boundary.
- Focused verifier/trust tests passed all 122 cases. Full SDK suites passed
  436 on Windows x86-64 CPython 3.13.13 and 438 on WSL Linux x86-64 CPython
  3.12.16. The Windows suite skipped two existing POSIX-specific signing tests,
  both of which ran in WSL. Strict SDK and installed-consumer typing, wheel
  and sdist checks, and tracked/untracked whitespace checks passed.
- The implementation needs no data reset and creates no temporary integration
  break. PR 10.5 can compose `CallbackVerifier.open` with its app lifecycle and
  use `verify` for request admission.
