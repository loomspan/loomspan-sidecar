# Python SDK signing and issuance implementation plan

## Overview

- Ticket `ai/thoughts/tickets/PR-10.3-python-sdk-signing-and-issuance.md`
- Research `ai/thoughts/research/PR-10.3-python-sdk-signing-and-issuance.md`

- Issue an opaque execution credential from application-authenticated
  identity and atomically publish the corresponding public trust at startup.

## Current state

Baseline is `a27e9aff5a57fbb84cdf5546ded7a32604b2c707` on `main`. The
research document is the only new file on entry to planning. Python's
`CredentialSnapshot` in `sdks/python/src/loomspan_sdk/_credential.py` already
owns secret transport and redaction for both clients. The package accepts
already-issued credentials and has no signer. Java's `ExecutionTokenIssuer`,
`IssuanceSettings`, `AuthenticatedIdentity` and `SigningKeys` implement the
source contract. `ExecutionJwtDecoder` and `CallbackJwtDecoder` are the actual
Java receivers and have fixed-clock seams used by existing tests.

## Desired end state

An application initializes one `ExecutionTokenIssuer` with explicit typed
signing settings at startup. Each call passes a distinct
`AuthenticatedIdentity` captured from authentication. The issuer returns the
existing `CredentialSnapshot` for use in either client. Signing requires
neither a source token nor any web context. Both modes publish exactly one
public RSA JWK, with the same public identity as Java for the same key. Startup
fails if the signing settings, private input, or publication are unusable.
The exact signed wire representation and the actual Java read behavior each
have independent, executable tests.

## Scope

In scope are the Python core identity, issuance and startup signing API, direct
dependencies, public JWKS export, current usage docs and focused Python/Java
verification. PR 10.4 owns Python callback verification/trust. PR 10.5 owns web
and application lifespan composition. PR 10.6 owns maintained consumer adoption
and aggregate support and deployment proof. Java production, TLS configuration,
management, release/push, rotation coordination and operational key or data
changes are outside this ticket.

## Active project guardrails

Apply the [design lens](../design-lens.md#simplicity-and-technical-debt).
Destructively replace superseded development contracts. Keep one supported
signing path per mode and omit compatibility machinery. The credential and
HTTP client contracts already established in PR 10.1/10.2 continue to serve
callers. Preserve operational identity, keys and reference packs. No development
data reset is needed. The application owns identity capture and the operator
owns file provisioning and rotation. Java tests stay within the SDK/Sidecar
boundary and use no Loomspan Framework internal APIs.

## Impact and risk analysis

- Identity mix-ups or prefix normalization could give one user another's
  privileges. Capture names immutably, match exactly and make the credential
  explicit on each call.
- JSON float/datetime convenience conversion drops valid Java issuance
  precision. Java itself writes exact decimal dates and its current Nimbus
  readers round some decimal literals. The issuance API must retain precision
  independent of that receiver behavior.
- An unconstrained crypto loader can accept legacy containers or reject valid
  PKCS#8 variants. Check the precise PEM envelope and use a typed ASN.1 schema
  before the validated RSA loader.
- A wrong export path or partial write can destroy operator material or break
  trust. Stage the complete public file in its existing parent and perform a
  single replace. Detect existing aliases by filesystem identity. The operator
  controls both paths and keeps one process responsible for each export path.
- Crypto/ASN.1 exceptions can include input. Translate failures into bounded
  SDK errors with no sensitive exception chain and no input repr or logging.

## Implementation approach

### Developer decision on optional PKCS#8 attribute values

The developer approved delegating payload validation for unused optional
PKCS#8 attribute values to the BER libraries. Keep strict PEM and PKCS#8
structure validation, including attribute OIDs and nonempty value sets,
RSA key validation, and embedded public-key agreement. Keep the existing
Java fixtures as regression coverage. Do not add Java-specific rules for
the payloads of arbitrary unused attribute values. Document in the Python
SDK README that the libraries may accept some values the Java SDK rejects,
such as certain malformed date or string payloads and unsupported ASN.1
types. These values do not participate in signing or public trust export.

Use an exact integer nanosecond lifetime and clock. A `timedelta` or float
would lose issuer parity. Decimal-aware JSON via `simplejson` emits exact
NumericDate numbers using `Decimal(f"{timestamp_ns}e-9")` (exact construction
independent of the ambient decimal context). Check the Java Instant domain
from second `-31557014167219200` through `31556889864403199`, including the final
second's 999,999,999 ns. Check the startup sample and the sample used for each
issue, once per operation. Python preserves Java's positive representable
issuer lifetimes and the baseline of both receivers. A one-nanosecond lifetime
can collapse to equality during Java parsing, and extreme values can round out
of range. Verify and document this behavior. Receiver parser changes would be a
separate contract change. Use the normal compact JWS encoding (base64url
header and payload, signed joined bytes, base64url signature) with
`cryptography` RSA PKCS#1 v1.5 and SHA-256. This fixed-profile assembly needs
no generic JWT parser or JSON customization. PyJWT's high-level datetime
path would discard subsecond precision and adds no signing capability needed
here. Standard JSON and SHA-256 implement the RFC 7638 calculation over
canonical `e`, `kty`, `n` members.

Use `pyasn1` and `pyasn1-modules` for complete BER parsing of
RFC 5958 OneAsymmetricKey and RFC 8017 RSA structures. The validated
`cryptography` loader alone rejects the matching embedded-public-key fixture.
Parse algorithm, attributes and embedded public key through standard schemas.
Use the RSA loader's key validation on the canonical DER encoding of the
parsed inner key, then check the RSA type, minimum strength and optional public
key consistency. Keep supported BER forms and PEM whitespace from the current
Java fixtures. No handwritten ASN.1 codec, key conversion API, or fallback
branch for unsupported formats.

During implementation a synthetic Java `SigningKeys` probe exposed a gap in
the typed decoder alone. The AttributeValue `ANY` preserves opaque bytes, and
typed INTEGER decoding normalizes malformed encodings. Java rejected malformed
nested values, including a nonempty NULL, empty INTEGER, and a truncated
constructed value. It accepted well-formed primitive, constructed, and
indefinite-length context-tagged values. Add `asn1` 3.3.0's documented BER decoder
as a complete wire-structure check before the typed schema and RSA validation.
This one extra pure-Python dependency keeps the accepted Java fixtures and
rejects malformed wire encodings without implementing a BER parser or using
undocumented `pyasn1` tag-dispatch APIs. The exact-floor tests cover this
dependency on the same Windows and Linux interpreters as the other libraries.
[Python-ASN1 Decoder API](https://python-asn1.readthedocs.io/en/latest/reference/asn1.html#asn1.Decoder).

Use a single `os.replace` after closing the same-directory temporary file.
This uses a native rename on POSIX. CPython on Windows uses
`MoveFileExW` with replacement and without the cross-volume copy flag.
Use filesystems that support atomic same-directory replacement. A failed
replace is a startup error. No permission changes, directory creation,
copy/delete fallback, or guarantee of crash durability beyond atomic publication.
[Python os.replace](https://docs.python.org/3/library/os.html#os.replace),
[CPython posixmodule.c](https://raw.githubusercontent.com/python/cpython/3.13/Modules/posixmodule.c),
[Microsoft MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw).

Resolve the existing export parent for staging and replacement because the
temporary-file helper normalizes its directory argument. This preserves the
actual POSIX symlink-parent and `..` traversal and keeps both file entries in
the same directory. Existing-file overlap uses the original paths.

## Phase 1 — Identity, signer and issuer

### Changes

- [x] `sdks/python/src/loomspan_sdk/_issuance.py` defines immutable,
  copying `AuthenticatedIdentity(subject, authorities=())` and
  `IssuanceSettings(issuer="loomspan-app", lifetime_ns=900_000_000_000,
  additional_audiences=(), roles=())`. Accept actual collections of strings,
  reject scalar strings, mappings and blank/non-string entries, and expose
  copied tuples. Use Java's blank classification for parity, including its
  Unicode whitespace distinctions, without trimming nonblank names. Reject
  non-int, bool or nonpositive lifetimes. At startup reject a lifetime whose
  expiry does not fit the Instant range. Warn once per initialized issuer when
  strictly above 3,600 seconds, with fixed text and no setting/identity value.
- [x] `sdks/python/src/loomspan_sdk/_signing.py` defines separate frozen
  `ColocatedSigning(key_directory: Path)` and
  `ProvidedSigning(key_location: Path, jwks_export: Path)` shapes. Require
  actual path objects. Settings construction performs no I/O. Reject anything
  other than these two signing modes at initialization and rely on strict
  constructor keyword validation to reject unsupported or mixed settings.
- [x] `_signing.py` starts a fresh 2048-bit RSA key in colocated mode and
  selects `key_directory / "jwks.json"`. Provided mode reads its configured
  file once and has no generation branch. Full-match a single ASCII
  `PRIVATE KEY` block using Java's envelope and whitespace rules, require
  complete base64 quanta and use strict base64 validation. Decode the full
  PKCS#8 outer and inner structures, requiring empty remainders, supported
  versions, RSA encryption OID with absent or ASN.1 NULL parameters, valid
  optional attributes with nonempty values, and an aligned/complete embedded
  public key only in version 2 when present. Check the embedded modulus and
  exponent against the loaded key. Reject non-RSA and RSA below 2048 bits.
  Use library RSA sign/verify of a fixed startup challenge before publication
  to prove suitability for RS256 as Java does.
- [x] `_signing.py` derives unsigned-minimal base64url `n` and `e` and the
  RFC 7638 `kid`; exports one JWK with exactly `kty,n,e,kid,alg,use`.
  Reject normalized path overlap and existing-file overlap (hardlinks,
  symlinks and equivalent paths). Use original filesystem traversal when
  comparing existing identities, including paths with symlink parents and
  `..`; fail on stat errors other than a missing destination. Stage under
  the existing destination parent, close before replace on every platform,
  clean up the temporary entry on failure and preserve the prior public
  file/private input. A startup exception after successful publication should
  not be introduced by doing fallible initialization after the commit point.
- [x] `_issuance.py` defines `ExecutionTokenIssuer(signing, settings=...)`.
  Construction is the explicit startup action. It holds no user or login state.
  Issue only from `AuthenticatedIdentity`. In first-seen order, deduplicate
  audience from Sidecar, issuer and extras, and roles from the exact intersection
  of captured authority names with the configured allowlist. Use UUID4
  `jti` and the fixed Java headers/claims. Sign and return `CredentialSnapshot`.
  Reject issuer and credential state serialization and omit private data from
  repr, str, default logs and public errors. Translate expected IO, ASN.1 and
  crypto exceptions into fixed-context `LocalFailure` without retaining their
  chain. Keep raw bytes access internal. The code need not prevent deliberate
  introspection of object state or tracebacks with locals.
- [x] `sdks/python/src/loomspan_sdk/__init__.py` exports the five new public
  classes. `sdks/python/pyproject.toml` declares the directly used
  `asn1>=3.3,<4`, `cryptography>=48,<49`, `pyasn1>=0.6.5,<0.7`,
  `pyasn1-modules>=0.4.2,<0.5` and `simplejson>=4.2,<5` bounds alongside the
  existing transport dependencies. Verify these lower bounds on both local targets.
  Keep strict typing, using narrowly scoped imports for libraries lacking stubs.
- [x] `sdks/python/tests/test_issuance.py` and
  `sdks/python/tests/test_signing.py` add the focused evidence in the testing
  plan. Reuse the synthetic RSA/JWK vector under
  `sdks/java/core/src/test/resources/signing/`. Unit tests derive variants
  from that vector or generate synthetic keys.

## Test strategy

First prove the public issuer is absent with one focused test. Unit tests
assert exact wire bytes/claims and verify signatures independently of issuance,
then exercise real files and injected publication faults in scratch
directories. The installed package check detects build, metadata and typing
failures. Both Maven modules consume fresh credentials generated by the
shipping issuer, so current receiver proof has no dependency on Python
self-verification or historical Java fixtures alone.

## Acceptance-criteria traceability

| Acceptance criterion | Planned code evidence | Planned test evidence |
| --- | --- | --- |
| Trusted capture and exact profile, independent lifetime, no identity leakage | Immutable copied snapshots, fixed claim construction and integer nanosecond checks in `_issuance.py` | `test_issuance.py` identity mutation, two-user, role/audience, jti, warning and nanosecond/overflow assertions |
| Both startup modes and strict PEM | Closed settings types, one validated PKCS#8 path and exclusive key initialization in `_signing.py` | `test_signing.py` restart, fixture variants, safe failure and no-generation assertions |
| Public identity and failure-atomic export | Public-only thumbprint/JWK, input identity comparison and same-directory atomic replacement | `test_signing.py` exact fixture, overlap and injected publication failure tests; Java SDK test compares actual exports |
| Invalid settings, safe failures and operating docs | Typed settings, sanitized errors, unchanged opaque credential, both startup recipes in README | `test_signing.py`, `test_issuance.py` and distribution verifier |
| Actual receivers, installed docs and dependencies | Existing Java production decoders consume the actual Python issuer's output | `verify_java_issuance.py`, both Maven test classes, wheel/sdist verifier and recorded local dependency/platform checks |

## Risks and rollback/recovery

Failure aborts startup. Fix paths, permissions or private material and restart
with operator-owned configuration. A prior complete public file remains when
replacement fails. A successful colocated restart changes trust; reuse the
same provided key across restarts when stable identity is required. Operators
choose how to distribute overlapping public trust. No data reset, key
regeneration, release, or remote sync is part of implementation. If a library
probe contradicts exact issuance or the supported PEM/atomicity contract,
report the tradeoff before changing it or adding a bespoke parser.
