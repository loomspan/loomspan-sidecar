# Java SDK submission uncertainty testing plan

## Change Summary

Exercise the distinction between pre-dispatch local failure, possible-send
acceptance uncertainty, a known HTTP status, and status-read/wait termination.
Use the public blocking SDK against provider-free loopback fixtures.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Submission boundaries | An over-limit response supplies a plausible ID or a new path replays the POST | Complete-looking ID prefix plus extra bytes, ignored `Location`, both transfer framings, attempt count and successful next request |
| Interruption | A pre-interrupted call reaches the network, an in-flight call looks local, or cleanup waits for the peer | Zero-attempt pre-interrupt and latch-gated in-flight interrupt with bounded join, flag and same-client recovery |
| HTTP diagnostics | Overflow masks status, exposes partial JSON or copies credential/input into diagnostics | Fixed/chunked error responses, bounded malformed/non-object/truncated errors, bounded redaction and safe exception diagnostics |
| Read context and budgets | Shared classification loses requested ID, last valid snapshot, read interruption or wait deadline | Successful status overflow after a valid poll, oversized HTTP error context, and existing read/wait regression tests |
| Dependencies and lifecycle | Cleanup removes transport/TLS consumers or leaks resources on a new exit | Consumer audit, repeated bound failures and recovery, full SDK reactor including TLS and Boot SSL bundle |

## Existing Coverage and Environment Constraints

`SidecarClientEdgeTest` provides `Fixture`, an ephemeral loopback `HttpServer`
that counts every request and consumes its body before invoking the handler.
`reply` writes declared-size responses. `sendResponseHeaders(status, 0)` with
body bytes exercises chunked framing. Existing tests cover malformed/lost
acceptance, local/closed-client rejection, disabled redirect/auth rechallenge,
bounded redaction, successful discovery at the byte limit, malformed/truncated
reads, total wait deadlines, and interrupts during polling sleep and status
network reads. `SidecarClientTest`, `SidecarClientTlsTest` and Spring's
`SidecarClientAutoConfigurationTest` cover the normal flow and retained SSL paths.

Use Maven with Java 21 and the JDK's `keytool` for existing TLS fixtures. In the
current PowerShell environment `mvn -version` reports Maven 3.9.6 using
`JAVA_HOME=c:\hamdev\jbrsdk21` even without `java` on `PATH`. The independent SDK
reactor has no Sidecar/Framework dependency. Fixtures use synthetic local data,
ephemeral loopback ports and bounded waits. No Docker, model providers, deployed
endpoints, operational credentials or persistent data are needed for this ticket.

## Tests to Add or Update

The tests below belong in
`sdks/java/core/src/test/java/ai/loomspan/sdk/SidecarClientEdgeTest.java`.
Names are suggestions for the behavior under test.

### 1. `oversizedSubmissionResponsesLeaveAcceptanceUnknown`

- Use fixed-length and chunked `202` responses with a valid acceptance envelope
  at the start of the body and padding beyond the configured limit. Supply a
  valid-looking `Location` header too. In the declared-size case, the existing
  truncated over-limit reply separately exercises rejection at the header check.
- Assert `AcceptanceUnknownException`, null ID and last snapshot, and one POST
  attempt for each case. Check the same client can make a successful next call.
  Keep existing repeated overflow/recovery and exact-limit discovery coverage.

### 2. `interruptionsDistinguishLocalAndPossiblySentSubmission`

- For a valid submission on an already interrupted thread, assert
  `LocalFailureException`, unchanged interrupt flag, and zero fixture attempts.
  Run on an isolated caller thread or clear the test thread's flag in `finally`.
  A later successful request on the same client proves it is still usable.
- For in-flight interruption, signal from the fixture after the complete POST
  arrives, and hold the response using a release latch. Interrupt the caller
  only after the receipt signal. With a client response timeout well above the
  bounded join, assert that the caller exits while the response is still held,
  reports `AcceptanceUnknownException` with null ID and snapshot, and has its
  interrupt flag set at catch. Assert one POST and a subsequent successful read
  on the same client. Use `finally` to release the handler and clean up workers
  on failed assertions. Do not use a blind sleep to guess dispatch timing.
  If using the shared HTTP fixture, repeat the interrupted exchange on the same
  client past the pool's per-route capacity before the final recovery read, so
  the check can detect leaked connection leases. A direct peer-side close
  observation is equivalent evidence if a socket fixture is needed.

### 3. `httpErrorsKeepStatusWithoutUnsafeProblemDetails`

- Exercise fixed and chunked over-limit non-2xx bodies, with a JSON-looking
  prefix and synthetic diagnostic sentinel. Assert exact status, null problem,
  null submission ID, no response/credential/input sentinel in the diagnostic,
  no original cause, and one POST. Check subsequent successful use of the same
  client as part of the fixture sequence where practical.
- Exercise complete malformed or non-object error bodies within the byte bound
  and retain the existing truncated-error case. Assert exact status and null
  problem. Keep the complete bounded JSON problem test and its recursive
  credential-key and value redaction assertions.
- Cover an oversized HTTP error on an execution read or subsequent `await` poll
  with requested ID and, when polling, the last valid snapshot. Keep the first
  failed read terminal to the wait loop.

### 4. `statusOverflowPreservesWaitContext`

- Return a valid bounded `RUNNING` snapshot followed by oversized `200` on the
  same execution path. Assert `ProtocolException`, the requested ID, the
  retained `RUNNING` snapshot and exactly two polls.
- Keep current tests for requested-ID mismatch, timeout through slow headers,
  stalled or trickled body, interrupt while polling or blocked on a status read,
  and one attempt on failed discovery and status exchanges. Retain local
  validation, close idempotency and lost/malformed acceptance tests.
