# Local Rollback and Recovery Testing Plan

## Change Summary
Rollback reviews exact locally retained content, validates against current destination bindings, and confirms it through the existing destructive publication sequence as a fresh local snapshot with source provenance. The history browser adds editor/admin controls. Recovery guidance and a stopped full SQLite backup/restore test cover populated configuration and management identity.

## Impacted Areas and Risks
| Category | Risk | Planned evidence |
| --- | --- | --- |
| Retained source | Selected content is pruned or changed before acceptance, or a status is mistaken for destination validity | Exact-ID/status matrix, pruning race, independent validation, frozen content and unchanged original |
| Confirmation | Different selection, session, runtime or replacement grant uses an old review | HTTP stale-selection/runtime/grant tests; renewal succeeds; review ID cannot be reused |
| Authorization | Viewer or missing CSRF causes destructive action | Editor/admin/viewer, anonymous and CSRF HTTP tests for both POSTs |
| Publication | Validation/preparation failure destroys drafts; cutover races editing or another publication | Hook tests before/after cutover, publication/editing gate latches, lease/draft invalidation |
| Failure accounting | Reversion or status fault misreports running/intended state or reverts successful activation | Activation/revert/status injection plus restart/current/history checks |
| Browser | Hostile YAML enters DOM, selection changes leave stale confirm, keyboard users lack feedback | Playwright text rendering, focus/status, selection and refresh cases |
| Recovery | Incomplete SQLite file set or stale companions loses account or wrong committed pointer starts | Stopped database-set copy/restore with populated account and nonempty config |

## Existing Coverage and Environment Constraints
`ManagementConfigurationHttpIntegrationTest` already seeds management roles and exercises import review/confirm, CSRF, stale grants, failure responses and disconnect on a loopback Spring server. `RuntimeConfigurationIntegrationTest` uses publication hooks and latches for serialization, generation/fault behavior. `ManagementHistoryBrowserIntegrationTest` and `ManagementImportBrowserIntegrationTest` use local Playwright Chromium; the browser binary must be installed in the developer's test environment. `RuntimeConfigurationRecoveryIntegrationTest` uses temporary SQLite databases and application contexts. Maven Surefire runs JUnit tests with Java 21 and the installed beta 5 snapshot; `README.md` names `.\mvnw.cmd -B -ntp verify` as the standard full check. No tests need live external services, production data, real email delivery, or deployed Docker/Kubernetes.

## Tests to Add or Update

### 1. `rollbackStatusesProduceFreshLocalSnapshots`
- Type: HTTP/runtime integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Published, failed, pending and current retained sources are eligible; each destination gets a distinct ID and sequence with exact source provenance, independent validation and ordinary retention. Source status is displayed but never copied as destination outcome.
- Inputs/fixture: Seed full distinct configurations, then use store status updates or controlled publication failures for source status; use the current snapshot for the self-rollback case.
- Doubles or boundary isolation: Local SQLite and Spring test server.
- Edge cases: Empty skill list, same content as current, retention limit and protected current/generation IDs.

### 2. `rollbackMissingSourceAndStaleReviewPreserveEditing`
- Type: HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Unknown/pruned source at review or confirm returns explicit absence/conflict, with refreshed history/current available; changed selected ID, other session/review, runtime ID or replacement lease grant cannot confirm; renewal with the same grant remains valid.
- Inputs/fixture: Two retained IDs, separate editor sessions, foreign draft/lease, prune between review and confirm, publish or take over lease between review and confirm.
- Doubles or boundary isolation: Temporary SQLite; no shared external service.
- Edge cases: Forged source ID and grant; no grant; source pruned while publication gate is queued; no draft/history mutation on rejection.

### 3. `rollbackRequiresEditorAndCsrfWithoutLeaseOwnership`
- Type: HTTP security integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Viewer/anonymous and no-CSRF review/confirm are denied server-side; editor and admin can review/confirm while another editor owns the lease; execution JWT does not grant management rollback access.
- Inputs/fixture: Existing role/account helpers and browser-like clients.
- Doubles or boundary isolation: Loopback server with test JWT keys.
- Edge cases: Live account role/version/session invalidation at acceptance.

### 4. `rollbackCutoverAndFailureMatrix`
- Type: runtime integration with HTTP assertions where response codes matter
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java` and `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Invalid destination binding/content and prepare/stage failure leave drafts/lease; accepted cutover clears all even on commit or activation failure; successful reversion marks the new attempt `FAILED` and restores intended A; failed reversion faults mutations with intended B; status failure after B activation retains B running and pending bookkeeping; no pending status is presented as failed activation.
- Inputs/fixture: Existing runtime `Hooks` beforePreparation/beforeCommit/beforeFrameworkPublish/beforeRevert/beforeStatus, invalid REST binding, foreign draft and lease.
- Doubles or boundary isolation: Local resources and hook failures.
- Edge cases: History prune fault, restart after pending/fault states and accurate `current`/`history` response.

### 5. `rollbackSerializesAndSurvivesDisconnect`
- Type: concurrent runtime/HTTP integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationIntegrationTest.java` and `src/test/java/ai/loomspan/sidecar/configuration/ManagementConfigurationHttpIntegrationTest.java`
- Proves: Import/ordinary publication and editing/lease/session invalidation cannot bypass accepted rollback; session logout, disconnect and lease expiry after admission do not cancel it; admitted execution retains its original generation and REST resources until retirement.
- Inputs/fixture: Existing latches around preparation/publication and test execution handoff, two management sessions.
- Doubles or boundary isolation: Controlled hooks and local HTTP clients.
- Edge cases: Session invalidates while rollback is blocked after admission; source content remains consistent while concurrent pruning/publication waits.

### 6. `editorCanReviewAndConfirmRollbackFromHistory`
- Type: Playwright browser integration
- Location: `src/test/java/ai/loomspan/sidecar/management/ManagementHistoryBrowserIntegrationTest.java`
- Proves: Editor/admin see a status-labeled exact source summary, validation feedback, lease owner/current runtime, explicit draft-loss warning and separate confirm; viewer sees no action; content is text and keyboard/status feedback works.
- Inputs/fixture: Existing browser login helpers; hostile labels/YAML; foreign lease; valid retained source.
- Doubles or boundary isolation: Loopback Spring server and Playwright Chromium.
- Edge cases: Changing selected detail clears review; 404/pruned source refreshes list/current; stale runtime/grant requires renewed confirmation, renewal does not; disconnected confirm says outcome unknown and prompts inspection; fault/activation responses are truthful.

### 7. `stoppedFullDatabaseBackupRestoresConfigurationAndIdentity`
- Type: local persistence/restart integration
- Location: `src/test/java/ai/loomspan/sidecar/configuration/RuntimeConfigurationRecoveryIntegrationTest.java`
- Proves: A stopped copy of main database and existing WAL/SHM companions restores an active management account plus nonempty published content/history; startup follows the backup's committed pointer and management access remains usable. Stale destination companions are removed before restore.
- Inputs/fixture: Temporary original/backup/restored paths; create account through management identity fixture or repository-consistent seed; publish B after backup to show restore selects A.
- Doubles or boundary isolation: No live database; only stopped local contexts, local mail double if setup requires it.
- Edge cases: Companion files present/absent, writable restored paths, sensitive data persists, post-restore runtime/history and account authentication.

### 8. `supportedFrameworkSurfaceRemainsClosed`
- Type: architecture regression
- Location: `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`
- Proves: New production and test Java code imports no framework internal/autoconfigure types and adds no Java `@SkillMethod` skill.
- Inputs/fixture: Existing ArchUnit rules.
- Doubles or boundary isolation: None.
- Edge cases: New rollback service and runtime code.
