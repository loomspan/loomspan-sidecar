## Change Summary

Only two provided paths remain in core/Spring. Exactly one unencrypted RSA PKCS#8
PEM is accepted, with safe failure for every rejected category. Colocated remains
ephemeral. Public atomic exports, token profile/roles, receiver trust and ordinary
TLS/mTLS behavior remain covered. Maintained suite signing certificates disappear;
the same private inputs supply public fields and identity.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Input security | Permissive envelope/Base64/DER accepts bundles or junk | Complete positive/negative loader table, prior export untouched |
| Startup configuration | Removed fields silently ignored or secret values printed | Seven obsolete-property cases, relaxed names, empty values, captured logs/stack traces |
| Identity and protocol | PEM packaging changes kid/claims/roles | Fixed synthetic expected public vector and existing issuer tests |
| Filesystem | Export overwrites private input or falls back to non-atomic write | Existing seam failures, hard-link/normalized collisions, input hash/bytes preserved |
| Integration | Tests only verify independent fixtures | Actual SDK consumer → Sidecar → authenticated callback lanes |
| Cleanup | Removing signing fixtures breaks retained TLS or suite business behavior | Retained SDK/root TLS tests and all three provider-free SDK lanes |

## Existing Coverage and Environment Constraints

JUnit 6 core tests use TempDir/JCA/Nimbus; starter tests use Boot's
ApplicationContextRunner, AssertJ and OutputCaptureExtension. `SigningKeysTest`
already owns a deterministic NIO seam, restart and public-field assertions.
`ExecutionTokenIssuerTest` covers defaults/profile/exact intersection/concurrency.
`CallbackJwtTrustTest` exercises the actual signer and callback decoder in both
modes. Root tests cover waiting/reload/JWT/RBAC/forwarding plus TLS; they are not
themselves evidence that the revised SDK interoperates.

Use Java 21 from `JAVA_HOME`; add its bin directory to the process PATH if needed
without changing machine configuration. Maven, the suite .venv, Python dependencies,
Docker daemon and images, Playwright Chromium and installed Framework snapshot
must be usable. Local dependency/image downloads are allowed; no provider calls,
release steps or Framework rebuild are planned. Current environment health is
unverified. Check it during implementation, and report exact failures as pending
verification. Do not weaken code/tests to hide environment failures.

Suite lanes create unique project names, tmpfs data, disposable keys and isolated
networks; they preserve ordinary credentials/data/reference packs and clean only
owned run resources. Their normal generation of fresh disposable test identities
is distinct from regenerating existing credentials. Do not rerun business setup,
credential preparation, database resets or paid runners.

## Tests to Add or Update

### 1. `providedPemAcceptsSupportedWhitespaceAndRetainsIdentity`

- Type/location: core unit, `sdks/java/core/src/test/java/ai/loomspan/sdk/SigningKeysTest.java`.
- Inputs: fixed synthetic >=2048-bit RSA PKCS#8 fixture and checked expected public
  JWKS under `sdks/java/core/src/test/resources/signing/`, LF/CRLF/CR and surrounding
  space/tab/newline variants. Keep a fixture README declaring test-only provenance
  and expected n/e/kid for later SDK reuse.
- Proves: two initializations preserve the input bytes, exact n/e/kid, usable RS256
  signatures and exact public field set `kty,n,e,kid,use,alg`, no `x5c` or private
  members. Compare expected public fixture values, not only two implementations of
  the same computation. A modified input file has no effect on a running source;
  restart adopts valid changed provided material.
- Isolation: JCA/Nimbus and TempDir; no external services or keytool signing fixtures.

### 2. `providedPemRejectsInvalidMaterialWithoutFallbackOrDisclosure`

- Type/location: same core unit file; table-driven loop or parameterized cases
  using existing test dependencies.
- Inputs: encrypted-label PEM, PKCS#1 RSA-label, public key, certificate alone,
  valid key plus certificate/public block (before and after), two key blocks,
  non-whitespace prefix/suffix, empty/missing body, corrupt Base64/embedded junk,
  malformed DER, valid DER plus trailing bytes, truncated DER, EC PKCS#8,
  RSA 1024-bit PKCS#8 and nonexistent private input. Use actual JCA-generated weak
  and EC material so failure establishes algorithm/strength rather than label alone.
- Proves: startup throws, exception has no parser/provider cause/private marker,
  existing public export remains byte-for-byte prior content and no generated
  fallback/public/temp artifact appears. Encrypted fixture need not contain real
  secret material; all material is synthetic.

### 3. `explicitModesAndRequiredPathsRemainStrict`

- Type/location: core SigningKeysTest plus Spring context test below.
- Inputs: absent/unknown mode, null provided record, each missing provided path,
  missing colocated directory, provided paths in colocated mode and colocated path
  in provided mode.
- Proves: safe actionable failure; SDK creates no directories or private material.
  Existing colocated two-start test still requires distinct kid and only jwks.json.

### 4. `atomicExportFailureAndInputAliasesNeverDestroyMaterial`

- Type/location: core SigningKeysTest using retained FileOperations seam.
- Inputs: missing export parent, directory destination, temp creation failure,
  write denial, move denial and AtomicMoveNotSupportedException. Assert only
  ATOMIC_MOVE + REPLACE_EXISTING, one attempted publication and no retry/fallback.
- Collisions: literal input path, normalized dot path and an existing hard link
  created with Files.createLink; add symlink coverage when available without
  silently losing the hard-link assertion on Windows. Keep link tests independently
  scoped so a missing symlink privilege cannot bypass other collision cases.
- Proves: private input/prior export unchanged; no SDK-created parent or stale temp;
  safe errors and initialization never succeeds. Cover both modes through shared
  publication path and at least one provided failure with real valid private input.

### 5. `minimalProvidedStartupAndObsoleteSigningPropertiesFailSafely`

- Type/location: Boot context,
  `sdks/java/spring-boot-starter/src/test/java/ai/loomspan/sdk/spring/ExecutionTokenAutoConfigurationTest.java`.
- Positive: only explicit mode/key-location/jwks-export, valid PEM. Require correct
  SigningKeySource/public export, startup restart identity and preserved defaults.
- Negative: each of `format`, `key-alias`, `keystore-password-reference`,
  `key-password-reference`, `certificate-location`, `keystore-password`,
  `key-password`; include empty values, provided and colocated modes, representative
  camelCase and SystemEnvironmentPropertySource uppercase underscore names.
- Assert fixed actionable property names, no unique secret-value marker in captured
  output/full exception chain, no parser cause and no export. Values deliberately
  include non-secret synthetic marker strings that must remain absent.
- Core handles exhaustive material categories; Spring adds representative bad
  envelope, weak/non-RSA/missing input to prove real loader startup delegation,
  along with every missing/mixed settings category. Do not duplicate every core
  mutation through a full Spring context.
