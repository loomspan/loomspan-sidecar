# Durable Configuration Snapshot Storage Testing Plan

## Change Summary

Introduce a real file-backed SQLite store for complete authored skill YAML and one authored REST YAML document. V1 Flyway migration creates durable snapshot, document, status and current-state tables; Spring JDBC transactions write complete records and initialize a new store. The runtime still uses mounted files until Phase 2, so this step proves storage behavior, not startup activation or request routing.

## Impacted Areas and Risks

| Category | Risk | Planned evidence |
| --- | --- | --- |
| Authored content | REST parsing/reserialization resolves `${NAME}` or changes literal secrets; skill labels/order get lost | Close/reopen real SQLite round trip comparing exact strings, labels and order |
| Snapshot integrity | Caller mutates a list or status update changes content; import/copy reuses ID | Defensive-copy and repeated-insert tests with source provenance |
| Schema and initialization | Partial first snapshot, accidental reseed or silent recovery of corrupt pointer | Fresh/reopen and forced transaction rollback; direct database corruption then startup rejection |
| Migration | Writes occur before migration or unsupported/corrupt history is ignored | Fresh V1 migration and deliberately invalid Flyway history/startup failure |
| SQLite operation | PRAGMAs not set on every connection; lock waits forever or WAL side files cannot be created | Read effective PRAGMAs, reopen from disk, finite writer-contention test |
| Deployment/reference | Non-root image has no writable persistent path; docs misstate live behavior | Configuration-reference and example assertions, README review |
| Framework boundary | Storage pulls unsupported Loomspan packages | Existing ArchUnit rule across application and test classes |

## Existing Coverage and Environment Constraints

There are no current SQLite, Flyway or persistence tests. `RestRouteLoaderTest` covers mounted route parsing and placeholder resolution; it must not be used as proof of authored storage. `LoomspanSidecarApplicationTest`, `RestRouteRestartIntegrationTest` and other context tests exercise the legacy mounted runtime and may need Phase 2 integration before broad `verify` passes. `ConfigurationReferenceTest` asserts README settings and sample paths. `SupportedLoomspanApiArchitectureTest` forbids `ai.loomspan.internal..` and `ai.loomspan.autoconfigure..`. Maven wrapper and JUnit 5/AssertJ are established; `.\mvnw.cmd -B -ntp verify` is the repository command. Tests use `@TempDir`, local files and no external services or credentials. The developer-installed beta 5 snapshot must stay the framework dependency; no framework build is part of this test plan.

## Failing Test First

- Name: `reopensCompleteAuthoredSnapshotWithoutChangingEitherHalf`
- Type: Spring JDBC repository integration against real SQLite file
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`
- Arrange/Act/Assert: Create one temp database, migrate it, write two named `SkillDocument` instances plus REST YAML containing `base-url: ${CUSTOMER_API_URL}` and a literal header secret; close the datasource/store, reopen the same path, and compare exact text, document order, local/source IDs and pending status.
- Expected pre-fix failure: the repository/storage API does not exist, so the test fails to compile. After its first minimal skeleton, it fails at persistence/reopen until the SQLite implementation is present.

## Tests to Add or Update

### 1. `reopensCompleteAuthoredSnapshotWithoutChangingEitherHalf`
- Type: real SQLite repository integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`
- Proves: complete snapshot persists, with original skill/REST text, labels and order.
- Inputs/fixture: inline model-backed and REST YAML; authored REST YAML with `${CUSTOMER_API_URL}`, comments and a literal sensitive header sentinel. Compare bytes/Java strings exactly, without parsing and reserializing.
- Doubles or boundary isolation: temporary file; separate database connections/datasource lifetimes; no HTTP or model calls.
- Edge cases: empty skill collection with canonical `targets: {}\nroutes: {}\n` REST text; `.yaml` and `.yml` labels and case-distinct labels.

### 2. `rejectsInvalidDocumentLabelsAndNullContent`
- Type: value-object/repository integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`
- Proves: null collection, element, YAML or REST document and blank/exact duplicate labels fail before partial persistence; SQL constraints also reject invalid direct writes where applicable.
- Inputs/fixture: null/blank/duplicate variants, including case-distinct nonduplicate labels.
- Doubles or boundary isolation: temp SQLite file for persistence-side checks.
- Edge cases: empty YAML string remains allowed because only null YAML is forbidden; empty document list is allowed.

### 3. `allocatesFreshLocalIdentityAndKeepsContentImmutable`
- Type: real SQLite repository integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotRepositoryTest.java`
- Proves: repeated saves of identical content have distinct local UUIDs and increasing sequence; source UUID is retained independently; modifying caller-owned collections after save and changing pending status to failed/published do not alter stored content.
- Inputs/fixture: mutable input list, same source UUID on two saves, original and subsequent status values.
- Doubles or boundary isolation: temp SQLite file; no runtime generation identity or framework internals.
- Edge cases: read result cannot expose a mutable backing list; invalid status value is rejected by schema.

### 4. `freshStoreInitializesExactlyOnceAndReopenPreservesCurrent`
- Type: real SQLite store integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`
- Proves: Flyway V1 and app init create exactly one pending empty snapshot and current pointer; no runtime-published status; reopened store keeps same ID and count.
- Inputs/fixture: new temp path, then same path after close/reopen.
- Doubles or boundary isolation: local SQLite database.
- Edge cases: `targets: {}\nroutes: {}\n`, zero skill rows, initialized flag 1, migration history present.

### 5. `rejectsCorruptInitializedOrHalfInitializedState`
- Type: real SQLite store integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`
- Proves: missing current pointer/snapshot or uninitialized marker with stray rows fails instead of seeding a new installation.
- Inputs/fixture: mutate each state through direct test JDBC after normal initialization or migration.
- Doubles or boundary isolation: temporary database; disable foreign keys only on the test corruption connection where necessary, never in production.
- Edge cases: a clean uninitialized singleton with no content may retry initialization after a rolled-back attempt.

### 6. `rollsBackIncompleteSnapshotAndInitialPointer`
- Type: real SQLite transaction integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`
- Proves: a forced failure after the snapshot header or first skill row leaves no status/documents/snapshot/pointer; a later valid attempt succeeds exactly once.
- Inputs/fixture: two documents, with the second causing a database constraint failure (or a narrow injected failure at the repository boundary) inside the same Spring transaction.
- Doubles or boundary isolation: use actual SQLite transaction, inspect all four tables on a new connection.
- Edge cases: first-store initialization rollback must leave the uninitialized marker and null pointer.

### 7. `migrationFailurePreventsRepositoryUse`
- Type: Flyway/SQLite startup integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`
- Proves: one migration path completes before reads/writes and refuses a mismatched V1 checksum or otherwise invalid migration history.
- Inputs/fixture: temp SQLite file with V1 history changed through direct test JDBC; fresh file for successful migration.
- Doubles or boundary isolation: no external migration service. V1 is the only explicitly supported schema, so no synthetic upgrade preservation test is planned.
- Edge cases: an existing initialized store with missing table/current row does not look like a fresh installation.

### 8. `appliesDurabilityPragmasAndTimesOutOnWriteContention`
- Type: real SQLite connection/transaction integration
- Location: `src/test/java/ai/loomspan/sidecar/storage/ConfigurationSnapshotStoreTest.java`
- Proves: foreign keys ON, WAL journal, FULL synchronous and 5000 ms busy timeout on effective connections; a held write transaction makes a competing write fail within a bounded interval without partial content, then succeed once released.
- Inputs/fixture: two independent connections to same temp file and latch-controlled lock holder.
- Doubles or boundary isolation: local filesystem only; use a generous upper timing bound to avoid brittle exact-millisecond assertions.
- Edge cases: close/reopen persists content and WAL is available; if temp filesystem cannot support WAL, report environmental failure rather than silently downgrading.

### 9. `configurationReferenceMatchesBoundPropertiesAndExamples`
- Type: existing documentation/configuration test update
- Location: `src/test/java/ai/loomspan/sidecar/config/ConfigurationReferenceTest.java`
- Proves: README lists `loomspan-sidecar.storage.database-path` once with default, writable directory and startup constraints; quickstart/Kubernetes examples mount a writable persistent data path while retaining still-required legacy runtime mounts.
- Inputs/fixture: README and sample YAML files.
- Doubles or boundary isolation: file inspection only.
- Edge cases: no assertion that old read-only configuration files are imported into SQLite.

### 10. `sidecarCodeAndTestsDependOnlyOnSupportedLoomspanPackages`
- Type: existing ArchUnit regression
- Location: `src/test/java/ai/loomspan/sidecar/architecture/SupportedLoomspanApiArchitectureTest.java`
- Proves: new storage code/tests use no unsupported framework type; Java `@SkillMethod` prohibition remains active.
- Inputs/fixture: compiled Sidecar application/test classes.
- Doubles or boundary isolation: no services.
- Edge cases: none beyond existing rule coverage.

## Safe Verification Commands

- Full safe suite: `.\mvnw.cmd -B -ntp verify` — run and report concrete failures. Legacy startup tests may remain blocked until Phase 2; do not label them passing or add bridging code solely for this ticket.
