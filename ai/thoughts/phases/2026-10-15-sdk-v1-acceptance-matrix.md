[design lens](../design-lens.md#simplicity-and-technical-debt). No data reset is needed.

unit names are planned ownership boundaries, not issued implementation tickets or

`C:/opendev/code/loomspan-sidecar-test-suite`; **Framework** is

## Shared evidence rules, execution tiers and closure

Full malformed claim/cnf/DNS/export-path/preset permutations run at owning component
boundaries with real keys/validators; repeat wrong-purpose/bound/authorization and
applicable trust/peer negative samples in every actual primary composition above.
Both callback-chain arrangements run every CALLBACK row; each composition records
its arrangement, with both arrangements represented per transport/path/topology
using strategy variants. Arrangement implementation is shared across credential
strategies after JWT validation; component proof plus those composed boundary cases
avoids an unnecessary full multiplication while preserving session instrumentation.
Independent upload/URL/application-hosted/separately-hosted trust and file/database
bootstrap evidence remain mandatory source variants, not an all-composition product.

Use [exact planned commands and evidence schema](2026-10-15-sdk-v1-deployment-recipes.md#exact-future-local-commands-and-evidence-tiers).
Focused SDK `mvn -f sdks/java/pom.xml verify` and root `mvn verify` remain separate.
Suite runner tiers: focused for API/fault fixture feedback, composition for every
72-row topology/configuration case, lifecycle for P3 variants, release for all
required local evidence plus P4 consumers/security/restoration. `--scenario <ID>`
selects every required variant of that ID, never one convenient happy path. The
matrix manifest enumerates prior source parameter lists, composition assertions,
versions and required evidence; missing/unrun required local variants fail readiness.
Evidence includes full unit test paths from registry, exact command/config/revisions,
safe per-layer attempts/effects and measured gates. No container runs during this
documentation ticket and no Framework-only test result is accepted as Sidecar evidence.

P1 owns the harness agreement update before implementation, all initial security
enforcement/denial/persistence and initial API/no-retry proof. P2 owns group issuer/
member integration; P3 owns lifecycle mechanisms, races and faults, not just tests
of assumed behavior. P4 requires all prior planned rows locally passing, clean
consumer packaging and documentation, closure of temporary breakage and independent
security-focused review, then separately authorized publication/hosted checks.
Manual external rows record UNVERIFIED/NOT_RUN until separately authorized; they
limit only those compatibility claims and do not gate deterministic local release.
