# Export current configuration as a portable, integrity-checked bundle

## Outcome

Users can download the complete configuration currently running on this server
for backup or promotion from development to QA to production. The bundle carries
configuration, never another server's history or installation identity.

## Requirements

- Provide protected export through the embedded console and management API for
  viewers, editors and admins. Capture the runtime-published snapshot at export
  start and retain that immutable content through concurrent publication/pruning.
  Never export the intended database pointer as a substitute for runtime state.
  Export an active empty configuration faithfully; if no runtime snapshot exists,
  explain that export is unavailable rather than inventing one.
- Export only current published configuration. No all/history/private-draft mode.
  Include every authored skill YAML document, its source label, and complete REST
  routes/targets. Preserve YAML text, sensitive literals and placeholders without
  resolving, rewriting, redacting or encrypting them. Exclude accounts, sessions,
  leases, private drafts, history and deployment settings, including URL allowlists
  and environment values, SMTP, model connections and SSL bundles.
- Define format 1 as a ZIP containing UTF-8 `manifest.json`, `rest.json` and
  individual UTF-8 YAML payloads under `skills/`. The manifest records integer
  `formatVersion: 1`, source snapshot identity, informational producer Sidecar and
  framework versions, and the complete payload inventory with SHA-256 digests.
  Map skill payload entries to original source labels in the manifest; use safe
  generated archive names rather than interpreting labels as filesystem paths.
  `rest.json` carries the complete authored REST configuration. Specify exact field
  names and JSON schemas during planning and document them with format fixtures.
  Source identity is provenance only; omit source publication-status/history data.
- Supply a reusable, non-mutating bundle reader for the next ticket. Require the
  supported format, complete unambiguous inventory, matching digests and structurally
  valid payloads. Reject duplicate entries/source labels, missing or unexpected
  payloads, unsafe paths, corrupt/encrypted archives and unsupported versions.
  Integrity checks detect corruption, not authenticity; no signing infrastructure.
  Do not extract arbitrary archive paths or execute content. Destination framework
  validation and activation belong to PR 1.5.2, not the bundle parser.
- Use generous fixed v1 bounds: 100 MiB ZIP input, 512 MiB total expanded entry
  content and 10,000 ZIP entries. MiB means 1,048,576 bytes; boundaries are inclusive.
  Enforce actual bytes consumed, not only claimed ZIP metadata. Apply matching
  format bounds on export so successful exports are eligible for the v1 reader;
  explain oversize exports rather than returning a purportedly valid partial bundle.
  Avoid unnecessary whole-archive duplication or unbounded decompression. No extra
  user-facing tuning settings are required in v1.
- Keep authorization server-enforced, execution JWT permissions separate, and
  existing session-idle/CSRF rules intact. Export does not acquire/renew an editing
  lease or modify drafts/configuration. Show a concise notice that downloads can
  contain sensitive values. Supply browser verification, format/parser tests and
  user documentation in this ticket.

## Acceptance criteria

- [ ] Authenticated viewers/editors/admins download the exact runtime snapshot,
  including an empty active configuration; unauthorized requests are rejected.
  Concurrent publication/pruning cannot mix identities and payloads; absence of
  runtime state is explicit. Export leaves editing and execution state unchanged.
- [ ] Round-trip fixtures preserve complete YAML text/source labels, REST content,
  sensitive literals and unresolved placeholders, while excluding installation,
  private-draft and historical data. Metadata and exact format 1 layout are documented.
- [ ] The reader rejects corrupt, unsupported, ambiguous, incomplete, unsafe and
  checksum-mismatched bundles without state changes or unsafe filesystem writes.
  Informational application/framework versions do not determine format compatibility.
- [ ] Compressed/expanded/entry-count boundary checks cover allowed and excessive
  values, including misleading ZIP metadata; oversize exports fail clearly. A
  representative large configuration exercises the generous limits without an
  artificial smaller request/parser bottleneck in the delivered export path.
- [ ] Console download, sensitive-content notice, session/role behavior and safe
  errors are verified. Documentation explains configuration-only backup, integrity
  versus authenticity and limits; no import or rollback action is introduced yet.
