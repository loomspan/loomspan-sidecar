# Represent isolated configuration drafts and frozen candidates

## Outcome

Sidecar can edit an isolated complete configuration copy, associate validation with
its exact content, and freeze a candidate without changing its source snapshot.
This supplies the draft model for later session-owned management editing.

## Requirements

- Use PR 1.1.1's complete authored-content boundary for drafts and immutable
  candidate copies. Construct each draft from a supplied runtime-published snapshot
  and retain its durable base identity. Do not discover the base by reading the
  SQLite intended-production pointer or copying another user's draft. Phase 2/3
  integration supplies the authoritative runtime snapshot.
- Preserve complete named YAML, REST configuration, literal values and unresolved
  references. Allow temporarily invalid authored YAML while editing; validation is
  explicit and remains the framework's responsibility. Editing a draft must not
  mutate its source snapshot, another draft or an already frozen candidate.
- Associate validation with the exact immutable authored content submitted for
  validation. Edits invalidate the result; a late result for old content must not
  validate newer edits. Retain source-labelled errors and available locations.
  Implement content/result association only, not a YAML validator, validation
  executor, framework preparation cache or HTTP client cache.
- Provide an immutable content copy for validation/publication. Later edits or
  dropping the draft cannot change that copy. Freezing content does not itself
  authorize publication or start a runtime update.
- Keep draft state ephemeral and separate from stored submitted snapshots. Add no
  SQLite draft persistence, session registry, draft manager with its own ownership
  tracking, lease timers, event bus or publication synchronization mechanism.
  Phase 3 will place drafts under real server-session ownership and coordinate
  lifecycle operations with the actual lease and publication services.
- Implement the smallest internal model and operations needed for these behaviors.
  Do not prebuild lifecycle callback interfaces for future integrations. Concrete
  representation and content comparison are planning choices. Document the later
  obligations below without claiming they are enforced by this model alone.

## Acceptance criteria

- [ ] Tests prove independent complete drafts from the same source snapshot and
  exact authored-content preservation, including invalid YAML and placeholders.
  Editing either draft cannot mutate the source or the other draft.
- [ ] The draft retains the supplied runtime snapshot identity as its base; it has
  no dependency on the intended-production pointer or history/retention operations.
- [ ] Edits invalidate validation, and a result associated with older content cannot
  validate newer edits. Source labels and available error locations are preserved.
- [ ] Frozen candidate content is unchanged after later draft edits or discarding
  the draft reference. Freezing does not perform persistence or runtime publication.
- [ ] The model adds no recoverable draft persistence, session/lease registry,
  framework preparation resources or independent coordination subsystem.
- [ ] Documentation identifies the draft model's guarantees and explicitly assigns
  session privacy, lifecycle enforcement and concurrency verification to the later
  integrations below. Model tests do not claim end-to-end management behavior.

### Required later integration

These are retained roadmap requirements assigned to later phases, not additional
Phase 1 implementation or acceptance criteria:

- **Phase 3 — ownership and lifecycle:** Drafts and validation results are private
  to the owning server session, even against administrators and other sessions of
  the same user. No cross-session or process-restart recovery. Logout/session expiry
  clears drafts; lease expiry/release preserves a draft while its session and base
  remain valid. Resuming requires lease reacquisition and an unchanged runtime base.
  Discard clears the draft and releases ownership. Admin takeover starts from
  production; the former owner keeps its private draft only while session/base
  remain valid. One instance-wide editing lease and one writable tab per session
  are enforced using actual session/tab authorization, not caller-supplied usernames.
- **Phases 2/3 — publication coordination:** Successful framework publication
  invalidates prior-base drafts and cancels leases in coordination with draft
  creation/edits so stale state cannot escape. Pointer commit/reversion alone and
  ordinary publication failure preserve valid drafts. Coordinate this in the real
  management/publication services; do not pause execution dispatch or add a second
  ownership system. Phase 3 owns integrated draft/lease concurrency verification.
- **Phase 2 — validation and accepted updates:** Validate prepares then releases
  temporary resources; Publish requires successful validation of exact frozen content
  and prepares/stages afresh. Serialize acceptance through completion. Once accepted,
  logout, expiry, takeover, account changes, disconnect or discard cannot cancel or
  modify the update. No cancel operation or durable job service. Verify actual
  execution isolation and publication behavior against the public framework API.
- **Phase 5 with Phases 2/3 — destructive transfer:** Validate/stage before clearing
  all drafts. Failure before cutover leaves drafts intact; after cutover they stay
  discarded even if activation fails. Confirmation binds to the specific lease grant
  and runtime snapshot; coordinate competing edits through completion. Clearing a
  private draft must never delete immutable submitted history, including pending
  and failed attempts. Verify these behaviors through the real transfer path.
- **Phases 3/4 — editing defaults:** Phase 3 owns the `15m`
  `loomspan-sidecar.management.edit-lease-timeout` and `30m`
  `loomspan-sidecar.management.session-idle-timeout`. Phase 4 supplies activity-based
  renewal at most every 30 seconds and a two-minute warning. Background polling
  must not keep an idle login alive; mouse movement or an open tab alone does not
  renew editing. Browser checks include preservation of local editor text on lease
  loss subject to session/base invalidation, while stale writes remain rejected.

Only `ai.loomspan.api` framework Java types may be used in production/tests, retaining
ArchUnit checks against internal/autoconfigure dependencies. Use the developer's
installed beta 5 snapshot and matching local framework documentation for any API
integration. No framework rebuild, snapshot repository, release or tag; hosted CI
awaits published beta 5.
