# Keep configuration drafts private and enforce exclusive editing ownership

## Outcome

Each management session edits its own unpublished configuration while one explicit,
expiring lease controls writes across users and browser tabs. Losing a lease cannot
expose another user's draft or permit stale writes, and background refresh cannot
keep an unattended session or editor alive indefinitely.

## Requirements

- Build on PR 1.3.1's real authenticated server sessions and Phase 1's draft model.
  Keep drafts and their validation results private to their owning session, including
  against admins and other sessions of the same account. No durable drafts, shared
  cross-user draft, cross-session recovery or second identity system.
- Create drafts from the complete runtime-published snapshot and its durable ID,
  never the SQLite intended-production pointer or another user's content. Coordinate
  capture with publication/history pruning so it cannot select stale/missing content.
  Preserve complete authored YAML/REST text, including temporarily invalid content,
  placeholders and literal values. Saving never validates or activates implicitly.
- One instance-wide editing lease and one writable tab per session. Enforce role,
  session, tab and current grant ownership server-side on each write. Viewer sessions
  cannot author or acquire write ownership. A second tab can read its own session's
  draft but cannot silently take ownership; unrelated sessions see ownership/status
  information only. Never trust caller-supplied account identity.
- Assign a distinct identity to every new lease grant, including reacquisition by
  the same account/session/tab. Renewal preserves that grant identity. Expose enough
  ownership/expiry information for the later UI and Phase 5 destructive confirmation,
  without disclosing draft text or validation results to others.
- Implement acquisition, renewal, explicit release, discard and admin takeover.
  A conflicting acquisition/write returns a clear conflict without altering content
  or ownership. Admin takeover revokes the old grant and starts from production;
  it never inherits the previous owner's draft. The former owner retains its own
  draft only while its session and runtime base remain valid.
- Use positive `loomspan-sidecar.management.edit-lease-timeout`, default `15m`.
  Only meaningful user activity renews editing: typing, paste, clicks, scrolling or
  explicit Continue editing. Mouse movement, automatic validation/status polling
  and leaving a tab open are not activity. Support activity reports no more often
  than every 30 seconds and expose expiry for the Phase 4 two-minute warning.
  Server expiry/ownership checks remain authoritative.
- Integrate with the `30m` management session-idle timeout from PR 1.3.1. Background
  requests must not extend effective login lifetime; editor activity reports can.
  An expired login cannot be revived by a late activity report. No separate durable
  scheduler or distributed lease service is needed for this single-instance design.
- Logout, login expiry and account-triggered session invalidation clear that session's
  draft and release its lease. Lease expiry or explicit release preserves its draft
  while the session/base remain valid; resumption requires reacquisition and an
  unchanged runtime base. Discard clears draft and lease. Restart clears all session
  editing state. Do not return stale private draft content after invalidation.
- Any edit invalidates prior validation, including equal-content replacements.
  Associate results with the exact candidate so late validation cannot validate a
  newer edit. Expose sufficient draft identity/state for PR 1.3.3 responses and the
  UI to recognize stale results. Do not add a cross-user revision scheme.
- Join the concrete Phase 2 publication coordinator's synchronization. Actual
  successful framework publication invalidates prior-base drafts and cancels leases
  in a short coordinated transition; no stale creation, write or renewal can escape.
  This must also happen when status recording subsequently fails and `publish()`
  throws. Pointer commit/reversion and ordinary rejected publication do not invalidate
  drafts or cancel valid leases. Other sessions may edit the old base during candidate
  preparation; do not hold a global editing lock for the entire preparation or pause
  execution dispatch. Refactor the real coordinator as needed, without a duplicate
  runtime state owner or speculative lifecycle framework.
- Configuration fault state rejects draft-content mutation, new editing ownership
  and renewal that would imply editing remains available. Preserve inspection and
  permit logout/release/discard to clean up private state. All editing lifecycle
  actions remain unable to cancel an already accepted frozen publication.
- Expose protected, CSRF-safe draft/lease operations and state suitable for the later
  console; document their contracts. Enforce privacy and authorization in real HTTP
  tests. Validation execution, configuration history and Publish endpoints belong to
  PR 1.3.3. Do not implement import/rollback or browser UI here.

## Acceptance criteria

- [x] Tests with real management sessions prove private drafts/validation across users,
  admins and multiple sessions of one account. One writable tab and one instance
  lease are enforced; stale session/tab/grant writes cannot modify content.
- [x] Draft creation uses runtime A while SQLite intends B, remains consistent across
  concurrent publication/pruning, and preserves complete authored content. Saves do
  not activate execution; edits and late validation results obey exact-candidate rules.
- [x] Acquisition, contention, renewal, expiry, release, resume, discard and admin
  takeover produce the specified ownership/content outcomes. Replacement grants
  receive fresh identities; renewal does not. No takeover inherits another draft.
- [x] Controlled-clock/session tests prove activity-based `15m` lease and `30m` login
  expiry, including ongoing polling and automatic validation traffic. Late requests
  cannot revive expired ownership; valid activity can renew while ownership remains.
- [x] Logout, account/session invalidation and restart clear the correct private state.
  Lease expiry/release alone preserves eligible drafts, and changed runtime bases
  prevent resumption and disclosure of invalidated draft content.
- [x] Real Sidecar publication integration proves atomic successful invalidation versus
  competing creation/edit/renewal, including publication followed by bookkeeping
  failure. Ordinary publish failure/reversion preserves valid drafts and leases.
  Editing during preparation and execution dispatch continue as specified.
- [x] Faulted configuration rejects further editing while allowing inspection and
  cleanup. Lease loss, logout or takeover does not cancel an accepted frozen update.
- [x] Protected API tests cover hierarchy, CSRF, privacy, stale conflicts and ownership
  status without content leaks. Documentation records lifecycle/defaults and clearly
  assigns the remaining Publish admission checks to PR 1.3.3 and browser UX to Phase 4.
