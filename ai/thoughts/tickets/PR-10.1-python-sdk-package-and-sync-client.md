# PR 10.1: Discover and execute Sidecar skills from an installed synchronous Python SDK

## Development constraints

**Sidecar is still in development. Destructively replace superseded contracts,
code and schemas; no compatibility shims, legacy adapters, parallel legacy APIs
or migration machinery solely to preserve obsolete development behavior.**

Apply the [design lens](../design-lens.md#simplicity-and-technical-debt). Choose the
simplest complete solution and minimize technical debt. Keep implementation,
tests and documentation proportional. No data reset is expected; preserve existing
credentials, identities, operational data and reference packs. Document any newly
required development-data reset and its impact; this is not permission to delete
deployed data or regenerate operator keys.

## Outcome

Deliver an independently installable Python SDK that plain Python applications can
use with an existing credential to discover skills, submit work, inspect status and
wait for completion. Establish the shared public models and protocol behavior used
by the later async and FastAPI tickets.

## Requirements

- Create `loomspan-sdk` / `loomspan_sdk` under `sdks/python` with `src` layout,
  standard pyproject metadata, wheel/sdist, typed public objects and `py.typed`.
  Start at `0.1.0.dev0`; versions advance independently of Java/Sidecar/Framework.
  Set `requires-python = ">=3.12"`. Core must install/import without FastAPI,
  Starlette, an ASGI server or a repository checkout at runtime.
- Provide synchronous list/get skills, submit, get execution and wait operations,
  using current Java observable behavior/defaults. Accept explicit per-call opaque
  credentials; reject empty/whitespace/control/non-ASCII transport values and hide
  token bytes from default output, serialization and SDK exception chains.
- Preserve all Java public descriptor/status/failure/event fields, schema strings,
  optional configuration identity and absent versus empty history. Copy mutable
  nested data. Preserve result text exactly; FAILED is a terminal result, not an
  automatic exception. Reject malformed required envelopes, mismatched IDs,
  duplicate JSON fields and trailing JSON tokens; tolerate additive fields.
- Require valid absolute HTTP(S) base URLs without userinfo/query/fragment, preserve
  base paths, safely encode accepted skill names as one segment and reject Java's
  prohibited forms. Build status URLs locally; never follow Location. Submit only
  JSON objects; accept an ID only from a complete valid 202 body; reads require 200.
- Retain 2-second connect, 10-second total response, 8 MiB response size, and per-wait
  60-second/250 ms defaults with positive finite validation. Bound streamed bytes
  and the complete HTTP exchange/body, including stalled or trickling responses.
  Each wait read is bounded by the remaining wait budget. Prove a real synchronous
  deadline that stops underlying I/O; a caller thread timeout alone is insufficient.
- One attempt per HTTP operation; disable retries, redirects, auth rechallenge,
  cookie persistence and automatic compression negotiation/decompression. No shared
  user Authorization defaults. TLS verifies certificates/hostnames using ordinary
  SSL contexts, including private CA/client identity; no insecure convenience flag.
- Distinguish local pre-send failures, known HTTP failures, protocol failures and
  acceptance uncertainty after possible submission. Preserve observed HTTP error
  status even when its body is unusable/oversized. Expose only bounded valid problem
  objects with credential redaction, not raw error bodies or parser diagnostics.
  Never infer an execution ID or resubmit. Poll only successful nonterminal reads
  and stop on the first read failure.
- SDK wait errors retain requested ID/last valid snapshot; standalone status errors
  retain requested ID. Native KeyboardInterrupt propagates with cleanup. No WaitState
  or interruption adapter. Local wait termination/close never cancels remote work.
  Context-managed close is idempotent, rejects new calls, and releases incomplete
  responses without unbounded draining.
- Share protocol/models internally with the forthcoming async client. No private
  event loop in the sync API, transport plugin registry, business-schema compiler,
  settings framework or SDK YAML/environment binding. HTTPX is a candidate only;
  choose the smallest transport satisfying the contract during planning.
- Own focused tests, core usage documentation and installed-package examples.
  Declare direct dependencies with tested ranges and pin development/test tooling.
  Begin the agreed CPython/platform checks for implemented scope; PR 10.6 owns
  final combined coverage, not retroactive proof for this unit.

## Acceptance criteria

- [ ] Wheel and sdist build/install outside the checkout; typed core imports and
  existing-credential usage work without web packages, signer or Sidecar internals.
- [ ] Discovery/submission/status/wait preserve Java public fields, result fidelity,
  validation and default semantics, including FAILED and optional diagnostics.
- [ ] Slow/stalled/streamed/oversized responses demonstrate actual deadline/body
  bounds, resource release, no replay, known-status preservation and uncertainty.
- [ ] Concurrent callers keep credentials isolated; URL/TLS/cookie/redirect and
  safe-output checks establish the required transport boundaries.
- [ ] Wait errors carry context; interruption and repeated close clean up without
  remote cancellation; the client remains usable after recoverable request errors.
- [ ] Focused tests, installed examples and current-behavior docs pass independent
  review; selected dependencies and any platform checks deferred to 10.6 are explicit.
