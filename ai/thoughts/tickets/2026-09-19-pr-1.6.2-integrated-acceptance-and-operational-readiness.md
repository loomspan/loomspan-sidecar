# Prove the complete Compose workflow and operational recovery

## Outcome

Operators and maintainers have reproducible evidence that the complete v1 console,
durable configuration and existing execution service work together in the supported
Compose deployment, including interruption and recovery. Beta 5 readiness is grounded
in Sidecar integration evidence with outstanding release gates stated accurately.

## Requirements

- Exercise the real browser, Sidecar application and container deployment from
  PR 1.6.1. Use controlled JWT/model/REST fixtures and a local SMTP capture service
  for deterministic integration/end-to-end checks. Capture email only in the test
  environment; do not send to real recipients or include the capture service in
  the product runtime image or production Compose configuration. Planning owns
  the tooling and test organization; avoid a new general-purpose test platform.
- Demonstrate first administrator setup through the emailed link, management login,
  invitation and email-only password recovery, with the documented production TLS
  arrangement and trusted link URL. Verify existing login/execution availability
  during mail unavailability and management-lock isolation from execution on an
  uninitialized installation without a usable setup credential.
- Cover the complete author/save/validate/publish workflow and authenticated skill
  execution, including both REST and model-backed YAML skills. Exercise concurrent
  browser sessions and editing ownership, private drafts, stale writes/confirmation,
  and successful publication's draft/lease invalidation. Management roles and CSRF
  remain enforced independently from execution JWT authorization.
- Demonstrate current-configuration export/import between two independently stored
  instances, preserving authored YAML, route mappings and URL placeholders while
  each destination resolves its own allowed environment values. Validate before
  destructive cutover; invalid bundles/bindings preserve active configuration and
  drafts. Successful import uses a fresh local identity and discards drafts under
  the existing confirmation policy. Exercise local retained-history rollback as a
  newly validated publication, not a pointer change or transferred source history.
- Exercise persistent container recreation, process interruption around the committed
  pointer/publication boundary, and shutdown while execution/update work is active.
  Prove startup activates the committed selection before dispatch, load/activation
  errors fail startup, accepted updates are not cancelled by browser disconnect or
  logout, and admitted execution retains matching generation resources through the
  existing shutdown completion/cutoff. Do not invent crash guarantees beyond the
  agreed database-first policy or add a second shutdown budget.
- Perform the documented stopped-instance full database backup/restore in the Compose
  deployment. Verify the SQLite file set, volume ownership, recovered accounts and
  managed configuration, committed-pointer activation and post-restore inspection.
  Demonstrate the operator route for an unusable installation or unreverted
  publication fault without introducing automatic reconciliation, online backup or
  an account-reset bypass. Configuration ZIPs, retained-history rollback and full
  database recovery retain their distinct scope and sensitive-data handling.
- Consolidate operator guidance and Phase 6 acceptance evidence in existing repository
  documentation/report conventions. Reuse relevant earlier ticket evidence for
  focused correctness checks, identify and finish checks previously deferred to
  integrated deployment, and record actual new cross-feature/deployment outcomes.
  Fix discovered defects within the agreed behavior and supply affected regressions;
  do not count framework-only tests as Sidecar proof or turn this phase into a
  redesign of settled contracts.
- Complete local integration readiness against the developer-installed beta 5 snapshot
  before final framework release checks. Record the remaining release gate explicitly:
  publish framework beta 5 first, then switch Sidecar's framework dependency to
  `1.0.0-beta.5` for its final build/tests and final commit; hosted CI resolves the
  published artifact and must be verified before Sidecar release. Do not claim those
  deferred checks passed. This ticket does not authorize publication, release tags
  or executing that dependency switch before the framework release workflow permits it.

## Acceptance criteria

- [x] Reproducible real browser/application/container exercises cover emailed setup,
  invitations, recovery, HTTPS login and trusted links using captured test mail;
  mail failure and missing setup credentials preserve the agreed execution/login
  availability. No real email recipients or production capture service are used.
- [x] Integrated authoring/publication and REST/model-backed execution succeed;
  concurrent sessions preserve ownership/privacy, reject stale operations and enforce
  roles/CSRF separately from JWT execution. Successful publication invalidates stale
  drafts/leases, and disconnect/logout cannot cancel an accepted update.
- [x] Two-instance round trips preserve authored configuration and resolve placeholders
  to each instance's destination. Invalid imports/bindings leave editing/active state
  intact; confirmed import and local rollback produce fresh local snapshots and the
  documented draft loss without importing history.
- [x] Container recreation and interruption evidence establishes durable selection,
  restoration before dispatch and startup failure on invalid selected state. Active
  work/publication/shutdown interaction preserves captured generations, resource
  lifetime and the existing bounded shutdown policy.
- [x] Following the Compose backup/recovery guide restores a usable installation with
  correct database files, permissions, accounts and selected configuration, including
  recovery from the documented fault/unusable-state scenario. The guide distinguishes
  full recovery, ZIP transfer and local rollback without new recovery mechanisms.
- [x] Earlier deferred integrated checks are accounted for and completed; relevant
  Sidecar regressions and new deployment checks pass against the installed snapshot.
  Evidence states what ran and its outcome, and operator guidance matches the verified
  deployment. Any failures prevent an integrated-readiness claim.
- [x] Readiness documentation distinguishes completed local acceptance from the pending
  published-framework dependency switch, final build/tests/commit, hosted CI and
  Sidecar release. No deferred release evidence is fabricated and no publication or
  tagging is performed under this ticket.
