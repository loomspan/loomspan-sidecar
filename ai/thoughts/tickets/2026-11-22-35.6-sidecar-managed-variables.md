## Development constraints

All Loomspan products are in development with no deployments or customers. Destructively replace superseded contracts, code and schemas. Breaking other Loomspan projects until their own updates land is acceptable. Do not add compatibility shims, legacy adapters, parallel legacy APIs or migration machinery, or take on other technical debt to preserve backward compatibility.

35.5 and 35.6 are separate local commits. Keep both commits local during this work. A temporary build or test failure in 35.5 is acceptable when 35.6 fixes it. Remove obsolete HTTP credential handling in 35.5 and its managed builder call site in 35.6. Verify the combined Sidecar build and affected tests after 35.6.

Apply the [design lens](../design-lens.md). Choose the simplest solution that meets the requirements, minimize technical debt, and keep tests and documentation proportional. Document any required development-data reset and its impact. This ticket does not authorize deleting deployed data.

## Outcome

Run in loomspan-sidecar with the Framework revision implementing 35.1–35.4 and the 35.5 HTTP changes. Managed editing, validation, publication and restoration use the selected authored candidate and current installation values. This ticket completes the managed half of the Sidecar migration.

## Requirements

Preserve authored documents throughout editing and storage. For managed installation, discover variables across execution configuration and executor-backed skill documents and supply Framework with the exact explicit value map for that candidate. Keep lookup inside the installation boundary and retain generation ownership through publication and restoration.

Installation values become current only on successful publication. Draft value edits apply to preparation of that draft. Rollback selects historical authored documents and resolves their references against the installation's current published values. Restart restores the selected published documents with the published installation values.

Dropping the last reference to a name omits it from the map supplied to Framework for that candidate. The installation retains the encrypted value until an editor explicitly removes it and publishes the removal.

Managed value entry, encrypted storage and lookup accept every variable name valid in an authored reference and preserve its spelling and case exactly. Sidecar discovers names and locations and passes the original documents and exact value map to Framework through its public API. Framework performs substitution and detects mapping-key collisions before overwrite.

Keep one management Validate action with one pass/fail result for the selected draft revision. First run Framework validation on the authored documents. On structural errors, report the document issues and stop before value lookup. Otherwise assemble the exact value map and attempt detached preparation. Validate succeeds only when preparation succeeds. Publication requires successful validation of the exact revision being published.

## Acceptance criteria

- [ ] Keep authored YAML in drafts and management reads. Support literals and explicit references for provider API keys, headers and Gemini service-account JSON. Replace managed editor/service restrictions on direct literals. Update management examples and authored consumer packs. Preserve existing authorization and storage access boundaries.
- [ ] Verify both forms through an authorized management read and a configuration-only export. With a literal credential, both show the value exactly as authored. With a `$var` reference, both show only the authored marker. Use a distinct test value for the reference and assert it is absent from the read response and every export entry. Keep supplied managed values encrypted in storage and explain this visibility rule in the editor and management examples.
- [ ] Discover distinct names and all authored locations across the candidate's execution YAML (below each connection and target namespace executor settings) and below top-level config in executor-backed skill documents. Walk mapping keys, values and sequences, including unknown executor fields. Within these locations, a mapping whose only key is the exact case-sensitive string `$var` is a marker. A mapping with additional keys is ordinary data and traversal continues into its entries. Strings including `${region}` are literal. Other skill fields and section selectors trigger no lookup. Preserve authored marker keys and ensure collisions fail before overwrite.
- [ ] Verify a marker with a non-string, blank or whitespace-padded name fails authored validation before value lookup. Report the authored location and the corresponding Framework reason (`name-must-be-string`, `blank-name` or `padded-name`).
- [ ] Save a value for `region/name` through the management API and use `{ $var: region/name }` as a mapping key in an executor-backed skill's config. Verify detached preparation succeeds when the resolved key is unique. Change only the managed value to match an existing sibling key and verify preparation reports the collision at the authored locations.
- [ ] Validate a draft with a structural error and a missing installation value. Verify the editor receives the structural issue before any value lookup or detached preparation.
- [ ] For each detached preparation, publication and restoration, assemble the exact explicit map for the selected documents. An empty map works for a reference-free candidate. A skill-only name counts, repeated names require one entry, unrelated stored names stay out, and a missing/blank value fails even when Spring defines it. Report authored locations and reasons without supplied values.
- [ ] Remove encrypted record injection into HTTP executor settings. Observe resolved fixed headers and skill-level paths on a real HTTP request. Caller-token passthrough remains request-scoped. Preserve existing storage protection for managed values and existing generation ownership.
- [ ] Validate draft revision A, then edit a skill to reference a new name in structurally valid revision B. With its value missing, Validate fails and tells the editor which name needs a value and where it is referenced. Publication is blocked, the draft stays editable, and the active generation keeps serving. Supply the value without editing the YAML. Verify this creates a new revision, publication requires validating that revision successfully, and publication then succeeds. The stored documents and editor still show the authored marker.
- [ ] Publish A with skill path `/records/a` and a fixed header supplied by `service.token` with test value `v1`. Save draft B with path `/records/b` and rotated value `v2`. Before publishing B, verify new requests still use `/records/a` and `v1`, including after restart. Admit work under A, publish B, and observe `/records/b` and `v2` together on a new request. Roll back to A's documents and observe `/records/a` and `v2` together on a new request. Work admitted under A before B was published finishes with `/records/a` and `v1`. Restart after rollback and again observe `/records/a` and `v2` on the same request.
- [ ] Publish documents that drop the last reference to `service.token` while leaving its stored value alone. Verify the candidate map omits the name. Roll back to documents that reference it and verify the retained published value is used without re-entry.
- [ ] Publish documents that no longer reference `service.token` and remove its installation value in that publication. Attempt to roll back to A. Report the missing name and its authored locations, keep the active generation serving, and preserve the rollback draft. Supply a replacement in that draft and retry publication. New work uses A's documents with the replacement value.
- [ ] Verify both file startup and managed validation/publish/restoration with the updated Sidecar test suite, including external loomspan-sidecar-test-suite fixtures and affected current consumer packs. Record the tested Framework and Sidecar revisions and test results for the cross-project handoff. Cloud ZIP transport, variable-store access and tenant Vertex policy belong to Cloud.
