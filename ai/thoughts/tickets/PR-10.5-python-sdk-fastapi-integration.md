# PR 10.5: Wire secure callbacks and reusable SDK resources into FastAPI naturally

## Development constraints

**Sidecar is still in development. Destructively replace superseded contracts,
code and schemas; no compatibility shims, legacy adapters, parallel legacy APIs
or migration machinery solely to preserve obsolete development behavior.**

Apply the [design lens](../design-lens.md#simplicity-and-technical-debt). Choose the
simplest complete solution and minimize technical debt. Keep implementation,
tests and documentation proportional. No data reset is expected; preserve existing
credentials, identities, operational data and reference packs. Document any newly
required development-data reset and its impact; this is not permission to delete
deployed data or regenerate operator keys.

## Outcome

Let a FastAPI application use ordinary lifespan, routers and dependencies for
Sidecar invocation and authenticated callbacks, replacing custom security glue
without changing its existing authentication or business authorization.

## Requirements

- Compose 10.2 async client, 10.3 issuer and 10.4 verifier/trust. Provide one small
  integration object, one pure ASGI middleware, and typed client/issuer/principal
  dependencies with normal FastAPI dependency overrides. Exact names in the design
  sketch are illustrative. Do not create a custom router, callback decorator,
  settings framework or parallel protocol implementation.
- Typed configuration/integration construction performs validation only: no files,
  keys, network or background work. Explicit async application lifespan initializes
  signer/export, callback trust, owned refresh and reusable client. Startup failures
  propagate and partial initialization is cleaned up. Compose existing lifespans;
  initialize mounted callback security from the owning app. Resources are app-owned,
  not globals or lazy per-request initialization. Exit cleans up owned resources
  without an added remote-execution drain/cancel/recovery coordinator.
- Plain client-only use remains independent of FastAPI/signing/callback setup.
  Applications supply trusted authenticated identity explicitly, issue credentials
  and pass them per operation; no provider adapter registry or inferred login claims.
- Protect the entire default `/loomspan/callbacks` prefix and descendants, not
  similarly named siblings, even when a handler omits the principal dependency.
  Support one validated configurable literal absolute non-root prefix; reject
  ambiguous paths/settings consistently with Java. Missing initialized security
  fails closed. Principal dependency reads already-verified request-local identity.
- Inspect raw ASGI headers: require exactly one valid bearer Authorization header,
  reject duplicate headers and access_token query parameters including encoded
  names, and never read/wrap/consume bodies for authentication. Sessions/cookies
  do not authenticate callbacks. Return 401 with WWW-Authenticate: Bearer without
  login redirects; application denials return 403. Authenticated GET/POST allowed,
  other methods denied. Document actual upstream malformed-path/TRACE rejection
  rather than promising servlet-specific status codes.
- Preserve bodies/business headers and exact verified roles. Business code owns
  role/record authorization using issuer plus subject. Clear request-local identity
  after success/error/cancellation. Keep unrelated browser authentication/CSRF
  behavior intact; prove ordering with CORS/login middleware, mounts and root paths.
- Runtime trust withdrawal/expiry affect new admission, not already-admitted callback
  code. Prove withdrawal/recovery and admitted callbacks finishing with their original
  identity. Sidecar strict pre-forward expiry remains separate from callback skew.
- Package web integration under the fastapi extra; no runtime server/CLI installation
  requirement. Own complete runnable FastAPI and single-worker colocated/provided-key
  examples, with public export ownership explicit. For provided replicas, separate
  per-process export paths can share signing identity; no shared-writer coordinator.
  Add tests/docs for explicit lifespan, invalid startup and business authorization.
  Do not expose tokens/private keys in OpenAPI examples, dependency errors or logs.

## Acceptance criteria

- [ ] Installed FastAPI example submits using a small trusted identity adapter,
  reuses app-owned client/issuer and serves authenticated ordinary router callbacks.
- [ ] Lifespan startup/partial failure/shutdown and omitted initialization are safe;
  dependency overrides work and core remains independently importable/usable.
- [ ] Full-prefix enforcement rejects duplicate/query/session credentials and
  malformed paths, respects method policy, and preserves business request bodies.
- [ ] Concurrent requests and error/cancellation paths keep identity isolated;
  ordinary browser/CSRF routes and mounted/root-path boundaries remain correct.
- [ ] Runtime trust withdrawal/recovery and expiry-at-admission are verified with
  admitted requests allowed to finish; middleware order cannot silently bypass auth.
- [ ] Colocated/provided examples state single-writer ownership and run from an
  installed package; focused tests/docs pass independent review.
