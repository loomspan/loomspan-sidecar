# Sign into management with local accounts and email-only password recovery

## Outcome

Operators can establish the first administrator, invite local management users,
sign in and recover forgotten passwords by email. Spring Security and SQLite own
management identity independently of the existing execution JWT authentication.

## Requirements

- Use Spring Security form login, server-side sessions, CSRF protection and salted
  adaptive password hashing. Store local accounts and required account/token state
  in the existing SQLite database using Flyway and Spring JDBC. Complete migrations
  before account operations. Do not add an external identity provider or JPA.
- An account's username is its email address. It is unique and immutable in v1;
  document consistent normalization and comparison chosen during planning. An admin
  changes an address by creating a replacement account and disabling the old one.
  There is no public self-registration or email-change workflow.
- Support hierarchical roles `viewer`, `editor`, `admin`. Viewers may inspect
  published/submitted configuration; editors also author, validate and publish;
  admins also manage accounts and take over editing leases. Actual configuration
  operations belong to PR 1.3.2/1.3.3. These roles and login cookies grant no execution
  API access. JWT credentials likewise do not grant management account permissions.
  Preserve existing execution JWT roles, ownership and observability authentication.
- Protect management browser/API routes with their own session/CSRF behavior;
  preserve stateless execution authentication. Passwords, tokens and private account
  state must not leak through logs, errors or caches. Include login/logout and
  current-session identity/role operations for the later console.
- Require the environment-only `LOOMSPAN_SIDECAR_SETUP_TOKEN` to authorize initial
  administrator creation. Require a nonblank high-entropy operator-supplied token;
  choose and document exact validation in planning. Never log/store its plaintext.
  Missing/unusable credentials on an uninitialized instance lock management setup
  and explain the condition without secrets. They must not disable execution.
- Initial setup selects the administrator email and sends a single-use password-set
  link. The administrator chooses a password through that link, establishing mailbox
  control before the account can log in. Persist bootstrap completion separately
  from configuration-store initialization. Complete initial administrator creation
  and consume bootstrap access atomically; concurrent or replayed attempts cannot
  create competing initial administrators. An initialized installation neither needs
  the setup environment variable nor reopens setup when it remains configured.
  Interrupted or failed email setup must be retryable without bypassing the setup
  credential, granting access prematurely or leaving bootstrap permanently stranded.
- Admins create accounts with email and role; Sidecar sends the same kind of
  single-use password-set link. Users choose their own initial passwords. Pending
  users cannot log in. Admins can change roles and disable/re-enable accounts, but
  cannot assign replacement passwords as a recovery bypass. Prevent disabling,
  removing or demoting the last enabled administrator, including concurrent changes;
  an unactivated invited admin cannot serve as its replacement.
- Passwords require at least 15 characters, uppercase and lowercase letters, a
  number and a special character. Support a maximum of at least 64 characters,
  spaces and password-manager paste/autofill, without silent truncation. Choose
  exact character classification and maximum during planning. No common-password
  blocklist, breached-password service, background checking or periodic expiration.
  Apply the same rules to initial password setting, change and reset.
- Provide authenticated own-password change with current-password verification and
  an unauthenticated forgot-password request/reset flow. Recovery is email only:
  no offline account repair, security questions or administrator-set password.
  Use unpredictable, expiring, single-use tokens with protected durable storage,
  bounded request/login/token attempts and generic forgot-password responses that
  do not reveal account existence. Bind tokens to their account and purpose; invalid,
  expired, replayed or disabled-account tokens cannot grant access. A reset cannot
  re-enable an account. Select expiry/throttling defaults during planning.
- Successful password changes/resets invalidate affected sessions and outstanding
  password-recovery tokens; require normal login afterward. Disable and role change
  also invalidate affected sessions. PR 1.3.2 joins that invalidation to draft/lease
  cleanup. An already accepted publication must not be cancelled by these events.
- Configure SMTP in deployment application YAML using standard `spring.mail.*`
  settings. Configure sender address and trusted external console base URL in
  application YAML under `loomspan-sidecar.management.*`; exact Sidecar key names
  are planning choices. Build emailed links from that configured URL, never an
  untrusted request host. Mail settings/credentials stay outside managed snapshots
  and configuration exports; do not add a console SMTP editor or a mail-provider API.
- Missing/unavailable email delivery prevents email-dependent setup/recovery, but
  existing accounts can still log in and execution remains available. Bound mail
  connection/send waits and provide secret-free operator diagnostics and retryable
  user flows. No plaintext-password fallback or separate durable mail/job platform.
  A failed delivery must not leave the user without a usable password or a safe retry.
- Establish `loomspan-sidecar.management.session-idle-timeout` with default `30m`.
  Meaningful authenticated user activity can extend it; background polling cannot.
  PR 1.3.2 implements the editor activity/lease integration and its end-to-end checks.
  No cross-process login/session recovery is required.

## Acceptance criteria

- [x] Real SQLite tests prove account uniqueness, durable bootstrap completion and
  secure password/token storage across restart. Fresh configuration storage alone
  never counts as completed management bootstrap.
- [x] Missing/bad setup credentials lock management only. Concurrent first-admin
  attempts, failed email/retry, link expiry and replay cannot bypass setup or create
  competing initial admins. Initialization stays consumed after restart even when
  the setup token is still present. Initial login requires emailed password setting.
- [x] Admin account invitation, role changes, disable/re-enable and replacement-email
  workflow work with real authorization. Pending/disabled accounts cannot log in;
  concurrent account changes cannot eliminate the last enabled administrator.
- [x] Password composition/length rules apply consistently without blocklist or
  breach checking. Password hashing, login throttling, CSRF and session invalidation
  are verified. Management cookies/roles and execution JWT permissions remain separate.
- [x] Controlled local mail delivery tests cover configured sender/link origin,
  invitations and reset. Expired, reused, incorrect-purpose and disabled-account
  tokens fail; successful reset changes the password once, invalidates sessions and
  does not auto-login. Forgot-password responses do not disclose account existence.
- [x] Missing configuration and SMTP failures permit existing login/execution while
  making email-dependent operations unavailable and retryable. Secrets are absent
  from failure responses/logs. No production email is sent by tests.
- [x] Identity/session APIs and minimal usable setup/login/password forms are documented
  and verified without requiring the Phase 4 editor. Idle expiry works, with the
  editor-specific activity integration explicitly assigned to PR 1.3.2.
- [x] Application YAML/deployment guidance documents SMTP, sender/base URL, setup
  credential, password policy, account replacement and email-only recovery limits.
  Relevant execution/security and supported-framework-boundary regressions pass.
