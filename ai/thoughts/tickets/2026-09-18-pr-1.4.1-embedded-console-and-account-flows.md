# Access the embedded console and manage accounts in the browser

## Outcome

Users can enter Sidecar's embedded management console, complete account setup and
recovery, and inspect current published configuration. Administrators can manage
accounts without calling management APIs manually. This establishes the browser
shell for Phase 4's authoring and publication workflow.

## Requirements

- Serve the console inside Sidecar and manage only that instance. Choose frontend
  tooling, layout and packaging during implementation planning; ship the assets
  with Sidecar without requiring a separate frontend service. Use the existing
  Phase 3 management contracts and standard Spring security mechanisms.
- Provide the uninitialized/locked landing state and first-administrator setup
  authorized by the one-time environment setup credential. Explain an unavailable
  setup credential without exposing it. Initialized instances do not reopen setup.
  A management lock must not disable authenticated execution.
- Provide email-address login, logout, emailed initial-password setup,
  forgotten-password requests, reset-link completion and own-password changes.
  First-administrator setup also uses the emailed initial-password link. Do not
  imply an account can log in before password setup or automatically log users in
  after reset. Expired/used links and failed delivery have actionable, safe feedback.
- Preserve immutable email usernames, no public registration, and email-only
  recovery. Recovery requests must not reveal account existence. SMTP, sender and
  trusted external console URL remain deployment configuration, outside the UI.
  Missing/unavailable email delivery leaves existing login and execution available;
  email-dependent flows explain their unavailability and allow safe retries.
- Explain and enforce the existing password policy consistently with the server:
  minimum 15 characters, uppercase and lowercase letters, a number and a special
  character; retain long-password, space, paste and password-manager support.
  Do not introduce common/compromised-password checks or periodic password changes.
- Provide admin account creation through emailed password-setup links, role changes
  and disable/re-enable. Keep email addresses immutable and protect the last enabled
  administrator. Preserve server-driven session invalidation after reset, disable
  or role change; stale browser state cannot continue privileged operations.
- Reflect hierarchical viewer/editor/admin permissions in navigation and actions.
  Management uses server sessions and CSRF protection; execution JWT permissions
  remain separate. UI visibility does not replace server authorization. Never
  reveal another session's private draft or validation results.
- Provide authorized read-only views of runtime-published skill YAML and REST
  routes/targets, preserving authored content and placeholders. Identify the durable
  runtime snapshot; do not label the intended database pointer as current execution.
  Viewers can inspect this content, including authored sensitive values. Background
  refreshes must not keep an otherwise idle login alive.
- Keep the console usable with keyboard navigation, labelled controls and textual
  feedback alongside color. Render authored configuration and diagnostics as text,
  not executable markup. Supply this ticket's browser verification, build/packaging
  evidence and user/deployment documentation.

## Acceptance criteria

- [x] The packaged Sidecar serves the console and current-configuration views without
  a separate frontend service; authenticated viewers see the runtime snapshot's
  complete authored skills/routes/targets and preserved placeholders safely rendered.
- [x] Browser flows cover management-locked startup, first-admin setup, emailed
  password setup, login/logout, forgotten-password/reset and own-password change.
  Bootstrap cannot be reused, invalid/used links are explained, reset does not log
  in automatically, and recovery requests do not disclose account existence.
- [x] Password guidance matches server acceptance, including composition, length,
  spaces and paste/autofill. Email outage behavior preserves existing login and
  execution while giving safe retry feedback for email-dependent operations.
- [x] Admin browser workflows create accounts, change roles and disable/re-enable;
  immutable emails and last-admin safeguards hold. Session invalidation removes
  stale access, and viewer/editor/admin permissions, CSRF and draft privacy remain
  enforced through real authenticated management requests.
- [x] Background refresh does not extend idle login; management setup/lock and
  account flows leave execution authorization independent. Keyboard use, text
  feedback and safe content rendering are verified for the delivered screens.
- [x] Relevant regression checks pass against the installed framework snapshot;
  console access, account flows and embedded asset packaging are documented.
